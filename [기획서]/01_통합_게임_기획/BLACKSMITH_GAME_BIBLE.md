# Blacksmith 통합 게임 기획서

## 1. 프로젝트 약속

> 한 명의 대장장이가 제한된 하루 작업량 안에서 작품 한 점을 직접 만들고, 강화의 위험 앞에서 멈출지 더 도전할지 선택하며, 그 작품이 다른 사람과 세계에서 겪은 생애와 결과를 돌려받는 Android 세로형 제작 게임.

차별화 문장:

> 장비를 대량 생산하는 게임이 아니라, 작품의 출생·성장·소유·손상·복원·사건 기록을 제작하는 대장장이 게임.

핵심 재미:

```text
강화의 즉각 판단
→ 작품을 세상에 보냄
→ 작품의 생애와 세계 결과가 돌아옴
→ 다음 강화·복원·제작 이유가 생김
```

강화는 반복 동력이고 작품 생애·세계 환류는 의미와 장기 보상이다.

## 2. 권위와 상태 구분

현재 기획 권위는 다음 순서를 따른다.

1. 최신 사용자 승인 Decision과 병합된 배치 정본
2. `CURRENT_CONFIRMED_DECISIONS.md`
3. `docs/planning/CURRENT_R1_CANON_REGISTRY.json`
4. 본 Game Bible과 현재 Hub 문서
5. 과거 Prototype·PoC·연구·Draft 문서

과거 문서가 최신 Decision과 충돌하면 최신 Decision이 우선한다.

현재 상태:

- 단계: `TOTAL_PLANNING / CANON_CONFLICT_RESOLUTION`
- 제품 구현: `BLOCKED`
- 최신 제품 runtime·Android·접근성·성능·사람 플레이: `NOT_RUN`
- 명예의 전당: `FUTURE_CONTENT_HOLD`
- 현재 검증 상한: `+50`
- 장기 최종 강화 상한: `DEFERRED`

### 역사 구현 증거

기존 Prototype과 MVP-003의 구현·자동 테스트 결과는 삭제하지 않는다. 다만 아래 상태로 분류한다.

- 과거 구현 수치: `LEGACY_IMPLEMENTED_VALUE`
- 다음 검증 초기값으로 재사용되는 수치: `BASELINE_TEST_PRESET`
- 최신 제품 요구사항: 최신 승인 Decision과 본 문서가 소유
- 과거 `IMPLEMENTATION_VALIDATED / HUMAN_VALIDATION_PENDING`: 당시 HEAD의 역사 증거이며 최신 제품 PASS가 아님

## 3. 핵심 설계 원칙

- 한 명의 대장장이만 운용한다.
- 한 번의 일반 강화 입력은 한 번의 결과만 만든다.
- 작품은 공장식 소모품이 아니라 UID와 생애를 가진다.
- 영구 완성도는 제작 완료 시 한 번 결정하고 같은 작품에서 재추첨하지 않는다.
- 낮은 완성도도 강화·수식어·고객·세계 사건 접근을 막지 않는다.
- 강화 비용·위험·소비 자원은 판단 전에 확인할 수 있어야 한다.
- 피로도는 성공률을 낮추는 벌이 아니라 오늘의 작업 우선순위를 제한하는 자원이다.
- 날짜는 플레이어가 하루를 끝낼 때 진행하며 고객·세계 결과의 공통 시간축이다.
- 판매·납품된 작품은 소유자·사건·손상·복원·계승 이력을 유지한다.
- 일반 실패는 작품과 역사를 지우지 않고 손상·대파·잠금·복원 목표를 만든다.
- 완전 파괴는 명시적이고 충분히 고지된 플레이어 선택에서만 허용한다.
- 작은 세로 화면에서 한 번에 중요한 판단 하나만 요구한다.
- 자동화는 반복 편의를 제공하지만 중요 이정표·위험·소유권·날짜 판단을 우회하지 않는다.

## 4. 핵심 루프

```text
의뢰·세계 소식 확인
→ 작품 종류와 재료 선택
→ 직접 제작
→ 영구 완성도 결정
→ 일반 강화와 멈춤·추가 도전 판단
→ +10 정밀강화 이정표
→ 보관 또는 방문 고객 납품
→ 즉시 인과 결과
→ 피로도·날짜 진행
→ 지연된 고객·세계 결과
→ 같은 UID의 재방문·손상·복원·계승
→ 명성·관계·새 의뢰·다음 작품 목표
```

### 세션 위계

- 주 행동: 제작·강화·멈춤 판단
- 환류 행동: 고객 납품·결과 확인·재방문
- 장기 행동: 작품 포트폴리오·세트·연대기·관계·수집가
- 후속 보류: 명예의 전당·대형 세계 콘텐츠

고객 대화와 세계 사건은 강화보다 긴 별도 장르가 아니라 강화 선택에 의미를 되돌려주는 짧은 환류 구간이다.

## 5. 작품 구조

### 작품 계열

- 무기
- 방어구
- 악세서리

모든 작품은 동일한 기본 강화 대상이다. 시스템적인 `대표 장비`, `주력 장비`, `보조 장비` 등급을 두지 않는다.

### 작품 정체성

```text
작품 UID
├─ 출생
│  ├─ 작품 종류
│  ├─ 주재료
│  └─ 영구 완성도
├─ 정밀강화
│  ├─ 정밀 등급 1개
│  ├─ 일반 수식어 A
│  └─ 일반 수식어 B
├─ 작품 생애
│  └─ 활성 사건·연대기 수식어 1개
└─ 기록
   ├─ 제작·강화 이력
   ├─ 소유자·사용자
   ├─ 손상·복원·계승
   └─ 고객·세계 사건 연대기
```

### 성장 축

- 영구 완성도: 어떻게 태어났는가
- 강화 단계: 어떤 위험과 선택을 거쳤는가
- 일반 수식어 A·B: 제작자가 어떤 역할과 성질을 부여했는가
- 사건·연대기 수식어: 세계에서 어떤 작품으로 기억되는가

## 6. 제작

### 직접 제작

- 터치와 접근성용 자동 작업으로 제작 진행도를 채운다.
- 빠른 연속 터치의 피버는 불이익을 주지 않는다.
- 제작 시작은 피로도를 소비하며 터치마다 추가 피로도를 소비하지 않는다.
- 피버의 정확한 공격력·가치 보정은 `LEGACY_IMPLEMENTED_VALUE / BASELINE_TEST_PRESET`이다.

### 정밀 결과와 영구 완성도

- 정밀 결과 예시: `STANDARD / GOOD / PERFECT`, 자동 제작은 `AUTO`
- 영구 완성도 예시: `APPRENTICE / STANDARD / REFINED / MASTERWORK / PERFECT`
- 정밀 결과는 완성도 분포에 영향을 줄 수 있다.
- 완성도는 작품의 출생 상태이며 같은 UID에서 재추첨하지 않는다.
- 정밀 결과와 영구 완성도를 UI·데이터에서 분리한다.
- 정확한 분포·성능값은 버전형 테스트 프리셋으로 관리한다.

기존 `quality_*` 필드는 구현 호환을 위해 보존할 수 있으나 신규 정본 용어를 덮어쓰지 않는다.

## 7. 강화

### 현재 검증 범위

- 현재 검증 상한: `+50`
- 정밀강화 이정표: `+10 / +20 / +30 / +40 / +50`
- 장기 최종 상한: 사람 플레이·성장 속도·반복 재미 검증 후 확정
- 기존 `+100`: `LEGACY_IMPLEMENTED_VALUE / DEFERRED_TEST_TARGET`

### 일반 강화

- `+10` 이정표 사이의 단계
- 버튼 한 번으로 즉시 한 번 판정
- 비용·확률·위험·현재 작품 상태를 사전에 표시
- 정확한 비용·확률·피로도는 테스트 프리셋

### 정밀강화

각 `+10` 이정표에서 다음 중 작품 상태에 맞는 중요한 선택을 제공한다.

- 정밀 등급 결정·성장
- 일반 수식어 A 또는 B 추가
- 일반 수식어 A 또는 B 강화
- 보조재료·촉매 투입
- 위험·효과·작품 목적에 따른 선택

`+10~+50`의 예시 배치는 고정 정답이 아니며 각 이정표의 실제 선택 문법은 R2~R3에서 상세화한다.

### 실패·손상·대파·복원

- 강화 실패는 단계 유지 또는 단계 하락 등 프리셋 상태 전이를 따른다.
- 손상·대파는 강화 단계를 낮출 수 있다.
- 일반·특수 수식어는 삭제하지 않고 요구 강화 단계까지 잠글 수 있다.
- 복원·재강화로 요구 조건을 다시 만족하면 잠긴 성질을 복구한다.
- 같은 이정표를 다시 통과해도 최초 보상을 중복 지급하지 않는다.
- 대파는 흉터·변형·조건부 성질과 새로운 연대기를 만들 수 있다.
- 완전 파괴는 명시적이고 정보가 제공된 선택에서만 허용한다.
- 완전 파괴 후에도 과거 UID와 역사 기록은 보존한다.

과거 `+11 단계 하락`, `+30 즉시 파괴`, 실패 보정 수치는 역사 구현값이며 현재 제품 불변 규칙이 아니다.

## 8. 수식어와 재료

### 재료 계층

- 주재료: 작품 종류·기본 성능·출생 정체성
- 보조재료: 정밀강화 성질·상황 보정
- 촉매: 성공·성장·가치·위험 조정

보조재료·촉매는 제작·강화·방문 고객 지원에 사용하는 공유 재고다. 별도의 지원 전용 인벤토리를 만들지 않는다.

### 일반 수식어

- 일반 정밀강화 수식어 슬롯은 A·B 두 개로 고정한다.
- 세 번째 일반 수식어 슬롯을 기본 제공하지 않는다.
- 일반 수식어는 플레이어의 정밀강화 선택 계층이다.

### 사건·연대기 수식어

- 작품당 현재 활성 사건·연대기 수식어는 1개다.
- 방문 고객에게 실제 인계되어 생애가 활성화된 작품만 획득할 수 있다.
- 작품의 실제 사용·기여·결과가 확인된 결정적 세계일정에서 계보가 생성된다.
- 후속 세계일정은 새 수식어를 무한 추가하지 않고 기존 계보를 강화·변형·잠금·복원·대체한다.
- 이전 이름·효과·변화 원인·시점은 작품 연대기에 영구 보존한다.
- 같은 일정·고객·결과 반복으로 무한 성장시키지 않는다.
- 일반 수식어 A·B를 점유하거나 덮어쓰지 않는다.

## 9. 피로도와 날짜

- 피로도는 제작·강화·복원 등 오늘 수행할 작업량을 제한한다.
- 피로도 부족은 작업 시작을 막을 수 있으나 성공률·완성도를 몰래 낮추지 않는다.
- 판매·보관·기록 확인 같은 관리 행동은 원칙적으로 핵심 작업 피로도를 소비하지 않는다.
- 날짜는 플레이어가 하루 종료를 선택할 때만 진행한다.
- 게임 날짜는 고객 재방문·세계일정·마감·시장 변화·작품 결과를 연결한다.
- 피로도·날짜 넘기기가 대기벽이나 최적 스킵이 되면 구조 실패로 검토한다.

기존 기본 피로도 20, 제작 3, 일반 강화 1, 정밀강화 3, 잔여 50% 이월 등의 숫자는 `LEGACY_IMPLEMENTED_VALUE / BASELINE_TEST_PRESET`이다.

## 10. 고객·납품·세계 결과

### 방문 고객

- 고객은 목적·사용 환경·필수 조건·추가 목표·기한을 대화로 제시한다.
- 일반 고객은 자신이 아는 범위에서 정직하게 말하고 불확실성을 표시한다.
- 특별한 거짓말은 단서와 검증 가능성이 있을 때만 사용한다.
- 플레이어는 숫자 경고문을 읽는 대신 대화에서 의도·위험·환경을 추론한다.

### 납품과 생애 활성화

- 고객 생애는 작품을 `[방문 고객]`에게 실제 인계한 후에만 활성화된다.
- 보관 중이거나 단순 제작 완료된 작품에는 고객·세계 생애가 붙지 않는다.
- 납품 시 소유권·대금·재고·세계 기록 생성을 원자적으로 처리한다.
- 재시도는 중복 지급이나 작품 복제를 만들지 않는다.

### 즉시 결과와 지연 결과

- 납품 직후: 고객이 작품을 어떻게 사용할지, 어떤 선택이 기여할 수 있는지 보여준다.
- 날짜·세계일정 후: 실제 성공·부분 성공·실패·손상·대파·새로운 필요를 보여준다.
- 결과는 강화·수식어·지원·고객 행동이 어떻게 기여했는지 인과적으로 설명한다.
- 숨은 무작위 처벌이 작품을 자의적으로 파괴하지 않는다.

### 지원 자원

- 보조재료·촉매·조언은 선택적 지원이다.
- 지원하지 않았다는 이유만으로 자동 실패하지 않는다.
- 지원 자원은 납품 확정 시 즉시 완전 차감한다.
- 예약·대여·지연 정산·반환·환불·복구를 제공하지 않는다.
- 확정 전에 종류·수량·현재 재고·기회비용을 표시한다.
- 완성된 추가 장비를 제공하면 별도 작품 UID와 생애를 가진다.

## 11. 작품 생애·소유권·재방문

모든 납품 작품은 다음을 기록한다.

- 작품 출생·강화·수식어
- 현재 소유자
- 실제 사용·기여
- 예정·완료 사건
- 성공·실패·손상·복원
- 계승·재방문·후속 의뢰
- 제작자 명성·관계 환류

### 소유권

- 수리·복원·재강화 의뢰는 임시 위탁이며 원소유자를 유지한다.
- 소유자 사망·은퇴 시 상속자를 우선한다.
- 폐기·파산·처분된 플레이어 제작 작품은 수집가 경로로 돌아올 수 있다.

### 수집가

- 플레이어가 직접 제작하고 방문 고객에게 실제 납품한 뒤 승인된 처분 경로에 들어간 작품만 취급한다.
- 건너뛴 작품은 `COLLECTOR_HELD` 상태로 순환·재등장하며 FOMO 영구 손실을 만들지 않는다.
- 외부 세계 작품은 수집가 재고·회수·재구매 대상이 아니다.

## 12. 세트와 연대기

- 세트는 같은 이름·외형·재료만 모은 정적 컬렉션보다 실제 사건 연대기와 역할 연결을 우선한다.
- 성공뿐 아니라 실제 기여가 있는 실패·희생·손상·복원도 세트 성립에 참여할 수 있다.
- 보상은 범용 수치 보정, 상황 태그, 역사 표시를 분리한다.
- 같은 공동 사건을 미기여 작품에 복사하지 않는다.
- 세트 전체가 등록·보상을 자동 획득하지 않으며 개별 UID의 실제 기여를 검증한다.

정확한 세트 수·구성품 수·보정값은 테스트 값이다.

## 13. 자동 단조

자동 단조는 반복 입력 접근성과 편의를 위한 보조 기능이다.

- 목표 단계·반복·단조 방식·사용 자원 설정 가능
- 부족·가득 참·중지 조건을 명확히 표시
- 중요 선택이 없는 저위험 반복만 처리
- `+10` 정밀강화 이정표, 위험 개방 구간, 자원·가치·소유권 판단에서는 강제 정지
- 손상·대파·완전 파괴 선택을 자동 확정하지 않음
- 첫 코어 버티컬 슬라이스의 핵심 판단을 대체하지 않음

## 14. 모바일 UX·접근성

- Android 세로형, 한 손 사용 우선
- 한 화면의 주 행동 1개
- 주요 입력 48dp 상당 이상
- 색상만으로 성공·위험·선택을 전달하지 않음
- 결과 창 자동 닫힘 금지
- 진동·화면 흔들림·모션 감소 옵션
- 반복 탭 대안으로 제한적 자동 작업 제공
- 정밀 입력 대안으로 느린 게이지·넓은 판정·정밀 보조 제공
- 정밀 보조가 최고 희귀 보상을 자동 제공하지 않음
- 비용·확률·위험·소유권·소비 시점을 확정 전에 표시

실제 Android·접근성 통과는 사람과 기기 증거 뒤에만 판정한다.

## 15. 첫 코어 버티컬 슬라이스

첫 코어 증명은 플레이어가 선택한 작품 한 점의 완전한 왕복이다.

```text
작품 한 점 선택·제작
→ +10 정밀 이정표
→ +20 정밀 이정표
→ +30 정밀 이정표
→ +40 정밀 이정표
→ +50 정밀 이정표
→ 방문 고객에게 납품
→ 즉시 인과 결과
→ 피로도·날짜 진행
→ 지연된 세계 결과
→ 같은 UID 재방문
→ 복원·재강화·후속 판단
→ 작품 생애가 다음 강화 이유로 환류
```

완료 조건:

- `+50` 도달만으로 완료하지 않는다.
- 강화 선택이 고객·세계 결과에 인과적으로 연결돼야 한다.
- 같은 UID 재방문 후 플레이어가 다음 강화·복원 행동을 자발적으로 정해야 한다.
- 다른 작품군은 플레이 가능한 병렬 루프가 아니라 종료 화면·제작법 카드 등 제한된 비플레이 미리보기로만 제시한다.
- 작품 한 점은 검증 범위를 통제하기 위한 플레이어 선택 대상이며 시스템 대표작으로 승격하지 않는다.

정확한 세션 길이·자원·확률·날짜 수·재방문 간격은 `BASELINE_TEST_PRESET`이다.

## 16. 경제·수치 권위

### 정본 불변 규칙

- 어떤 자원이 존재하는가
- 언제 소비되는가
- 취소·실패 시 반환되는가
- 무엇을 판단 전에 공개하는가
- 손상·복원·완전 파괴가 어떤 상태 전이를 따르는가
- 피로도와 날짜가 어떤 판단을 만드는가

### 버전형 테스트 프리셋

- 강화 비용·성공 확률
- 피로도 소비·이월
- 재료·촉매 수량
- 보상량
- 날짜 진행량·재방문 간격
- 손상·복원 요구 수치

상태 분류:

- `LEGACY_IMPLEMENTED_VALUE`
- `BASELINE_TEST_PRESET`
- `EXPERIMENT_VARIANT`
- `CURRENT_VALIDATED`
- `DEPRECATED_PRESET`

각 프리셋은 버전·빌드·가설·변경 변수·고정 변수·행동 증거·결과·한계를 기록한다. 가능한 한 한 번에 한 핵심 변수만 조정한다. 구조적 의미가 바뀌면 밸런스 변경이 아니라 새 기획 Decision이 필요하다.

## 17. 코어 재미 검증

코어 재미는 만족도 또는 행동 로그 한쪽만으로 통과시키지 않는다.

### 행동 증거

- 강화 지속과 중단 사이에서 실제 고민
- 일반 수식어 A·B와 주요 정밀강화 선택 기억
- 납품 결과에 어떤 선택이 기여했는지 설명
- 같은 UID 재방문 후 자발적 복원·강화·재납품 의도
- 피로도를 작업 우선순위 자원으로 사용
- 날짜가 세계 결과와 후속 작업을 연결한다고 이해
- 손상·복원이 무의미한 벌이 아니라 생애와 목표를 만든다고 인식

### 회상 인터뷰

- 이 작품이 다른 작품과 어떻게 달랐는가
- 왜 그 시점에 강화를 멈추거나 계속했는가
- 납품 결과에 어떤 선택이 영향을 줬는가
- 세계 결과를 본 뒤 다음에 무엇을 하려 했는가
- 같은 작품이 돌아왔을 때 무엇을 느꼈는가
- 피로도와 날짜 때문에 무엇을 먼저 했는가

행동과 인터뷰가 충돌하면 통과를 보류하고 원인 가설을 세운 뒤 최소 변경으로 재검증한다. 만족도·완료율·클릭 수·세션 시간은 실패 지점을 찾는 보조 지표이며 단독 통과 근거가 아니다.

정확한 표본 수·통과 비율·반복 횟수는 테스트 값이다.

## 19. 명예의 전당 — 후속 콘텐츠 보류

명예의 전당 방향은 승인됐으나 현재 구현·코어 슬라이스 범위가 아니다.

- 경쟁·랭킹·점수·상위 퍼센트·시즌 보상 없음
- 플레이어 작품과 외부 세계 작품을 볼 수 있는 비경쟁 아카이브
- 첫 입성 스냅샷과 성공적으로 제출된 최고 자격 상태 보존
- 테마 전시관·검색·필터 중심
- 테마는 기획하고 포함 작품은 공개 규칙으로 자동 판정
- 수집가와 외부 작품 경로를 분리
- 현재 상태: `FUTURE_CONTENT_HOLD`

과거 서버 랭킹·리더보드 표현은 폐기된 방향이다. 미래 구현 재개 시 시간 권위·오프라인·기기 시계·등록 제한을 현재 플랫폼 경계와 함께 다시 검토한다.
