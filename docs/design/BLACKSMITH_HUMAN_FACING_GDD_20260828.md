## 2. 플레이어가 얻게 될 약속

```text
강화하고 싶은 한 작품을 고른다
→ 다음 +1의 이득·성공 가능성·손상 가능성·필요 자원을 읽는다
→ STOP 또는 PUSH를 결정한다
→ 성공·유지·손상의 결과를 즉시 확인한다
→ 손상됐다면 수리·손상 상태에서 재도전·인계 중 하나를 선택한다
→ 고객이 같은 작품을 실제 사용한 결과를 받는다
→ 이 작품의 이야기가 연대기에 남고, 다음 작품의 판단으로 돌아간다
```

대표 행동은 강화 버튼을 누르는 일 자체가 아니라 **보이는 정보를 읽고 위험을 감수할 정도를 정하는 일**이다. 성공하면 +1이라는 명료한 전진, 제작의 상승감, 작품의 가치가 보상이다. 실패해도 무작위로 모든 것을 빼앗기지 않는다. 결과는 유지 또는 손상 중 하나이며, 손상은 다음 시도에서 수리·위험 관리·인계 타이밍을 배우게 한다. 이때 목표 감정은 “내가 한 번 더 밀기로 했기 때문에 이 결과가 났다”는 긴장, 안도, 아쉬움, 애착이다.

## 3. 첫 세션에서 남겨야 할 기억

첫 세션은 기능을 모두 설명하는 시간이 아니다. 플레이어가 **한 작품을 키우고, 그 작품의 운명을 직접 결정했다**고 느끼게 해야 한다.

1. 새 작품 한 자루를 만들고 등급을 확인한다.
2. 일반 강화로 +0에서 +9까지, 매번 +1씩 올린다. 성공은 반드시 +1이며 여러 단계가 한 번에 오르지 않는다.
3. **5강 단위**에서 제작 상승감이 커진다. 이는 연출·사운드·표현의 이정표이며, 확률·재료·새 슬롯을 바꾸는 새 규칙이 아니다.
4. `+9 → +10`에서 유일한 **정밀강화**를 경험한다. 성공하면 무기에만 태그 키워드 하나가 귀속된다.
5. +10 이후 +11부터는 처음으로 손상 가능성이 있는 실패 구간을 읽고, 여러 번의 STOP OR PUSH 기회를 가진다. 목표는 +15 도달 강제가 아니라 “언제 멈출지”를 선택하는 것이다.
6. 인계 뒤 같은 무기가 고객의 실제 사용 결과로 돌아온다. 손상은 보여주기 위해 강제하지 않는다. 실제 손상이 났을 때에만 한 번의 수리 선택이 열린다.

현재 Phase 1 대표 Slice의 목표 길이는 **6~8분 인간 플레이테스트 가설**이다. 실행 타이머나 검증 완료 사실이 아니다.

## 4. 핵심 루프와 세션 루프

### 4.1 핵심 루프: 강화의 긴장

| 단계 | 플레이어가 보는 것 | 플레이어가 판단하는 것 | 즉시 피드백 |
|---|---|---|---|
| 작품 준비 | 무기, 현재 강화, 등급, 내구도, 필요한 자원 | 이 작품에 투자할 가치가 있는가 | 작품의 출생과 정체성 |
| 강화 미리보기 | 다음 목표, 성공·실패·손상 결과, 비용 | 지금 밀면 이득이 위험보다 큰가 | 실행 전 결과의 의미를 읽을 수 있음 |
| 강화 실행 | 한 번의 시도 | PUSH를 실제로 감수 | 성공 +1 / 실패·유지 / 실패·손상 |
| 상태 재평가 | 강화도, 현재/최대/기본 내구도, 수리 가능 여부 | 수리할까, 손상된 채로 밀까, 멈출까 | 다음 결정의 조건 변화 |
| 인계·귀환 | 같은 UID의 고객 실제 사용 결과 | 지금 인계할 때의 의미를 해석 | 작품 생애의 결과와 연대기 |

### 4.2 세션 루프: 강화 후 생애로 닫히는 한 편

`제작 → 강화 판단 반복 → +10 정밀강화 → +11 이후 STOP/PUSH → 인계 → 실제 사용 결과 → 필요 시 수리 또는 다음 강화`.

고객 생애는 강화 판단의 **지연된 인과성**을 보여준다. 인계 자체가 손상을 만들지 않으며, 고객의 실제 사용과 해당 사건의 원인이 있어야만 손상 판정이 가능하다. 따라서 고객 결과는 무작위 벌금이나 고정된 연출이 아니라, 같은 작품을 계속 관찰할 이유를 만든다.

## 5. 강화 시스템을 사람의 말로 설명하면

### 5.1 일반 강화와 제작 상승감

- 일반 강화 성공은 언제나 `+1`이다.
- +5, +10, +15처럼 **5강 단위**는 작품이 성장했다는 더 강한 시각·사운드·표현의 비트다. +10을 제외하면 정밀강화, 새 부가효과, 확률 변경, 새 재료 규칙을 만들지 않는다.
- +10은 첫 경제적 안정 지점이며, +11은 손상 가능성이 처음 열리는 명확한 위험 전환점이다.
- +10, +30, +60, +90은 장기 강화에서 이미 확보한 성과를 지키는 기준점이지만, 저장·면책·새 게임 규칙을 뜻하지 않는다.

### 5.2 `+9 → +10` 정밀강화와 무기 키워드

- 정밀강화는 `+9 → +10` **한 번뿐**이다.
- 성공하면 플레이어가 얻는 것은 캐릭터 능력이나 플레이어 키워드가 아니라, **그 무기에 귀속된 태그 키워드 하나**다.
- 무기에는 세 종류의 플레이어 표시 키워드가 있다. 제작 등급에서 오는 **등급 키워드**, 정밀강화에서 오는 **태그 키워드**, 의미 있는 생애에서 오는 **사건 키워드**다.
- 이는 네 번째 장비 슬롯이 아니다. 기존 `GRADE_AFFIX / CATALYST_AFFIX / CHRONICLE_AFFIX`의 사람이 읽는 분류다.
- 태그 키워드는 **촉매 계보 + 정밀강화 방식**의 조합으로 정해진다. 정밀강화 방식은 무기 능력치·내구도와 태그 해석 문맥에만 영향을 주며, 등급이나 사건 키워드를 바꾸지 않는다.
- +10으로 플레이어 칭호를 주지 않는다. 칭호는 미래 별도 콘텐츠이며 +10 보상으로 확정되지 않았다.
- 빈 촉매 계보일 때 어떤 태그를 쓸지는 아직 미확정이다. 이 상태의 태그 쓰기/표시는 추측으로 구현하지 않는다.

### 5.3 실패가 주는 학습

강화 실패의 최종 결과는 `실패·유지` 또는 `실패·손상` 중 하나다. 강제 단계 하락과 별도 치명타 결과는 없다. +10 이하를 목표로 한 강화 실패에는 손상이 없고, +11부터 손상은 **실패했을 때에만** 가능하다.

플레이어는 실패 뒤에도 “무엇이 일어났는지, 그래서 다음에 무엇을 할 수 있는지”를 읽어야 한다. 이것이 재도전의 이유다. 무작위 결과를 숨기거나, 수리·손상·세계 사건이 서로 별개 패널티처럼 겹쳐 이해되지 않게 만들지 않는다.

### 5.4 강화 → 태그 → 생애: 메인 강화가 기억으로 남는 연결

강화는 계속 메인이다. 태그와 생애는 강화 버튼을 누른 뒤에만 붙는 별도 수집 시스템이 아니라, **한 번의 강화 판단이 작품의 정체성과 이후 이야기에 남는 세 층**이다.

```text
제작 등급으로 작품의 출발을 본다
→ +0~+9에서 STOP OR PUSH를 반복한다
→ +9 → +10에서 승인된 촉매 계보와 정밀강화 방식의 조합이 태그를 해석한다
→ 유효하게 승인된 조합이 있다면 성공 시 그 해석이 무기 태그가 된다
→ +11 이후에는 강화·수리·인계를 계속 판단한다
→ 고객의 실제 사용과 사건 결과가 같은 무기 UID에 남는다
→ 의미 있는 결과만 연대기가 되어 다음 작품을 고를 때의 기억이 된다
```

따라서 +10의 태그는 “강화를 끝냈다”는 도장이 아니다. 승인된 촉매 계보와 정밀강화 방식의 조합을 통해 이 작품이 **어떤 정체성으로 완성됐는지** 보이는 무기 정체성으로 바꾸는 전환점이다. 고객 생애도 강화와 독립된 경영 체크리스트가 아니다. 그 정체성을 가진 같은 작품이 실제로 사용된 뒤 돌아왔을 때, 플레이어는 다음 강화·수리·인계를 더 개인적인 판단으로 느낀다.

### 5.5 태그 시스템: 무기에 남는 완성 경로의 정체성

무기 키워드는 세 줄의 임의 수식어가 아니다. 각 줄은 **언제 생겼고, 무엇을 말하며, 무엇을 바꾸지 못하는지**가 다르다.

| 키워드 | 언제 생기는가 | 플레이어가 읽는 의미 | 바꾸지 않는 것 |
|---|---|---|---|
| 등급 키워드 | 제작 시 | 이 작품의 출발 품질 | 정밀강화 방식·생애 사건 |
| 태그 키워드 | `+9 → +10` 정밀강화 성공 시 | 승인된 촉매 계보와 방식의 조합으로 해석된 무기 정체성 | 등급·사건 키워드·플레이어 칭호 |
| 사건 키워드 | 의미 있는 생애 결과 시 | 이 작품이 고객과 세계에서 실제로 겪은 일 | 제작 등급·태그의 출처 |

태그가 생기는 정확한 순서는 다음과 같다.

```text
촉매 계보 → 정밀강화 방식 → 태그 키워드
```

1. **촉매 계보**는 태그가 속할 후보 가족과 계보의 범위를 정한다.
2. **정밀강화 방식**은 그 계보 안에서 태그 정체성을 해석하는 문맥을 정하고, 무기 능력치와 내구도에만 영향을 준다.
3. 유효하게 승인된 촉매 계보·방식 조합이 있는 `+9 → +10` 성공 시, 이 둘의 조합으로 해석된 태그 키워드 **정확히 하나**가 무기의 `CATALYST_AFFIX`에 기록된다. 빈 촉매 계보는 현재 태그 기록을 막는다.
4. 이후 사건이 생기더라도 사건은 `CHRONICLE_AFFIX`에 남는다. 사건이 태그를 덮어쓰거나, 태그가 등급을 바꾸지 않는다.

이 분리는 플레이어가 “이 무기는 원래 어떤 작품이었나(등급) / 내가 어떻게 완성했나(태그) / 누구와 어떤 일을 겪었나(사건)”를 한눈에 구별하게 한다. 네 번째 affix 슬롯, +10 플레이어 칭호, 일반 강화에서의 태그 생성, +20 이후의 추가 정밀강화는 현재 범위에 없다.

**현재 미확정:** 실제 태그 이름·표시 문구·촉매 계보와 방식의 조합표, 그리고 빈 촉매 계보일 때의 선택/기본값/차단 흐름은 승인되지 않았다. **선택 UX는 아직 미확정**이므로, 이 빈자리를 임시 태그나 AI가 지은 이름으로 채우지 않는다. 현재 구현의 `PRECISION_KEYWORD_PENDING_CONTENT`는 플레이어에게 보여 줄 태그가 아닌 **내부 임시 값**과 구현 흔적일 뿐, 제품 태그 콘텐츠가 아니다.

## 6. 내구도·수리: 손해가 아니라 다음 판단의 재료

무기는 보이는 세 숫자로만 상태를 판단한다.

```text
현재 내구도 / 최대 내구도 / 기본 최대 내구도
```

- 현재 내구도는 지금의 손상이다.
- 최대 내구도는 남아 있는 구조적 상한이다.
- 기본 최대 내구도는 태어났을 때의 기준이다.
- 화면의 상태(정상·경미·중대·파괴)는 위 숫자에서 계산한 **하나의 유효 상태**다. 현재 손상과 최대 내구도 흉터를 두 개의 숨은 벌점으로 중첩하지 않는다.

실제 손상으로 현재 내구도가 내려간 작품만 수리 작업을 한 번 열 수 있다. 파괴된 작품은 수리할 수 없고, 이미 가득 찬 현재 내구도를 다시 수리할 수도 없다. 수리는 현재 내구도를 회복시키지만 최대 내구도 회복은 아직 승인되지 않았다. 결과 품질과 최대 내구도 흉터 가능성은 다음 강화 선택을 더 입체적으로 만들기 위한 **현재 테스트 예산**이며, 최종 밸런스가 아니다.

중대 상태라고 강화가 막히지는 않는다. 플레이어는 수리, 손상 상태의 도전, 멈춤/인계 중 하나를 스스로 택한다. 이 선택이 수리 시스템이 강화의 재미를 가리는 대신 강화의 STOP OR PUSH를 더 깊게 만드는 기준이다.

## 7. 고객과 작품의 생애

고객 콘텐츠의 목표는 고객 관리량을 늘리는 것이 아니라, **내가 강화한 바로 그 작품이 누군가의 삶에서 실제로 쓰였다는 결과**를 보여주는 것이다.

- 인계나 구매 그 자체는 손상을 만들지 않는다.
- 실제 사용이 있어야 손상 판정을 할 수 있다.
- 하나의 사건은 하나의 무기 UID에 최대 한 번만 손상 판정을 한다.
- 임무 성패와 아이템 손상은 같은 축이 아니다. 좋은 결과여도 손상될 수 있고, 나쁜 결과여도 손상되지 않을 수 있다.
- 세계 사건은 최대 내구도를 직접 깎지 않는다. 실제 손상이 발생했다면 현재 내구도와 상태는 내구도 규칙이 처리한다.
- 사건 키워드는 단순 인계나 화면 표시만으로 자동 지급하지 않는다. 의미 있는 사건만 연대기에 남긴다.

플레이어가 첫 세션에서 기억해야 할 장면은 “+10을 만든 무기가 고객에게 갔고, 그 무기가 돌아왔을 때 내가 올린 강화와 남긴 흔적을 다시 보았다”는 것이다.

### 7.1 생애 주기: 고객의 실제 사용으로 닫히는 흐름

생애 주기는 고객 수를 늘리거나 대기 시간을 관리하는 루프가 아니다. 한 무기 UID를 끝까지 추적해 강화의 결과를 다시 플레이어의 다음 판단으로 돌려주는 짧은 닫힌 흐름이다.

```text
제작·등급 기록
→ 강화와 +10 태그
→ 인계
→ 실제 사용
→ 사건 결과
→ 내구도·수리 가능 여부·연대기 확인
→ 다음 강화 / 수리 / 다음 인계 판단
```

핵심 연결은 다음 한 줄로 기억한다.

```text
인계 → 실제 사용 → 사건 결과 → 다음 판단
```

- **인계:** 같은 물리 무기 UID가 고객에게 간다는 소유 변화다. 인계·구매·보유 기간·메뉴 조작만으로는 손상이 나지 않는다.
- **실제 사용:** 고객이 그 작품을 사건에서 실제로 사용했을 때만 결과가 열린다. 그러므로 “내가 만든 검이 쓰였다”는 인과가 먼저 보인다.
- **사건 결과:** 임무의 성패와 무기 손상은 독립된 두 결과다. 좋은 임무가 곧 무손상, 나쁜 임무가 곧 손상을 뜻하지 않는다.
- **다음 판단:** 실제 손상이 생기면 현재 내구도가 줄고 그때만 한 번의 수리 작업이 열릴 수 있다. 손상이 없으면 작품을 확인하고 다음 강화 또는 다음 인계를 판단한다.

### 7.2 고객 이벤트: 결과의 원인을 보여 주는 규칙

고객 이벤트는 “랜덤하게 내구도를 깎는 알림”이 아니다. 각 이벤트는 **같은 UID, 실제 사용, 선언된 위험 프로필, 사건 원인**을 갖고 결과를 남긴다.

| 이벤트에서 확인할 것 | 플레이어에게 필요한 답 | 보호 규칙 |
|---|---|---|
| 실제 사용 여부 | 이 무기가 정말 쓰였는가 | 실제 사용이 없으면 손상 판정 없음 |
| 사건 원인 | 왜 이 결과가 일어났는가 | 손상 시 실제 원인과 같은 UID의 전후 내구도를 공개 |
| 위험 프로필 | 이 사건이 작품을 얼마나 험하게 다루는가 | 임시 수치로 보편 확률을 모든 고객 카드에 강요하지 않음 |
| 손상 판정 | 이번 사건이 작품 상태를 바꾸었는가 | 한 사건·한 UID에 최대 한 번, 세계 사건은 MAX를 직접 손상하지 않음 |
| 다음 행동 | 지금 무엇을 할 수 있는가 | 실제 손상 후에만 수리 작업 가능 여부를 표시 |

현재 테스트 프로필은 `NONE / LOW / MEDIUM / HIGH / DIRECT`를 사용하지만, 이는 최종 밸런스 표가 아니다. 확률형 프로필은 현재 내구도 상태에 따라 조정될 수 있고, `DIRECT`는 한 번의 손상을 확정한다. 사건과 명시적으로 관련된 무기 키워드 또는 기능만 확률형 프로필을 최대 한 단계 낮출 수 있다. 모든 태그가 어느 사건에나 보편 방어력으로 작동하지 않으며, 일반 키워드로 `DIRECT`를 무효화할 수도 없다.

### 7.3 대표 한 편: 강화한 작품이 고객의 기억이 되는 순간

1. 플레이어는 한 무기의 등급과 내구도를 보고 +9까지 강화한다.
2. `+9 → +10`에서 유효하게 승인된 촉매 계보와 정밀강화 방식의 조합으로 태그가 해석된다. 성공하면 이 무기에만 태그 하나가 남는다. 빈 촉매 계보는 현재 태그 기록을 막으며, 실제 선택 UX는 아직 미확정이다.
3. +11의 위험을 읽고 멈추거나 밀어 본다. 실패했다면 유지 또는 손상이라는 읽을 수 있는 결과를 받고, 손상이라면 수리·손상된 상태의 재도전·인계 중 하나를 고른다.
4. 인계 뒤 고객이 **같은 무기를 실제 사용**한 사건 결과를 확인한다. 손상이 발생했을 때 결과 화면은 실제 원인, 같은 UID의 내구도 전후, 수리 가능 여부와 다음 행동을 보여 줘야 한다.
5. 제작·태그·의미 있는 손상/수리/인계/세계 결과만 연대기에 남는다. 일반 강화 버튼을 누른 모든 기록은 연대기로 쌓지 않는다.

이 한 편이 성공하면 플레이어는 “고객 이벤트를 하나 처리했다”가 아니라, **“내가 +10에서 완성한 그 무기가 누군가에게 쓰였고, 이제 내가 이 작품을 어떻게 이어 갈지 다시 정한다”**고 말할 수 있어야 한다.

## 8. 화면과 정보 우선순위

세로형 화면에서 가장 먼저 읽혀야 하는 것은 장식이 아니라 다음 결정이다.

1. **작품 정체성:** 이름/무기, 강화 단계, 등급, 태그·사건 키워드.
2. **이번 결정:** 목표 단계, 성공·실패·손상 결과, 비용, STOP 또는 PUSH의 의미.
3. **상태 변화:** 전후 강화와 내구도, 수리 가능 여부, 다음 행동.
4. **생애 맥락:** 어느 고객의 실제 사용 결과인지, 왜 일어났는지, 연대기에 남는가.

현재 구현 근거에는 `vertical_slice` 공방 화면, 고객 결과 화면, 강화·정밀강화·수리·고객 실제사용 resolver가 있다. 그러나 실제 클라이언트에서 이 정보 위계가 충분히 읽히는지, 터치가 편한지, Android 세로형 해상도에서 합성되는지는 아직 별도 실행 증거가 필요하다.

## 9. 시각·사운드 언어

현재 승인된 시각 방향은 `ILLUSTRATED_WORKSHOP_BOOK`이다. 따뜻한 손그림 공방 노트의 종이·가죽·철·목재 물성과, 게임 조작에 필요한 현대적이고 선명한 정보 계층을 함께 쓴다.

- **Keep:** 따뜻한 공방의 손맛, 작품을 기록하는 책 같은 정서, 한눈에 읽히는 강화 결과.
- **Avoid:** 검정·금색 위주의 과거 `STYLIZED_DARK_FORGE` 보드를 최종 그림체로 되살리는 일, 장식 때문에 확률·내구도·다음 행동을 가리는 UI.
- **Do Not Drift:** 고객·환경·UI·VFX가 서로 다른 게임처럼 보이거나, AI 이미지 안의 가짜 텍스트를 실제 규칙처럼 취급하는 일.

새 이미지는 실제 게임 consumer와 해상도·상태 요구·권리 기록이 있을 때만 만든다. 생성 후보는 곧바로 제품 에셋이나 구현 완료가 아니며, 최종 방향 잠금 또는 런타임 승격만 사용자 확인을 받는다.

| 적대 가정: 기능 목록만 남는가 | `IMPROVE` | 모든 핵심 시스템을 STOP OR PUSH → 즉시 결과 → 생애의 지연된 인과성에 다시 연결했다. |
| 적대 가정: +10 보상이 플레이어 키워드로 오해되는가 | `PROTECT` | 무기 귀속 태그, 촉매 계보+정밀강화 방식, 플레이어 칭호 제외를 명시했다. |
| 적대 가정: 태그와 고객 생애가 한 줄 요약에 그치는가 | `IMPROVE` | 태그가 만들어지는 순서, 세 키워드의 역할, 실제 사용 기반 고객 이벤트, 결과 후 다음 판단을 독립 설명으로 보강했다. |
| 적대 가정: 시각 자료가 곧 구현으로 오해되는가 | `MITIGATE` | 이미지 후보·승인·runtime evidence의 구분과 실제 consumer gate를 유지했다. |

외부 사례는 요구사항을 자동으로 만들지 않으며, Blacksmith 고유의 작품 UID 생애와 강화 우선 원칙을 대체하지 않는다.


### 인접 사례 결론

| 사례 | 참고할 점 | ADOPT / ADAPT / REJECT |
|---|---|---|
| Shop Titans | 제작품이 고객/모험의 맥락을 얻는 감정적 프레이밍 | `ADAPT`: 강화한 작품이 고객의 실제 사용 결과로 돌아오는 감정. `REJECT`: 시장·길드·다중 상점 관리층. |

**차별점:** Blacksmith는 판매/던전의 양방향 루프가 아니라, 한 무기 UID에 강화 판단의 결과가 고객 실제 사용·손상·수리·사건·연대기로 축적되는 구조다. **남은 불확실성:** 6~8분 Slice에서 플레이어가 강화 자체를 충분히 즐긴 뒤 생애 결과를 “보너스가 아닌 내 선택의 결과”로 느끼는지는 아직 `NOT_RUN`이다.

조사 원문은 [Godot UI layout](https://docs.godotengine.org/en/stable/tutorials/ui/size_and_anchors.html), [Godot Android export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html), [Android game design](https://developer.android.com/games/design/overview?hl=en), [Android vitals](https://developer.android.com/games/optimize/vitals), [Shop Titans Steam page](https://store.steampowered.com/app/1258080/Shop_Titans/), [Moonlighter Steam page](https://store.steampowered.com/app/606150/Moonlighter/)를 기준으로 2026-08-28 KST에 확인했다. 이 링크는 구현·출시·권리·시장 적합성의 자동 PASS가 아니라 이번 판단의 외부 근거다.
