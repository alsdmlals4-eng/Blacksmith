# Blacksmith 강화 코어 재정렬 — 5회 적대적 검토

- 대상: `BS-CORE-20260820-01` 및 강화 DDD 재설계 제안
- 상태: `PLAN_REVIEW_EVIDENCE`
- Human/Player evidence: `NOT_RUN`

## Loop 1

전체 공격:
- 강화가 메인이라면서 정밀제작·고객·생애 정보가 화면과 플레이 시간을 장악하면 정본과 실제 경험이 다시 뒤집힌다.
- DDD를 반복 클릭/확률 자극으로 오해할 위험이 있다.

검증:
- 현재 기존 기획은 고객/작품 생애 세부 Decision이 매우 많고, 실제로 강화보다 문서 복잡성이 커질 위험이 있다.

개선:
- 모든 보조 시스템에 `강화 전 고민 / 결과 체감 / 다음 강화 이유` 삭제 테스트를 적용.
- DDD는 행동→기대→피드백→보상/손실→다음 질문 계약으로 제한.

재검사: 새 코어 계층과 일치.

## Loop 2

전체 공격:
- 순수 확률 강화는 긴장보다 도박성·피로·운 의존을 키울 수 있다.
- 실패 연속이 무의미하면 사용자가 게임을 끌 이유가 생긴다.

검증:
- Lost Ark 공식 팀 메시지도 낮은 확률 성공의 환희와 반복 실패·재료 부족의 좌절을 함께 언급하고 이후 비용/재료/성공률 완화를 반복했다.

개선:
- `RISK_PLUS_RECOVERY_PROGRESS`를 우선 후보로 올림.
- 최대 bad-luck window를 Balance Budget의 필수 변수로 둠.

재검사: 긴장감은 유지하면서 실패 피로 제어 가능.

## Loop 3

전체 공격:
- 실패 보호가 강하면 실패가 사실상 진전 게이지가 되어 긴장이 사라질 수 있다.
- 보호 아이템/비용이 매번 정답이면 선택이 아니라 세금이다.

검증:
- MapleStory Star Force 공식 구조처럼 고위험 구간과 보호 수단을 분리하는 원리는 쓸 수 있지만 그대로 가져오면 장기 MMO 경제에 종속된다.

개선:
- 실패 누적은 보조 장치이며 성공을 빠르게 확정하는 주 진행바가 되지 않도록 상한/효율 조정.
- 보호 선택은 특정 고위험 구간에서만 제공하고 opportunity cost를 갖게 함.

재검사: 일반 강화 반복 리듬 보존.

## Loop 4

전체 공격:
- 작품 생애를 보조로 내렸다고 해서 실패마다 작품을 파괴하면 UID 애착이 오히려 강화 버튼을 누르지 못하게 만들 수 있다.
- 반대로 아무 손실도 없으면 긴장감이 부족하다.

검증:
- 현재 프로젝트는 같은 UID 생애와 기록을 강한 보조 가치로 이미 구현/보존한다.

개선:
- 기본 실패는 `FAIL_HOLD / FAIL_DAMAGE`.
- 고위험에서는 `CRITICAL_BREAK_UID_PRESERVED`를 우선 후보로 둠.
- 실제 UID 영구 삭제는 기본 계약에서 제외.

재검사: 강화 위험과 작품 애착을 동시에 유지.

## Loop 5

전체 공격:
- 성공률·손실을 숨기면 긴장은 커질 수 있으나 결과가 불공정하게 느껴진다.
- 모든 정보를 숫자로 펼치면 모바일 화면이 계산표가 된다.

검증:
- 프로젝트 기존 고객 UX는 이미 핵심 원인 2~4개만 전면에 두는 정보 계층 원칙을 갖는다.

개선:
- 강화 화면에는 `성공 기대 / 시도 비용 / 주요 실패 결과 / 보호 효과 / 다음 확보점`만 전면 노출.
- 세부 수학은 상세 보기.
- 확률에 직접 영향을 주는 실패 누적은 숨기지 않음.

재검사:
- 강화 전 핵심 판단 정보는 읽을 수 있고, 화면 정보량은 제한 가능.

## 5회 후 Better Alternative Search

비교:
- 순수 위험 사다리: 단순하지만 실패 피로가 가장 큼.
- 매 시도 위험 모드: 플레이어 표현은 크지만 반복 UX가 느려지고 정밀강화와 충돌.
- 위험 + 회복 누적: 일반 강화의 빠른 리듬과 실패 피로 제어의 균형이 가장 좋음.

현재 장기 권장:

`RISK_PLUS_RECOVERY_PROGRESS` 기본 + `PER_ATTEMPT_RISK_MODE`는 이정표/고위험 구간에만 부분 흡수.

CLEAN EXIT 제한:
- 기획 구조 공격은 5회 완료.
- 정확한 확률/경제/손상량은 `NOT_FINAL`.
- Human/Player evidence가 없으므로 재미 PASS는 선언하지 않는다.
