## 1. 플레이어 경험 약속

플레이어는 세로형 모바일 화면에서 다음 흐름을 즉시 이해해야 한다.

```text
제작/강화 후보 선택
→ 필요한 재료·비용·성공/실패 위험 비교
→ 실행 전 잃고 얻을 것 확인
→ 터치 입력 접수와 작업 진행 확인
→ 제작 결과와 장비 변화 확인
→ 다음 제작·판매·장착 행동 선택
```

핵심 감정은 **작은 성취의 연속**, **위험을 감수한 강화의 긴장**, **내가 만든 장비가 성장했다는 소유감**이다.

## 2. 범위와 보호 대상

### 포함

- Android 세로형 터치 UI
- 제작·강화·판매·장착의 정보 구조
- 재료·비용·성공 가능성·실패 손실 비교
- 입력 접수·진행·성공·실패 피드백
- 안전 영역·긴 한국어·한 손 조작
- 복귀 플레이어의 현재 목표와 최근 제작 결과

### 제외

- 제작·강화 확률과 경제 수치 변경
- 저장·인벤토리·장비 규칙 재계산
- 제품 Scene·script·data·asset 수정
- HTML 기획 대시보드

권위 상태와 계산은 기존 게임 시스템이 소유한다. UI는 표시 데이터를 받고 사용자 의도를 Signal/Command로 반환한다.

## 3. 화면별 중심 질문

| 화면/단계 | 중심 질문 | 첫 시선 | 핵심 행동 | 결과·복귀 |
|---|---|---|---|---|
| 제작 허브 | 지금 무엇을 만들 것인가 | 제작 후보와 부족 재료 | 후보 선택 | 상세 비교로 이동 |
| 제작 상세 | 비용을 감수할 가치가 있는가 | 결과 장비와 비용 | 제작 실행 | 결과 카드·인벤토리 반영 |
| 강화 상세 | 현재 위험을 감수할 것인가 | 전후 수치·실패 손실 | 강화/취소 | 인과가 보이는 결과 |
| 장비/인벤토리 | 무엇을 장착·판매할 것인가 | 현재 장착과 비교 차이 | 장착/판매 | 캐릭터 변화 확인 |
| 결과/복귀 | 방금 무엇이 바뀌었는가 | 새 장비·재료·다음 목표 | 계속 제작 | 허브의 의미 있는 위치 복귀 |

| `UXP-EMPTY-LOCKED-FALLBACK` | ADOPT | 빈 인벤토리·잠금·누락 이미지에서도 다음 행동 유지 |

## 5. 모바일 입력·상태 계약

- 핵심 행동은 한 손 엄지 도달 영역 안에서 완결한다.
- 터치 대상은 겹치지 않으며 스크롤과 실행 제스처를 혼동시키지 않는다.
- `focused/selected`, `disabled/locked`, `loading/error`를 같은 색 변화 하나로 표현하지 않는다.
- 실행 버튼은 결과 행동을 말한다: `확인`보다 `강화 재료 3개 사용`.
- 위험 강화는 성공 가능성만 강조하지 않고 실패 손실과 취소 경로를 함께 표시한다.
- 팝업 종료 뒤 팝업을 연 제작/장비 항목으로 돌아간다.

## 6. Godot 구현 경계

```text
제작·경제 권위 상태
→ 화면용 View Data
→ Control/Container/Theme 표시
→ 제작·강화·장착 요청 Signal
→ 도메인 처리
→ 결과 Event와 새 상태
→ UI 결과·복기 갱신
```

금지:

- 버튼 callback에서 장비·재료·골드 지급
- UI 애니메이션 완료를 제작 성공 시점으로 사용
- 화면마다 같은 비용/확률 계산 복제
- 기존 Theme·레이아웃 조사 없이 새 UI 프레임워크 추가

## 7. 접근성·폴백

- 성공/실패·희귀도·위험을 색만으로 구분하지 않는다.
- 음향·진동을 꺼도 상태와 결과를 텍스트·아이콘으로 확인한다.
- 작업 연출을 줄이거나 건너뛰어도 결과와 다음 행동이 남는다.
- 긴 한국어·최대 수치·작은 화면·safe area에서 잘림과 오입력을 검증한다.
- 이미지 누락 시 기본 도형·이름·수치로 제작과 장착 기능을 유지한다.

## 7A. UI 모션·중단·반복 계약

```text
입력 접수 → 처리 중 → 도메인 결과 확정 → 결과 표현
```

- 반복 클릭·제작·강화·보상 수령은 중복 지급·중복 소비·transform drift 없이 재진입해야 한다.
- 모션은 중단과 즉시 완료 경로를 가지며, 취소·건너뛰기 후에도 도메인 상태와 결과 카드가 동일해야 한다.
- `AnimationPlayer`·`Tween` 완료 signal은 제작 성공·재료 소비·보상·저장 권위 시점이 아니다.
- `Reduced Motion`, `mute`, `haptic-off`에서도 결과·위험·다음 행동을 텍스트·아이콘으로 보존한다.
- Android 반복 피로·기기 성능·사람 이해는 `NOT_RUN` 또는 `HUMAN_NOT_RUN`으로 유지한다.

## 9. 공용 승격과 프로젝트 전용

### Base 공용으로 유지

- 실행 전 예측, 비교 가능한 선택, 오류 복구, 다중 채널, 결과 인과
- UI가 도메인 규칙을 소유하지 않는 Godot 계약
- 자동·런타임·사람 증거 분리

### Blacksmith 전용

- 제작·강화·판매·장착 흐름
- 실제 재료·확률·장비 수치와 위험 단계
- Android 세로형 레이아웃·터치 위치·실기기 결과
