## 결정 83 — 방문 고객 거래 제품은 플레이어가 직접 선택

`[방문 고객]`이 장비 범주를 요청했을 때, 해당 범주에 속하는 판매 가능한 `[보관함]` 제품 중 **플레이어가 직접 하나를 선택**한다.

시스템은 가장 비싼 제품, 가장 높은 강화 제품, 정렬상 첫 제품 또는 최근 제작 제품을 자동으로 선택하지 않는다.

```text
요청 종류: 무기
→ 보관함의 판매 가능한 무기 목록 표시
→ 제품별 정보·거래 결과 비교
→ 플레이어가 제품 하나 선택
→ 최종 거래 확인
→ 거래 원자적 확정
```

## 기본 선택 없음

제품 선택 화면은 기본 선택 상태 없이 시작한다.

- 첫 번째 제품을 자동 선택하지 않는다.
- 추천 제품을 자동 확정 대상으로 지정하지 않는다.
- 정렬 변경이 선택 확정으로 이어지지 않는다.
- 화면 진입만으로 제품을 예약하지 않는다.
- 이전에 다른 요청에서 검토하던 제품을 자동으로 이어서 선택하지 않는다.

플레이어가 명시적으로 제품을 누르기 전에는 거래 대상 제품이 없다.

## 선택 후보

다음 조건을 모두 충족하는 제품은 요청 범주 안에서 동일하게 선택 가능하다.

```text
제작 완료
+ 보관함에 존재
+ 판매 가능
+ 요청 범주 일치
+ 다른 거래로 소유권이 이전되지 않음
+ 영구 파괴·소실 상태가 아님
→ 선택 후보
```

후보 자격을 차단하지 않는 요소:

- 낮은 강화 단계
- 정밀강화 미실행
- 고위 정밀강화 미실행
- 진화 미실행
- 수식어 부재
- 낮은 역사 가치

이 요소는 제품 가치·가격·세계 후속 결과에 영향을 줄 수 있지만, 요청 범주가 일치하는 제품의 선택 버튼을 비활성화하지 않는다.

## 표시 정보

제품 선택 목록과 상세 비교에는 최소 다음 정보를 표시한다.

- 제품 이름
- 세부 장비 종류
- 요청 범주
- 현재 강화 단계
- 정밀강화·고위 정밀강화 결과
- 진화 여부
- 대표 수식어와 보조 수식어
- 제작자와 현재 소유자
- 역사 가치·장비 연대기 요약
- 방문 고객 거래 가격
- 방문 고객 추가 보상 또는 관계·후속 가능성
- 판매 후 보관함에서 제외되고 소유권이 이전된다는 사실
- 이미 활성 세계 활동·중요 연대기와 연결된 제품이면 해당 사실

내구도 수치·내구도 조건은 표시하지 않는다.

## 비교 방식

플레이어는 같은 범주 제품을 비교할 수 있다.

```text
무기 요청

장검 A
- 강화 +12
- 판매 가격 1,200
- 대표 수식어 없음

도끼 B
- 강화 +24
- 판매 가격 2,100
- 대표 수식어: 파쇄

창 C
- 강화 +8
- 판매 가격 900
- 역사 가치 높음
```

정확한 가격 수치와 표시 항목의 우선순위는 후속 경제·UI 결정에서 확정한다.

비교 화면은 특정 제품을 정답으로 표시하지 않는다. 높은 가격 제품을 판매할지, 낮은 강화 제품을 처분할지, 중요한 연대기 제품을 보관할지는 플레이어 판단이다.

## 선택과 예약의 분리

제품을 한 번 선택해 상세 거래 결과를 보는 것은 아직 예약이나 소유권 이전이 아니다.

```text
제품 선택
→ 예상 거래 결과 확인
→ 취소·다른 제품 선택 가능
→ 최종 확인 전까지 보관함 소유 유지
```

원칙:

- 선택 미리보기 중 다른 요청 후보 목록에서도 제품을 숨기지 않는다.
- 일반 판매 화면에서도 최종 확정 전까지 판매 가능 상태를 유지할 수 있다.
- 동시에 두 비가역 확정이 시작되지 않도록 최종 거래 처리 동안만 제품 잠금을 사용한다.
- 장기 예약 상태는 사용하지 않는다.
- 선택을 취소하면 어떤 제품 상태도 변경되지 않는다.

## 최종 확인

거래 확정 전 최소 다음 정보를 다시 표시한다.

- 방문 고객 또는 고객 유형
- 요청 종류
- 선택 제품
- 제품 강화·수식어·진화 요약
- 지급 가격과 추가 보상
- 소유권 이전
- 보관함 제외
- 관계·약속·후속 세계 활동 생성 여부
- 취소 불가능한 비가역 행동이라는 사실

위험 등급과 기존 입력 계약에 따라 확인 또는 길게 누르기 입력을 사용한다. 접근성 대체 입력은 기존 계약을 따른다.

## 거래 원자성

최종 확정 시 다음 상태를 하나의 원자적 결과로 저장한다.

- 선택 제품 식별자
- 제품의 보관함 제외
- 기존 장비 식별자 유지
- 방문 고객에게 소유권 이전
- 판매 가격과 보상 지급
- 관계·약속·구독 상태 변경
- 후속 세계 활동 생성 여부
- 장비 연대기 거래 기록
- 방문 고객 요청 상태를 `거래 완료`로 변경
- 같은 제품이 다른 요청·일반 판매에서 판매 불가로 갱신

```text
제품 선택
+ 보상
+ 소유권 이전
+ 보관함 제외
+ 고객 요청 완료
+ 후속 상태
→ 원자적 저장
→ 이후 성공 연출
```

저장 완료 전에 성공 연출, 세계 활동 진입 또는 보상 사용을 허용하지 않는다.

## 취소·이탈·앱 종료

- 최종 확인 전에 취소하면 거래가 발생하지 않는다.
- 제품 선택 화면에서 다른 탭으로 이동해도 소유권은 변하지 않는다.
- 앱 종료 후 선택 미리보기 상태를 복구할 수 있으나, 임의로 다른 제품을 선택하지 않는다.
- 선택 상태를 복구하지 못하면 미선택 상태로 돌아가되 제품·보상·요청 상태는 이전 확정 상태를 유지한다.
- 최종 거래 저장 중 앱이 종료되면 원자적 저장 결과에 따라 거래 전 또는 거래 완료 상태 중 하나로 복귀한다.
- 제품이 보관함에서 사라졌는데 요청이 활성인 중간 상태를 허용하지 않는다.

## 동일 제품이 여러 요청 후보인 경우

같은 제품이 두 활성 요청 범주에 모두 속할 수 있다.

```text
제품 X
├─ 요청 A 후보
└─ 요청 B 후보
```

- 요청 A에서 제품 X를 미리 선택해도 요청 B 후보에서 숨기지 않는다.
- 요청 A의 최종 거래가 확정되면 요청 B에서는 즉시 판매 불가가 된다.
- 요청 B는 자동 거절·만료되지 않는다.
- 요청 B는 다른 제품으로 대응하거나 기한까지 보류할 수 있다.
- 제품 복제·중복 보상·동시 거래 확정은 금지한다.

## 일반 판매와의 관계

방문 고객 요청에 적합한 제품도 최종 거래 확정 전에는 일반 판매할 수 있다.

일반 판매 시 활성 방문 고객 요청 후보라는 사실과 영향을 받는 요청을 경고한다.

```text
무기 요청 활성
+ 장검 A를 방문 고객 선택 미리보기 중
→ 일반 판매 진입
→ 활성 요청 후보 경고
→ 일반 판매 확정
→ 장검 A 보관함 제외
→ 방문 고객 선택 상태 해제
→ 요청은 다른 무기로 계속 대응 가능
```

동시에 방문 고객 거래와 일반 판매를 확정하지 않도록 제품 단위 비가역 거래 잠금을 사용한다.

## 정렬·필터

제품 목록은 다음 정렬·필터를 제공할 수 있다.

- 강화 단계
- 예상 거래 가격
- 세부 장비 종류
- 제작 시점
- 수식어·진화 여부
- 역사 가치 또는 중요 연대기 연결 여부

정렬·필터는 탐색 보조 기능이다.

- 정렬 첫 제품 자동 선택 금지
- 추천 정렬이 자동 확정 순서가 되는 것 금지
- 필터 때문에 선택 중인 제품이 숨겨져도 거래가 자동 확정되거나 취소되지 않음
- 필터 해제 시 동일 제품 식별자로 복귀

## 접근성

- 제품 목록의 읽기 순서를 안정적으로 유지한다.
- 제품 이름, 강화 단계, 가격, 중요 연대기 연결, 선택 버튼을 화면 읽기 환경에서 구분한다.
- 색상만으로 고가·중요·선택 상태를 구분하지 않는다.
- 텍스트 확대 상태에서도 제품 비교와 최종 확인이 가능해야 한다.
- 기본 선택이 없다는 상태를 화면 읽기 환경에서도 알 수 있어야 한다.
- 길게 누르기 확인의 두 단계 접근성 대체 입력을 유지한다.

## 성능

- 제품 목록과 비교 정보는 데이터 상태에서 결정하며 연출이 선택 결과를 바꾸지 않는다.
- 목록이 길어져도 강화 화면·판매 입력·저장 무결성을 저하시키지 않는다.
- 저사양 기기에서는 제품 카드 시각 효과를 줄일 수 있지만 비교 정보는 유지한다.
- 제품 정렬이나 필터 변경으로 판매 가격·보상·요청 결과를 재추첨하지 않는다.

## 버티컬 슬라이스 검증

최소 다음 시나리오를 검증한다.

1. 같은 요청 범주에 속하는 제품 3개 이상 표시
2. 기본 선택 없이 목록 시작
3. 낮은 강화 제품도 선택 가능
4. 제품 A 선택 후 제품 B로 변경 가능
5. 최종 확인 전 취소 시 상태 변화 없음
6. 최종 거래 후 정확한 제품 하나만 보관함에서 제외
7. 같은 제품이 두 요청 후보일 때 한쪽 거래 후 다른 쪽 판매 불가 갱신
8. 일반 판매와 방문 고객 거래 동시 확정 방지
9. 앱 종료·복귀 후 임의 제품 변경·중복 보상 없음
10. 화면 읽기·텍스트 확대·대체 확인 입력으로 거래 완료
11. 내구도 관련 정보가 어떤 후보 판정·표시에도 존재하지 않음

## 선행 결정과의 관계

추가 결정 28의 다음 원칙을 구체화한다.

- 방문 고객은 장비 범주만 요청
- 범주에 속하는 판매 가능한 제품은 모두 후보
- 강화는 거래 자격이 아니라 가치 판단
- 내구도 시스템 없음
- 거래 제품은 플레이어가 선택
