## 신규 방문 고객 발생 시점

`[방문 고객]` 신규 요청의 일반 발생 판정은 **영업일 시작 시 최대 한 번만** 수행한다.

제작·강화·수리·일반 판매 같은 개별 영업 행동을 반복한다고 신규 고객 발생 판정이 추가로 실행되지 않는다. 앱 종료·복귀나 화면 전환도 같은 영업일의 발생 판정을 다시 수행하지 않는다.

```text
다음 영업일 시작
→ 미확인 비가역 결과와 만료 결과 정리
→ 활성 방문 고객 요청 수 확인
→ 빈 슬롯이 있으면 신규 요청 발생 판정 최대 1회
→ 발생 결과 원자적 저장
→ 일반 영업 시작
```

## 영업일 시작 처리 순서

신규 요청 발생 판정은 다음 순서 뒤에 수행한다.

1. 이전 영업 종료 체크포인트 복구
2. 미확인 강화·판매·세계 결과 정리
3. 방문 고객 요청의 거래·거절·만료 확정 상태 정리
4. 만료로 해제된 요청 슬롯 반영
5. 현재 활성 요청 수 계산
6. 신규 요청 발생 자격과 확정 트리거 확인
7. 영업일당 최대 한 번의 신규 요청 발생 판정
8. 발생 또는 미발생 결과 저장
9. 플레이어에게 일반 영업 조작 허용

이 순서를 통해 만료 결과를 확인하기 전에 새 고객이 같은 슬롯을 덮어쓰거나, 복구 과정에서 신규 요청이 중복 생성되는 문제를 방지한다.

## 영업일당 판정 횟수

### 일반 규칙

- 신규 요청 발생 판정: 영업일당 최대 1회
- 일반 무작위 요청 생성: 영업일당 최대 1개
- 빈 슬롯이 2개여도 한 번의 일반 판정으로 2개를 동시에 생성하지 않음
- 활성 요청이 2개면 일반 발생 판정을 수행하지 않음
- 요청이 0개 또는 1개이면 발생 자격을 가짐
- 요청 미발생 영업일을 허용함

```text
활성 요청 0개
→ 발생 판정 1회
→ 신규 요청 0개 또는 1개

활성 요청 1개
→ 발생 판정 1회
→ 신규 요청 0개 또는 1개

활성 요청 2개
→ 일반 발생 판정 생략
→ 신규 요청 0개
```

## 행동 반복에 의한 추가 판정 금지

다음 행동은 신규 방문 고객 발생 판정을 실행하지 않는다.

- 장비 제작 시작 또는 완료
- 일반 강화·정밀강화·고위 정밀강화
- 수리·정비
- 보관함 열기·정렬·필터 변경
- 일반 판매
- 방문 고객 요청 상세 열기
- 제품 제안 미리보기
- 거래·거절 확정 후 같은 영업일에 남은 슬롯 확인
- `[대장간]`, `[방문 고객]`, `[세계]` 탭 이동
- 앱 백그라운드 전환과 복귀
- 앱 재실행

기존 요청이 영업일 도중 거래·거절로 종료돼 슬롯이 비더라도, 해당 영업일의 일반 발생 판정을 이미 완료했다면 추가 요청을 즉시 생성하지 않는다. 다음 영업일 시작 판정까지 기다린다.

```text
영업일 시작
→ 일반 발생 판정 완료
→ 요청 A 거래 완료
→ 슬롯 1개 해제
→ 같은 영업일 추가 판정 없음
→ 다음 영업일 시작 시 다시 판정 가능
```

## 판정 완료 상태 저장

같은 영업일에 발생 판정을 반복하지 않도록 영업일 상태에 다음 정보를 저장한다.

- 현재 영업일 식별자
- 해당 영업일 신규 요청 판정 수행 여부
- 판정 유형: 일반 또는 확정 트리거
- 판정 결과: 발생·미발생·슬롯 포화로 생략
- 생성된 요청 식별자
- 생성 결과 저장 완료 여부

무결성 원칙:

- 앱 재실행 후 판정 수행 여부를 복구함
- 판정 결과 저장 전 요청 발생 연출을 시작하지 않음
- 생성 요청과 판정 완료 상태를 함께 원자적으로 저장함
- 요청만 생성되고 판정 완료 표식이 누락되는 상태를 금지함
- 판정 완료 표식만 있고 요청 데이터가 없는 상태를 무결성 오류로 처리함
- 발생 결과를 연출 애니메이션이나 불씨 정령 반응이 결정하지 않음

## 일반 무작위 요청

일반 요청은 영업일 시작 판정에서 다음 절차를 사용한다.

```text
활성 슬롯 확인
→ 일반 요청 발생 여부 판정
→ 발생 시 요청 후보 풀 결정
→ 장비 종류·조건·고객 유형·보상·기한 구성
→ 현재 활성 요청과 충돌 검사
→ 요청 데이터 원자적 저장
→ 방문 고객 알림 표시
```

정확한 발생 확률, 고객 유형 가중치, 장비 종류 분포와 중복 억제 규칙은 후속 결정에서 확정한다.

일반 요청은 다음을 보장하지 않는다.

- 매 영업일 반드시 발생
- 빈 슬롯을 항상 채움
- 현재 보관함에 있는 제품과 반드시 일치
- 항상 서로 다른 고객 유형
- 항상 서로 다른 장비 종류
- 항상 높은 보상 또는 진행에 유리한 요청

## 중요한 이름 있는 고객의 확정 트리거

검투사·모험가·수집가·병사 등 버티컬 슬라이스의 대표 고객이나 중요 서사 고객은 확률에만 의존하지 않고 **명시적 조건 트리거**로 등장시킬 수 있다.

가능한 트리거 예시:

- 특정 영업일 도달
- 특정 제작·강화 이정표를 이전 영업일까지 달성
- 선행 방문 고객 거래 또는 세계 결과 완료
- 특정 장비 종류 제작 가능 상태 개방
- 버티컬 슬라이스 테스트 시나리오 시작

### 확정 트리거 원칙

- 확정 고객도 `[방문 고객]` 요청으로 생성됨
- 요청 장비 종류·조건·보상·2영업일 기한을 사용함
- 고객 전용 장비를 자동 생성하지 않음
- 보관함에 제품을 자동 지급하지 않음
- 일반 제작·강화·판매를 중단시키지 않음
- 거래 전까지 제품을 예약하지 않음
- 거래·거절·만료와 후속 세계 활동은 기존 저장 계약을 사용함

## 확정 트리거와 슬롯 포화

활성 요청이 2개이면 중요한 고객의 확정 트리거가 충족돼도 실제 방문 요청을 생성하지 않는다.

대신 **방문 대기 조건**만 유지한다.

```text
중요 고객 트리거 충족
→ 활성 요청 2개
→ 실제 요청 생성 안 함
→ 기한 시작 안 함
→ 놓친 고객 처리 안 함
→ 요청 슬롯이 빈 다음 영업일 시작에 재평가
```

원칙:

- 대기 중인 고객 요청에는 남은 영업일을 부여하지 않음
- 대기 중인 고객을 미확인 활성 요청으로 집계하지 않음
- 슬롯 포화 때문에 관계·명성 패널티를 부과하지 않음
- 기존 활성 요청을 자동 교체하지 않음
- 중요 고객을 위해 일반 요청을 자동 거절하지 않음
- 대기 조건은 저장되지만 일반 요청 데이터와 분리함
- 슬롯이 비었다고 영업일 도중 즉시 등장하지 않고 다음 영업일 시작에 평가함

여러 확정 트리거가 동시에 대기할 경우의 우선순위는 후속 요청 생성 규칙에서 확정한다.

## 일반 판정과 확정 트리거의 우선순위

영업일 시작 시 확정 트리거와 일반 무작위 판정을 동시에 별도 실행해 요청을 2개 생성하지 않는다.

권장 처리 순서:

```text
빈 슬롯 확인
→ 대기 중인 확정 트리거 확인
→ 확정 트리거가 있으면 1개 생성
→ 해당 영업일 신규 요청 판정 완료
→ 일반 무작위 판정은 수행하지 않음
```

즉, 영업일당 신규 방문 고객 생성 상한은 경로와 관계없이 1개다.

- 확정 고객 1개 생성 + 일반 고객 1개 생성: 금지
- 여러 확정 고객 동시 생성: 금지
- 일반 요청 2개 동시 생성: 금지
- 요청 1개 생성 후 같은 날 슬롯이 비었다는 이유로 추가 생성: 금지

정확한 다중 확정 트리거 우선순위는 미정이지만, 한 영업일 한 개 생성 상한은 유지한다.

## 요청 미발생 영업일

신규 요청이 발생하지 않는 영업일도 정상 상태다.

플레이어는 다음 행동을 계속할 수 있다.

- 제작
- 강화·정밀강화
- 수리·정비
- 보관함 관리
- 일반 판매
- 기존 방문 고객 요청 대응
- 기존 거래의 후속 세계 활동 확인
- 영업 종료

요청 미발생을 오류나 빈 콘텐츠로 표현하지 않는다. 일반 영업은 방문 고객 이벤트와 독립된 핵심 운영 경로다.

## 알림·연출 계약

신규 요청이 발생하면:

- `[방문 고객]` 탭에 배지 표시
- 요청 장비 종류와 기본 기한 요약
- 중요한 이름 있는 고객이면 식별 정보 표시
- 자동으로 `[방문 고객]` 화면으로 강제 이동하지 않음
- 미확인 결과 정리 화면 위에 요청 팝업을 겹쳐 표시하지 않음
- 강화 입력이나 결과 연출 중간에 끼어들지 않음
- 불씨 정령은 보조 반응만 제공하며 요청의 유일한 정보원이 아님

영업일 시작 처리 중 여러 결과가 있으면 우선순위는 다음과 같다.

```text
저장 복구·무결성 오류
→ 미확인 비가역 결과
→ 요청 만료·세계 결과
→ 신규 방문 고객 알림
→ 일반 뉴스
```

## 저장·복구 시나리오

필수 검증:

1. 신규 요청 발생 직후 앱 종료 후 같은 요청으로 복귀
2. 신규 요청 미발생 영업일에서 재실행해도 새 판정 없음
3. 슬롯 2개 상태에서 재실행해도 숨은 요청 생성 없음
4. 영업일 도중 요청 거래 후 재실행해도 추가 판정 없음
5. 영업 종료 후 다음 영업일에서만 새 판정 실행
6. 확정 트리거가 슬롯 포화로 대기할 때 기한이 감소하지 않음
7. 슬롯 해제 후 다음 영업일에 확정 고객이 한 번만 생성
8. 확정 고객 생성일에는 일반 무작위 요청을 추가 생성하지 않음
9. 요청 생성 저장 중 오류 발생 시 중복 고객·중복 보상 없음

## 버티컬 슬라이스 적용

버티컬 슬라이스의 대표 고객 이벤트는 일반 확률에 맡기지 않고 명시적 테스트 트리거로 보장할 수 있다.

다만 다음을 반드시 구분한다.

- 일반 캠페인의 요청 발생 확률
- 버티컬 슬라이스 검증용 확정 트리거
- 준비 저장 데이터
- 이미 활성화된 방문 고객 요청

테스트 트리거는 고객 이벤트 파이프라인을 안정적으로 검증하기 위한 장치이며, 매 영업일 고객이 반드시 등장하는 게임 규칙을 의미하지 않는다.

## 현재 기획 상태 영향

이번 결정으로 해결되는 항목:

- 신규 방문 고객의 일반 발생 시점
- 영업일당 발생 판정 횟수
- 행동 반복과 앱 재실행에 의한 중복 판정 방지
- 중요 고객 확정 트리거와 슬롯 포화 처리
- 요청 미발생 영업일 허용

아직 미정인 항목:

- 일반 신규 요청 발생 확률
- 고객 유형·장비 종류·보상 가중치
- 같은 장비 종류 요청의 연속 중복 억제
- 여러 확정 트리거의 우선순위
- 버티컬 슬라이스 대표 고객 이벤트 조합
- 일반 영업과 방문 고객 이벤트를 포함한 15~25분 세션 예산
