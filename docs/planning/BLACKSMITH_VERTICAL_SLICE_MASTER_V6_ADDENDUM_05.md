## 강화 판정·저장·연출 순서

강화는 **최종 실행 입력이 완료된 순간 결과를 1회 판정하고, 비용·재료·장비 상태·보호 결과를 하나의 원자적 상태 변경으로 확정한 뒤 연출**한다.

연출은 판정을 생성하는 과정이 아니라, 이미 저장된 확정 결과를 표현하는 단계다.

```text
최종 확인 버튼 또는 길게 누르기 완료
→ 추가 입력 잠금
→ 강화 결과 1회 판정
→ 비용·재료·보호·장비 상태·연대기 변경을 함께 확정
→ 확정 상태 저장 완료
→ 저장된 결과를 기반으로 연출 재생
→ 결과 확인
→ 강화 작업대 갱신
```

## 원자적 확정 범위

한 번의 강화 실행에서 다음 항목은 서로 분리해 저장하지 않는다.

- 강화 시도 식별자
- 대상 장비 식별자와 시도 전 상태
- 사용한 강화 재료와 비용
- 보호 사용 여부와 보호 수단 소비
- 성공·유지·단계 하락·영구 파괴 결과
- 시도 후 강화 단계와 장비 상태
- 정밀강화 성공 결과
- 장비 가치·수식어 등 파생 상태 변경
- 영구 파괴 또는 중요 결과의 연대기 기록
- 결과 연출을 아직 확인하지 않았다는 복귀 상태

다음 중간 상태는 허용하지 않는다.

- 자원은 소비됐지만 강화 결과가 없음
- 결과는 적용됐지만 비용이 소비되지 않음
- 장비 단계만 바뀌고 정밀강화 결과가 누락됨
- 보호 수단만 소비되고 보호 판정이 반영되지 않음
- 동일 시도가 두 번 판정되거나 두 번 적용됨
- 앱 재실행으로 이전 결과를 다시 뽑을 수 있음

## 중단 시점별 복귀 규칙

| 중단 시점 | 복귀 처리 |
|---|---|
| 최종 실행 입력 완료 전 | 강화 미실행, 자원 미소비, 기존 작업대 상태 유지 |
| 최종 실행 입력 완료 후 저장 완료 전 | 완료되지 않은 변경을 적용하지 않고 시도 전 상태 유지 |
| 저장 완료 후 연출 시작 전 | 저장된 결과를 그대로 표시하고 재판정하지 않음 |
| 결과 연출 도중 | 저장된 동일 결과의 미확인 요약 또는 필요한 연출 구간을 재표시 |
| 결과 요약 확인 후 | 갱신된 장비·재료·자금 상태로 작업대 복귀 |

- 저장 완료 여부는 플레이어가 임의로 선택하는 분기가 아니다.
- 복귀 시 동일 강화에 대한 새 확률 판정을 수행하지 않는다.
- 결과가 확정된 시도는 취소·환급·롤백하지 않는다.
- 결과 미확인 상태가 있으면 일반 작업대 조작보다 먼저 해당 결과를 정리한다.

## 일반 강화와 일반 정밀강화

일반 강화와 일반 정밀강화는 동일한 원자적 처리 계약을 사용한다.

```text
실행 입력 완료
→ 결과 1회 판정
→ 재료·비용 소비
→ 성공·유지·하락·파괴 상태 적용
→ 정밀강화라면 성공 결과까지 함께 적용
→ 저장
→ 결과 연출
```

- 일반 정밀강화 성공 시 `10단위 단계 도달`과 `정밀강화 결과`를 분리하지 않는다.
- 일반 정밀강화 실패 시 다음 10단위 단계나 정밀강화 성공 결과를 일부만 적용하지 않는다.
- 영구 파괴 시 장비 삭제 상태와 손실·연대기 기록을 함께 확정한다.

## +49 → +50 고위 정밀강화

고위 정밀강화는 후보 선택부터 확정 상태에 포함한다.

```text
진화 후보 2~3개 공개
→ 플레이어가 후보 하나 선택
→ 길게 누르기 또는 접근성 대체 입력 완료
→ 특수재료·보조 재료·비용 소비
→ +50 도달 확정
→ 선택한 진화 형태 확정
→ 대표 특수 수식어 확정
→ 부가 결과 확정
→ 전체 상태를 함께 저장
→ 전용 진화 연출
```

- 후보 선택 완료 전에는 실행 판정이나 자원 소비가 발생하지 않는다.
- 최종 입력 완료 후에는 선택 후보를 변경할 수 없다.
- 특수재료 소비, `+50` 도달, 진화 형태와 대표 특수 수식어를 각각 별도로 저장하지 않는다.
- 앱 종료 후 복귀해도 동일한 선택 후보와 동일한 부가 결과를 표시한다.
- 진화 연출을 다시 보더라도 강화 또는 재료 소비를 다시 적용하지 않는다.

## 결과 연출 복귀

복귀 시 연출은 다음 원칙을 따른다.

- 아직 결과를 확인하지 않았다면 결과 요약을 반드시 표시한다.
- 최초 정밀강화·고위 정밀강화의 중요한 공개 정보가 누락되지 않게 한다.
- 장시간 전체 연출을 강제로 처음부터 반복할지는 UX 플레이테스트로 결정한다.
- 연출을 단축하거나 요약으로 대체해도 확정 결과의 모든 항목을 확인할 수 있어야 한다.
- 영구 파괴는 장비 이름, 이전 강화 단계, 주요 수식어와 손실 자원을 다시 확인할 수 있어야 한다.

## 저장 실패와 오류 경계

저장 처리에 실패한 상태에서는 강화 결과 연출을 성공적으로 완료한 것처럼 보여주지 않는다.

- 상태 확정 전에는 다음 강화 입력을 허용하지 않는다.
- 상태 확정이 불가능하면 자원·장비 변경을 적용하지 않고 시도 전 상태를 유지한다.
- 네트워크 재시도나 앱 재실행이 같은 시도를 중복 적용하지 않도록 시도 식별자를 사용한다.
- 오류 발생 사실과 현재 보존된 상태를 플레이어에게 명확히 알린다.
- 저장 실패를 강화 실패 결과로 위장하지 않는다.

정확한 저장 기술, 파일 형식, 트랜잭션 구현과 오류 재시도 횟수는 구현 계획 단계에서 결정한다. 다만 위의 사용자 경험과 상태 무결성 계약은 변경하지 않는다.

## 플레이테스트·검증 항목

- 최종 입력 직전 앱 종료 시 자원 미소비 확인
- 판정 직후 강제 종료 시 동일 결과 복귀 확인
- 일반 정밀강화 단계 상승과 정밀 결과의 동시 적용 확인
- 영구 파괴 도중 종료 시 장비 중복 복구·중복 삭제 방지 확인
- 고위 정밀강화 연출 도중 종료 시 동일 진화 후보·결과 복귀 확인
- 반복 실행·빠른 연타·앱 재시작으로 중복 소비 또는 중복 강화가 발생하지 않는지 확인
- 결과 미확인 상태가 정상적으로 정리된 뒤 작업대로 복귀하는지 확인

```text
ENHANCEMENT_RESOLUTION_ORDER: ROLL_THEN_ATOMIC_COMMIT_THEN_PRESENT
RESULT_ROLL_COUNT_PER_ATTEMPT: EXACTLY_ONCE
COST_AND_EQUIPMENT_STATE_COMMIT: ATOMIC
ANIMATION_AS_SOURCE_OF_RESULT: FORBIDDEN
RESOURCE_ONLY_LOSS_WITHOUT_RESULT: FORBIDDEN
DUPLICATE_APPLICATION_AFTER_RESTART: FORBIDDEN
PENDING_RESULT_RECOVERY: REQUIRED
HIGH_PRECISION_SELECTION_AND_RESULT_COMMIT: ATOMIC
EXACT_PERSISTENCE_TECHNOLOGY: IMPLEMENTATION_PLANNING_DECISION
```
