## 결정 82 — 방문 고객은 장비 범주만 요청

`[방문 고객]` 요청은 강화 단계·수식어·품질·내구도 같은 추가 조건을 요구하지 않고, **장비 범주 하나만 요청**한다.

대표 표시:

```text
요청 종류: 무기
```

요청 범주에 속하는 판매 가능한 보관함 제품이면 방문 고객 거래 후보가 된다.

```text
방문 고객 발생
→ 요청 종류: 무기
→ 보관함의 판매 가능한 무기 목록 표시
→ 플레이어가 판매할 제품 선택
→ 거래 확정 또는 거절·만료
```

## 내구도 시스템 부재 확정

블랙스미스 장비에는 **내구도 수치 또는 내구도 상태 시스템을 두지 않는다.**

따라서 선행 문서에 포함된 다음 표현은 현재 기획에서 사용하지 않는다.

- 내구도
- 내구 80% 이상
- 내구 손상
- 내구 보강
- 내구 지원
- 수리성에 따른 내구 회복
- 손상된 내구도 때문에 판매 불가
- 고객 요청의 내구 최소 조건 또는 선호

`수리`, `정비`, `손상` 같은 표현이 다른 선행 문서에 남아 있다면 장비 내구도 시스템을 의미하는 것으로 해석하지 않는다. 실제로 별도 파손·복구 시스템을 둘지는 후속 명시 결정 없이는 확정하지 않는다.

```text
EQUIPMENT_DURABILITY_SYSTEM: NOT_PRESENT
DURABILITY_VALUE_OR_PERCENTAGE: FORBIDDEN
DURABILITY_AS_REQUEST_REQUIREMENT: FORBIDDEN
```

## 요청 정보 구조

일반 방문 고객 요청의 필수 정보는 다음으로 단순화한다.

- 고객 또는 고객 유형
- 요청 장비 범주
- 제안 가격 또는 보상 정보
- 남은 영업일
- 거래 후 후속 활동 가능 여부

일반 요청에는 다음 정보를 생성하지 않는다.

- 최소 강화 단계
- 필수 수식어
- 필수 정밀강화 결과
- 필수 진화 결과
- 내구도 조건
- 품질 등급 조건
- 숨은 합격 조건
- 선택 선호 조건

```text
일반 방문 고객 요청
= 고객 식별 정보
+ 요청 장비 범주 1개
+ 보상
+ 2영업일 기한
+ 후속 가능성
```

## 장비 범주의 의미

요청 범주는 개별 제품 이름보다 상위 분류다.

예시:

- `무기`
- `방어구`
- 향후 명시적으로 추가되는 일반 장비 대분류

`요청 종류: 무기`라면 장검·도끼·창 등 무기 범주에 속하는 판매 가능한 제품은 모두 후보가 될 수 있다.

```text
요청 종류: 무기

후보 가능
├─ 장검
├─ 도끼
└─ 창
```

개별 장비 종류를 요청하는 구조는 일반 방문 고객의 기본 모델로 사용하지 않는다.

```text
일반 요청: 장검만 요구
→ 사용하지 않음

일반 요청: 무기 요구
→ 사용
```

중요 고객 콘텐츠도 기본적으로 같은 범주 요청 구조를 사용한다. 특정 서사에서 개별 제품 이름이 반드시 필요하다면 별도 사용자 결정으로 확정해야 하며, 현재 결정만으로 허용하지 않는다.

## 거래 후보 판정

방문 고객 거래 후보 여부는 다음 기준만 사용한다.

```text
제품이 제작 완료 상태인가
+ 플레이어 보관함에 존재하는가
+ 판매 가능한 상태인가
+ 요청 장비 범주에 속하는가
+ 다른 거래로 소유권이 이전되지 않았는가
→ 후보 가능
```

다음 요소는 후보 자격을 차단하지 않는다.

- 강화 단계가 낮음
- 정밀강화를 하지 않음
- 원하는 수식어가 없음
- 고위 정밀강화를 하지 않음
- 진화를 하지 않음
- 역사 가치가 낮음

이 요소들이 판매 가격이나 장비 자체 가치에 영향을 줄 수는 있으나, 방문 고객이 요구한 범주에 속하는 제품의 거래 자격을 숨은 조건으로 막지 않는다.

## 강화와 방문 고객의 관계

방문 고객이 강화 수치를 요구하지는 않지만, 플레이어는 더 높은 판매 가치나 다른 장기 목적을 위해 요청 기한 중 제품을 강화할 수 있다.

```text
요청 종류: 무기
→ 보관함 무기 즉시 판매 가능

또는

→ 새 무기 제작
→ 원하는 만큼 강화
→ 기한 안에 해당 무기 판매
```

원칙:

- 강화는 거래 가능 조건이 아니라 플레이어의 가치 판단이다.
- 강화하지 않은 무기도 범주만 맞으면 판매 가능하다.
- 특정 강화 성공을 방문 고객 대응의 필수 경로로 강제하지 않는다.
- 강화 실패로 장비 범주가 바뀌지 않는 한 요청 후보 자격은 유지한다.
- 강화 결과를 고객 요청에 맞추기 위해 보정하지 않는다.

## 일반 판매와의 관계

방문 고객 요청과 같은 범주의 제품도 일반 판매할 수 있다.

```text
활성 요청: 무기
보관함: 장검 A, 도끼 B

장검 A 일반 판매
→ 요청은 계속 활성
→ 도끼 B를 고객에게 판매 가능
```

- 요청 범주 제품의 일반 판매를 차단하지 않는다.
- 일반 판매 전에 활성 요청 후보임을 알려 줄 수 있다.
- 일반 판매된 제품은 방문 고객 후보에서 즉시 제외한다.
- 요청 범주에 속하는 제품이 없어져도 요청은 자동 거절되지 않는다.
- 기한 안에 새 제품을 제작해 대응할 수 있다.

## 요청 생성 방식 정정

추가 결정 27의 다음 내용은 이번 결정으로 정정한다.

### 유지되는 내용

- 현재 캠페인에서 제작 가능한 범위만 일반 요청 후보로 사용
- 현재 보관함 구성은 요청 범주를 직접 결정하지 않음
- 고객 성향 가중치는 데이터 기반
- 최근 일반 요청의 반복 억제
- 앱 재실행으로 요청을 재추첨하지 않음
- 요청 생성과 이력 저장의 원자성

### 대체되는 내용

- 개별 장비 종류 풀에서 요청 종류 선정
- 장검·방패 등 정확한 종류 반복 이력
- 최소 조건·선호 생성
- 2영업일 대응 가능성을 강화 조건까지 포함해 검사
- 중요 고객이 정확한 개별 장비 종류를 직접 지정

일반 요청 생성은 다음처럼 단순화한다.

```text
현재 제작 가능한 장비 범주 풀 구성
→ 고객 유형·사용 목적에 따른 범주 가중치 적용
→ 최근 일반 요청 범주 반복 억제
→ 요청 범주 1개 선정
→ 보상·2영업일 기한 생성
→ 요청과 범주 이력 원자적 저장
```

## 제작 가능한 범주 풀

일반 요청 후보 범주는 해당 범주에 속하는 제품을 현재 캠페인에서 하나 이상 정상 제작할 수 있을 때만 포함한다.

예:

```text
무기 범주
→ 현재 제작 가능한 장검 또는 도끼 존재
→ 무기 요청 후보 포함

방어구 범주
→ 현재 제작 가능한 방어구 제품 없음
→ 방어구 요청 후보 제외
```

현재 보관함에 완제품이 없어도 제작 가능 경로가 있으면 요청할 수 있다.

## 고객 성향 가중치

고객 유형은 요청 범주의 상대 확률에만 영향을 줄 수 있다.

예시 방향:

| 고객 유형 | 상대적으로 높은 범주 예시 |
|---|---|
| 검투사 | 무기 |
| 모험가 | 무기 또는 방어구 |
| 수집가 | 무기 또는 방어구 중 역사·전시 가치가 생길 수 있는 범주 |
| 병사 | 무기 또는 방어구 |

정확한 가중치는 후속 콘텐츠 밸런스에서 정한다.

- 검투사가 방어구를 요청할 수 있다.
- 수집가가 무기를 요청할 수 있다.
- 고객 이름으로 범주를 고정하지 않는다.
- 고객 전용 장비 범주를 만들지 않는다.

## 최근 반복 억제

최근 일반 방문 고객 요청 2개의 **장비 범주**를 기록한다.

```text
최근 요청
1. 무기
2. 방어구

다음 요청 생성
→ 무기·방어구 반복 가중치 감소 가능
```

다만 현재 제작 가능한 유효 범주 수가 적다면 반복을 허용한다.

- 반복은 완전 금지가 아니다.
- 유효 범주가 하나뿐이면 동일 범주 요청 가능
- 중요 고객 확정 요청은 일반 반복 이력을 갱신하지 않음
- 정확한 감소 배율은 플레이테스트 조정 대상

## 보상과 장비 가치

요청은 범주만 요구하지만 판매되는 개별 제품의 가치는 서로 다를 수 있다.

가능한 가치 입력 예:

- 장비 종류의 기본 가치
- 제작에 사용한 재료
- 강화 단계
- 정밀강화 결과
- 고위 정밀강화·진화 결과
- 수식어
- 역사·연대기 가치

이는 **거래 가능 여부의 조건이 아니라 가격 계산 입력**이다.

정확한 일반 판매 가격과 방문 고객 추가 보상 산정식은 별도 결정으로 남긴다.

## UI 표시

방문 고객 요청 화면은 조건 체크리스트 대신 범주와 후보 제품을 직접 보여준다.

```text
[방문 고객]
요청 종류: 무기
남은 영업일: 2
보상: 표시

보관함의 판매 가능한 무기 3개
→ 장검 +12
→ 도끼 +7
→ 창 +20
```

금지되는 UI:

- 내구도 바
- 최소 강화 조건 체크
- 수식어 합격·불합격 체크
- 숨은 선호 점수
- 필수 조건과 선택 선호의 복합 목록

후보가 없으면 다음처럼 표시한다.

```text
현재 판매 가능한 무기 없음
→ 무기를 제작하거나 요청을 거절할 수 있습니다.
```

## 저장·무결성 계약

요청 생성 시 다음을 하나의 원자적 결과로 저장한다.

- 요청 식별자
- 고객 또는 고객 유형
- 요청 장비 범주
- 보상
- 2영업일 기한
- 활성 요청 슬롯 점유
- 최근 일반 요청 범주 이력
- 당일 신규 요청 판정 완료
- 일반 미발생 누적 변경

거래 확정 시 다음을 원자적으로 저장한다.

- 선택 제품 식별자
- 제품 범주 일치 검증
- 보관함에서 제품 제외
- 고객 또는 외부 소유자로 소유권 이전
- 판매 보상
- 관계·후속 세계 활동
- 장비 연대기
- 요청 거래 완료 상태

앱 재실행으로 요청 범주나 선택 가능한 제품 기준이 바뀌지 않아야 한다.

## 검증 시나리오

최소 다음을 검증한다.

1. `요청 종류: 무기`에서 여러 무기 제품이 후보로 표시됨
2. 강화 단계와 수식어가 달라도 모든 판매 가능한 무기가 후보가 됨
3. 방어구가 무기 요청 후보에 표시되지 않음
4. 내구도 데이터·UI·조건이 존재하지 않음
5. 보관함에 무기가 없어도 제작 가능하면 무기 요청이 정상 유지됨
6. 요청 중 새 무기를 제작해 거래 가능
7. 요청 후보 무기를 일반 판매한 뒤 다른 무기로 대응 가능
8. 앱 재실행 후 요청 범주와 기한 유지
9. 최근 일반 요청 이력이 개별 장비 종류가 아니라 범주 단위로 저장됨
10. 고객 이름 코드 분기 없이 범주 가중치 적용 가능
11. 동일 제품의 일반 판매와 방문 고객 거래 중복 금지
12. 거래 가능 여부에 숨은 강화·수식어·내구 조건이 없음

## 현재 기획 상태 영향

이번 결정으로 해결되는 항목:

- 내구도 시스템 부재
- 방문 고객 요청의 조건 단순화
- 장비 범주 단위 요청
- 거래 후보 자격
- 추가 결정 27의 개별 종류·조건 생성 정정

아직 미정인 항목:

- 장비 범주의 최종 목록
- 고객 유형별 요청 범주 가중치
- 최근 범주 반복 억제 배율
- 일반 판매 가격과 방문 고객 보상 산정식
- 같은 범주 제품 여러 개 중 판매 제품 선택 UI
- 버티컬 슬라이스 대표 고객 이벤트 조합
