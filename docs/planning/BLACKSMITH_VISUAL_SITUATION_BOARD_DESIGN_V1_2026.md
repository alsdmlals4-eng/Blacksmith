## 0. 설계 결론

이번 산출물은 하나의 작은 글씨 종합 대시보드가 아니라 다음 보드 세트로 구성한다.

```text
BOARD-A  프로젝트 비주얼 기준
BOARD-B1 대장간 허브
BOARD-B2 단조·강화 작업대
BOARD-B3 보관함·자원 관리
BOARD-B4 결과·연대기
BOARD-C1 첫 작품 단조 시퀀스
BOARD-C2 일반 강화 판단 시퀀스
BOARD-C3 +49→+50 경로 선택 시퀀스
BOARD-C4 이름 고객 거래 시퀀스
BOARD-C5 세계 결과·연대기 시퀀스
BOARD-D  구현 명세 부록
```

화면 예시는 판독 가능한 크기로 분리하며, 기술 구조는 `BOARD-D`로 이동한다.

### 비교한 구성 방식

| 방식 | 장점 | 문제 | 판정 |
|---|---|---|---|
| A. 한 장 종합 대시보드 | 전체 범위를 한 번에 확인 | 화면이 작아지고 기술 표가 중심이 됨 | 제외 |
| B. 비주얼·4화면·시퀀스·부록 분리 | 화면 판독성, 비교성, 프로젝트 고유성 확보 | 보드 장수가 늘어남 | **권장·채택** |
| C. 화면별 장문 기술 문서 | 구현 세부 정보가 풍부 | 실제 플레이 모습을 한눈에 보기 어려움 | PART D 보조 자료 |

## A-2. 시각 언어의 핵심 문장

> **작품이 화면의 주인공이고, 불과 금속은 현재 행동을, 기록과 인물은 작품의 다음 삶을 보여준다.**

화면은 세 시각 층으로 구성한다.

1. **작업 층** — 화로·모루·망치·장비·불꽃처럼 현재 손으로 만지는 대상
2. **판단 층** — 성공률·비용·위험·보호·고객 적합도처럼 선택에 필요한 정보
3. **기억 층** — 장비 이름·소유자·세계 결과·연대기처럼 작품의 역사

## A-4. 제안 비주얼 방향

### 화면 배경

- 대장간 허브는 화로·모루·작업대가 한 공간에 보이는 **고정 세로형 작업장 일러스트**를 사용한다. `PROPOSED`
- 단조·강화 화면은 동일 작업장을 더 가까이 당긴 구도로 사용해 장소 연속성을 유지한다. `PROPOSED`
- 고객 화면은 대장간 내부를 유지하고 고객 반신·요청 문서·작품 비교만 전면에 올린다. `PROPOSED`
- 세계 결과 화면은 투기장·전시장·유적·군사 현장 등 고객 유형별 배경을 사용하되, 장비와 결과 정보가 배경보다 우선한다. `PROPOSED`

### 캐릭터 표현

- 고객은 세로형 모바일에서 읽기 쉬운 허리 위 반신 일러스트를 기본으로 한다. `PROPOSED`
- 모닥은 화로 주변 또는 하단 안내 영역에 작게 등장하며 중요 버튼·수치·장비를 가리지 않는다. `CURRENT/PROPOSED`
- 플레이어 대장장이의 전신 캐릭터를 항상 화면에 두지 않는다. 손·망치·앞치마 일부처럼 작업 주체를 암시하는 연출을 우선한다. `PROPOSED`

### UI 재질

- 기본 UI는 검은 철판·숯빛 패널을 사용한다. `INFERRED`
- 선택 테두리와 핵심 행동은 황동·금색을 사용한다. `CURRENT/INFERRED`
- 연대기와 소유권 기록에는 가죽·양피지 질감을 제한적으로 사용한다. `PROPOSED`
- 특수재료·고위 정밀강화는 보라색 전체 화면이 아니라 재료 자체와 일부 테두리에만 희소 색을 사용한다. `PROPOSED`

### 타이포그래피

- 확률·비용·버튼·상태는 가독성 높은 한국어 산세리프를 사용한다. `PROPOSED`
- 장비명·결과 제목·연대기 장 제목만 제한적으로 세리프 또는 각진 장식 서체를 사용한다. `PROPOSED`
- 장식 서체로 본문·확률·경고를 표시하지 않는다. `PROPOSED`

### 아이콘

- 망치·모루·불꽃·금속·보호석·촉매·장비 계보는 굵은 실루엣 중심으로 통일한다. `PROPOSED`
- 색만으로 의미를 구분하지 않고 아이콘·문구·숫자를 함께 사용한다. `CURRENT/PROPOSED`
- 계보와 보조 수식어 아이콘은 희귀도 별점처럼 보이지 않게 서로 다른 문양 계열로 설계한다. `PROPOSED`

### 모션·피드백

- 망치 타격은 짧은 화면 진동, 금속 변형, 불꽃, 충격음으로 물성을 전달한다. `INFERRED/PROPOSED`
- 강화 결과는 판정 전에 결과를 암시하지 않는다. `CURRENT`
- 성공은 장비 밝기·금속 울림·단계 상승으로, 실패는 단계·자원 변화와 함께 즉시 설명한다. `PROPOSED`
- 영구 파괴는 화려한 폭발 보상처럼 표현하지 않고, 장비 소실과 연대기 보존을 차분하게 보여준다. `CURRENT/PROPOSED`

## A-5. 금지 시각 요소

- 장르와 무관한 밝은 일반 판타지 메뉴
- 모바일 화면을 덮는 과도한 파티클과 불꽃
- 모든 고급 요소에 보라색·무지개색을 사용하는 희귀도 클리셰
- 확률과 위험을 장식 아래 숨기는 레이아웃
- 캐릭터 일러스트가 장비와 선택 정보를 압도하는 구성
- 결과 유형마다 완전히 다른 UI 문법
- 모닥을 성장 재화·버프 캐릭터처럼 보이게 하는 연출

## SCREEN-02 — 단조·강화 핵심 작업대

### 화면 계약

| 항목 | 내용 |
|---|---|
| 근거 수준 | `CURRENT + PROPOSED` |
| 현재 구현 | 단조·강화 PoC 존재. 최신 +50 이원화는 미구현 |
| 화면 목적 | 작품과 위험 정보를 동시에 보고 직접 단조하거나 강화 결정을 내림 |
| 핵심 행동 | 망치 입력, 정밀 마감, 일반 강화, 보호 사용, +50 경로 선택 |
| 중요 정보 3개 | 현재 작품·단계, 성공·실패 결과표, 비용·보호·재료 |
| 이전 화면 | 대장간 허브, 보관함 |
| 다음 화면 | 결과 Overlay, 보관함, 허브 |

### 공통 레이아웃

```text
┌──────────────────────────────┐
│ 작품명 · 제작등급 · +단계  ⓘ │
├──────────────────────────────┤
│                              │
│        장비 / 모루 / 화로     │
│       타격·강화 결과 연출     │
│                              │
├──────────────────────────────┤
│ 현재→목표 · 확률 · 최악 결과 │
│ 비용 · 보호 · 남은 재료       │
├──────────────────────────────┤
│ 주요 행동 버튼                │
│ 보조 행동 / 상세 확률         │
└──────────────────────────────┘
```

### 단조 상태

- 중앙 장비와 타격 지점이 가장 크게 보인다.
- 열·진행도는 장비 주변 또는 중앙 하단에 표시한다.
- 피버는 화면 전체 색 반전이 아니라 불꽃·망치 속도·테두리로 표현한다.
- 정밀 마감 진입 시 일반 타격 버튼을 잠그고 짧은 정확도 입력으로 전환한다.

### 일반 강화 상태

- `현재 단계 → 목표 단계`를 제목 바로 아래에 표시한다.
- 확률표는 성공만 크게 보여주지 않고 유지·하락·파괴를 같은 영역에 표시한다.
- 보호 선택 변경 시 결과표와 비용이 같은 화면에서 즉시 바뀐다.
- 위험도가 낮은 단계는 탭 실행, 파괴 가능 강화는 길게 누르기 또는 2단계 확인을 사용한다.

### +49→+50 경로 비교 상태

세로 화면이므로 좁은 좌우 비교 대신 **상하 2개 큰 경로 카드**를 사용한다.

```text
┌──────────────────────────────┐
│ +49 작품 · +50 경로 선택     │
├──────────────────────────────┤
│ 일반 정밀강화                │
│ 기존 위험 · 특수재료 없음    │
│ 성공 시 일반 +50             │
│ [결과표 보기]                 │
├──────────────────────────────┤
│ 고위 정밀강화                │
│ 특수재료 · 성공 확정          │
│ 특수 수식어·진화 후보 2~3개   │
│ [재료와 후보 보기]            │
├──────────────────────────────┤
│ 선택한 경로 요약 · 최종 확인  │
└──────────────────────────────┘
```

#### 일반 정밀강화 선택 후

- 기존 성공·유지·하락·파괴 결과표를 표시한다.
- `특수 수식어 없음`을 실패나 열등 등급처럼 표현하지 않는다.
- 성공하면 정상 +50 완성 결과와 이후 강화·명작 전당 자격을 표시한다.

#### 고위 정밀강화 선택 후

- 특수재료를 `촉매`와 `특수 보조재료` 역할로 구분한다.
- 촉매는 주 진화 계열, 특수 보조재료는 후보 변주를 보여준다.
- 유효 후보 2~3개를 실행 전에 공개한다.
- 후보를 선택한 뒤 비용·재료·특수 수식어를 한 번 더 요약한다.

| 상태 | 화면 변화 |
|---|---|

```text
┌──────────────────────────────┐

├──────────────────────────────┤

└──────────────────────────────┘
```

### 결과 유형별 변형

| 결과 유형 | 중심 시각 | 필수 정보 |
|---|---|---|
| 단조 완성 | 완성 작품과 제작 등급 | 등급 원인, 작품명, 다음 강화 |
| 강화 성공 | 단계 상승과 장비 변화 | 비용, 단계, 이정표·수식어 |
| 유지·하락 | 장비와 단계 변화 | 왜 발생했는지, 보호 효과 |
| 영구 파괴 | 빈 모루·남은 기록 | 장비 소실, 소유권 종료, 연대기 보존 |
| 고객 거래 | 고객·작품·거래 확인 | 가격, 관계, 소유권, 후속 방향 |
| 세계 결과 | 결정적 장면과 장비 기여 | 승패·성과, 기여 원인, 운명 상태 |
| 신규 해금 | 새 고객·재료·기록 | 해금 이유와 접근 위치 |

### 세계 결과의 고객 유형 변형

공통 UI는 유지하고 배경·결과 명사·기여 원인만 교체한다.

- 수집가: 전시·감정·보존·희소 기록
- 모험가: 탐험·유적·발견·분실·회수
- 검투사: 결정적 경기·명성·전투 흔적
- 군인: 작전·부대 생존·보급·공적 기록

고객별 전용 결과 엔진을 만들지 않는다.

## 화면 전환 원칙

- 허브·단조·강화는 하나의 제품 Shell 안에서 상태 View로 전환하는 방식을 권장한다. `PROPOSED`
- 보관함은 현재 작업 상태를 유지하는 전체 화면 Overlay 또는 내부 Screen으로 사용한다. `CURRENT/PROPOSED`
- 비가역 결과는 일반 Toast가 아니라 ResultEnvelope로 확인한다. `PROPOSED`
- 앱 복귀 시 미확인 비가역 결과가 있으면 허브보다 먼저 복구한다. `PROPOSED`
- 화면 전환 중 입력을 잠그며, 저장이 완료되기 전에 결과 버튼을 활성화하지 않는다. `CURRENT/PROPOSED`

```text
   ├─ ChronicleSnippet
   └─ StatusBanner
```

## D-2. 재사용 원칙

- `EquipmentSummaryCard`는 보관함·작업대·고객 비교·결과에서 같은 정보 순서를 사용한다.
- `ResultEnvelope`는 결과 유형별 데이터만 교체하고 레이아웃 문법을 유지한다.
- 고객 유형은 배경·아이콘·결과 어휘를 바꾸지만 요청·거래·소유권·세계 결과 파이프라인을 공유한다.
- +50 경로는 동일 작업대에서 비교하되 일반 결과표와 고위 후보 선택 View를 분리한다.

## D-3. 필수 화면 데이터

| 화면 | 필수 데이터 |
|---|---|
| SCREEN-01 | 작업일, 골드, 핵심 재료, 현재 작품, 활성 요청, 미확인 결과 |
| SCREEN-02 | 작품 ID, 단계, 등급, 수식어, 확률표, 비용, 보호, 특수재료, +50 경로 |
| SCREEN-03 | 작품 목록, 소유권, 운명 상태, 자원 목록, 한도, 정렬·필터 |
| SCREEN-04 | 결과 유형, 이전·이후 Snapshot, 원인, 자원·관계·소유권 변화, 연대기 |

## D-4. 저장·복귀

- 강화 판정은 결과 1회 생성 → 원자 저장 → 저장된 결과 연출 순서를 유지한다.
- 고객 판매는 최종 확인 전 예약·소유권 이전을 실행하지 않는다.
- 세계 결과는 한 번 생성된 결과를 다시 추첨하지 않는다.
- 앱 종료 시 미확인 ResultEnvelope ID를 저장해 복귀 후 같은 결과를 표시한다.
- 화면의 임시 스크롤·필터는 세션 상태, 작품·자원·거래·결과는 세이브 상태로 분리한다.

## D-5. 구현 우선순위

1. 공통 `EquipmentSummaryCard` 정보 위계 고정
2. `ResultEnvelope` 결과 계약 고정
3. SCREEN-02 작업대의 일반 강화·+50 경로 비교 화면 고정
4. SCREEN-01 제품 허브·복귀 흐름 고정
5. SCREEN-03 보관함·자원 화면 고정
6. SIT-004 고객 비교와 SIT-005 세계 결과 변형
7. 상태별 빈 화면·잠김·오류·접근성 보강

제품 코드는 사용자 `기획 완료`와 `검수 완료` 이후 별도 Codex Goal에서만 구현한다.

# 확인이 필요한 결정

## DEC-VIS-01 — 앱 시작 방식

### 권장안

```text
앱 실행
→ 저장 복구
→ 미확인 비가역 결과 우선 확인
→ 대장간 허브 즉시 진입
```

별도 타이틀·이어하기 메뉴는 사용하지 않는다. 설정·크레딧은 허브에서 접근한다.

대안은 전통적인 타이틀 화면을 두는 방식이다.

## DEC-VIS-02 — 제품 Shell

### 권장안

하나의 `BlacksmithApp` Shell 아래 허브·작업대를 상태 View로 전환하고, 보관함·결과는 Overlay 또는 내부 Screen으로 사용한다.

대안은 모든 기능을 완전한 별도 Scene으로 교체하는 방식이다.

## DEC-VIS-03 — 최종 아트 렌더링 강도

### 권장안

- 배경·장비: 질감이 읽히는 스타일라이즈드 2D 일러스트
- 고객: 반실사보다 단순화된 게임 일러스트 반신
- 모닥: 작고 단순한 상징 마스코트
- UI: 철·황동 재질을 암시하되 실제 금속 텍스처 과다 사용 금지

현재 실제 제품 아트가 없으므로 승인 전까지 `PROPOSED`다.
