## 2. 복원된 프로젝트 코어

> **망치질로 장비를 만들고, 커지는 위험 앞에서 멈출지 도전할지 선택하며, 완성한 작품이 사람과 세계에 남기는 흔적을 확인하는 모바일 대장간 게임.**

감정 곡선:

```text
만드는 손맛
→ 더 올리고 싶은 욕심
→ 잃을 수 있다는 긴장
→ 멈춤 또는 도전의 책임감
→ 작품 완성의 자부심
→ 누구에게 넘길지 고민
→ 세계에서 쓰이는 장면 확인
→ 다음 작품을 만들 동기
```

## 3. 유지할 강점

### 강화 공정성

- 성공률·비용·최대 하락·파괴·보호 효과를 실행 전에 공개
- 정밀강화는 10단위 진입 시도 자체
- +49→+50 특수재료 고위 정밀강화는 진화 선택과 높은 비용을 중심으로 한 확정 성공
- 판정 1회 후 비용·장비·연대기를 원자적으로 저장하고 연출

### 모바일 UX

- 고정 강화 작업대 + 상황별 하단 패널
- 저위험 반복 강화는 빠르게, 파괴·진화는 무겁게 표현
- 길게 누르기 대체 입력 제공
- 색상·사운드·진동·모션 하나에 정보를 독점시키지 않음

### 작품 생애주기

- 장비 ID, 제작자, 소유자, 강화, 수식어, 사건, 파괴 기록 연결
- 판매는 삭제가 아니라 소유권 이전
- 세계 결과가 동일 장비 ID와 연대기에 누적
- 앱 종료로 결과 재추첨·손실 되돌리기 금지

## 4. 확인된 주요 충돌

| 충돌 | 최신 판정 |
|---|---|
| 네 고객 동시 완주 vs 일반 영업·방문 요청 분리 | 네 고객 동시 완주 폐기 |
| 개별 장비 종류 요청 vs 장비 범주 요청 | 범주 요청 채택 |
| 고객 범주만 맞으면 선택이 얕아지는 문제 | 거래 자격과 공개 적합 신호 분리 |
| 손상·수리·내구 보강 vs 내구도 부재 | 수치 내구도 폐기, 비수치 운명 상태 채택 |
| Sheet의 +5/+10 vs PR 후반 +50 중심 | 일상 +5/+10과 장기 +50의 두 시간 지평으로 통합 |
| 상인 또는 수집가 두 번째 세트 | 수집가 확정 |
| 온라인 랭킹 명칭·목적 | 명작 전당 확정 |

## 5. 사용자 승인으로 해결된 P0

2026-07-31 사용자 승인을 기준으로 다음을 확정했다.

### P0-01 제작 등급

```text
보통 → 양질 → 우수 → 명품 → 걸작
```

### P0-02 수식어 모델

```text
계보 수식어 1개 + 보조 수식어 최대 2개
```

### P0-03 강화 이정표

- +10: 계보 수식어
- +20: 보조 수식어 1개
- +30: 계보 강화·방향 선택
- +40: 보조 수식어 2개째
- +50: 진화와 대표 특수 형태 승격
- +60 이상: 신규 슬롯 없이 기존 정체성 심화

### P0-04 고객 선택 의미

```text
거래 자격 = 요청 범주 일치
공개 적합 신호 = 등급·수식어·연대기와 고객 가치관의 일치
```

낮은 적합도여도 판매 가능하며 숨은 조건과 자동 추천을 사용하지 않는다.

### P0-05 장비 운명

수치형 내구도와 반복 수리 루프는 사용하지 않는다.

```text
정상 / 전투 흔적 / 분실 / 회수 / 영구 파괴
```

### P0-06 두 번째 콘텐츠 세트

수집가를 별도 결정론적 제작 파이프라인 증명 시나리오로 사용한다.

### P0-07 미래 온라인

사용자 노출명을 `명작 전당`으로 확정한다. 현재는 기획만 하며 구현하지 않는다.

## 6. 최신 15~25분 대표 흐름

| 시간 | 흐름 |
|---:|---|
| 0~2분 | 단조 마무리, 첫 강화 |
| 2~6분 | 새 장비 +0→+5, 완성·도전 판단 |
| 6~10분 | 준비 +49 대표작의 +50 진화 |
| 10~14분 | 검투사 요청과 작품 비교 |
| 14~17분 | 제품 직접 선택·판매·지원 또는 배팅 |
| 17~22분 | 자동 경기의 결정적 장면과 결과 |
| 22~25분 | 관계·장비 연대기·다음 목표 |

새 +5 장비와 준비된 +49 대표작의 두 시간축을 사용한다. 준비 장비는 신규 캠페인 기본 지급이 아니라 테스트 픽스처다.

## 8. Google Sheet 드리프트

현재 Sheet에는 다음 문제가 남아 있다.

- 고객 4종과 네 고객 상호작용을 현행 Demo 조건으로 기록
- +5/+10만 대표 흐름으로 기록하고 장기 +50 연결 미반영
- 최신 고객 범주 요청·최대 2개 요청·수집가 두 번째 세트 미반영
- `+`로 시작하는 텍스트가 수식으로 처리되어 여러 `#ERROR!` 발생
- 이전 Base 운영 버전 정보 잔존

Sheet는 사용자 `기획 완료` 후 마스터 기획에 맞춰 동기화한다.
