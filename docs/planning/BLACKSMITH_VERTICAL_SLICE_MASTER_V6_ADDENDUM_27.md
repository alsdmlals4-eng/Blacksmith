## 일반 방문 고객 요청 장비 종류 생성 방식

일반 `[방문 고객]` 요청의 장비 종류는 **현재 제작 가능한 장비 종류 풀 + 고객 성향 가중치 + 최근 일반 요청 반복 억제** 구조로 생성한다.

현재 `[보관함]`에 특정 제품이 존재하는지는 일반 요청 장비 종류 생성의 직접 입력으로 사용하지 않는다. 방문 고객은 플레이어가 이미 가진 제품만을 맞춤 구매하는 존재가 아니라, 현재 대장간이 정상적으로 제작할 수 있는 범위 안에서 수요를 제시하는 별도 요청 이벤트다.

```text
현재 진행에서 제작 가능한 장비 종류 풀 구성
→ 요청 고객 유형·사용 목적에 따른 성향 가중치 적용
→ 최근 일반 요청 장비 종류의 반복 가중치 감소
→ 유효 가중치 검증
→ 장비 종류 또는 범주 1개 선정
→ 조건·선호·보상·2영업일 기한 생성
→ 요청 데이터와 생성 이력 원자적 저장
```

## 일반 요청 후보 풀

일반 무작위 요청의 후보에는 현재 캠페인 진행에서 **실제로 제작 가능한 장비 종류**만 포함한다.

후보 포함 조건:

- 현재 제작법 또는 제작 기능이 해금돼 있음
- 필요한 제작 화면과 정상 제작 경로가 사용 가능함
- 해당 장비 종류의 완제품을 `[보관함]`에 등록할 수 있음
- 제작·강화·수리 결과가 기존 원자적 저장 계약을 사용함
- 방문 고객의 기본 2영업일 기한 안에 정상적인 대응 가능성이 존재함
- 고객 전용 장비 타입이 아님
- 테스트 전용 또는 디버그 전용 장비가 아님

후보 제외 조건:

- 아직 해금되지 않은 장비 종류
- 현재 캠페인에서 제작 기능이 봉인·비활성화된 종류
- 콘텐츠 데이터는 있으나 정상 UI로 제작할 수 없는 종류
- 개발자 전용 시험 장비
- 특정 고객에게만 사용 가능한 전용 장비 정의
- 2영업일 안에 정상 제작 경로가 존재하지 않으면서 요청만 생성되는 종류

`제작 가능`은 `[보관함]`에 이미 완제품이 존재한다는 뜻이 아니다.

```text
제작 가능 장검
+ 보관함 장검 0개
→ 장검 일반 요청 후보 포함 가능
→ 방문 이후 새 장검을 제작·강화해 대응 가능
```

## 보관함 비종속 원칙

일반 요청 장비 종류는 현재 보관함 구성에 맞춰 직접 결정하지 않는다.

금지되는 구조:

- 보관함에 가장 많은 장비 종류를 우선 요청
- 보관함에 완제품이 있는 종류만 요청
- 가장 높은 강화 장비의 종류를 자동 요청
- 판매가 잘 안 된 제품 종류를 강제로 요청
- 플레이어가 보관함을 비우거나 채워 고객 발생 종류를 직접 조작
- 거래를 쉽게 만들기 위해 시스템이 현재 제품과 정확히 일치하는 요청만 생성

허용되는 관계:

- 생성된 요청 종류에 맞는 기존 보관함 제품이 있으면 즉시 제안 가능
- 기존 제품이 없으면 요청 기한 안에 새로 제작 가능
- 기존 제품을 강화·수리해 조건을 맞출 수 있음
- 요청 후보 제품을 일반 판매하는 선택도 가능

일반 요청은 현재 보관함 상태를 참고해 `즉시 거래 가능 여부`를 표시할 수 있지만, 그 정보가 이미 확정된 요청 종류를 바꾸지는 않는다.

## 고객 성향 가중치

고객 유형 또는 사용 목적은 장비 종류 후보에 데이터 기반 가중치를 적용할 수 있다.

예시 방향:

| 고객 유형 | 상대적으로 높은 가중치 예시 |
|---|---|
| 수집가 | 의식 장비, 희소 장식 장비, 역사 가치가 드러나는 종류 |
| 모험가 | 방어구, 생존·기동·환경 대응 장비 |
| 검투사 | 무기, 경기 성능과 명성을 보여주는 종류 |
| 병사 | 방패, 표준 무기, 수리·보급이 쉬운 군용 종류 |

이 가중치는 장비 종류를 고객 전용으로 만들지 않는다.

- 수집가가 무기를 요청할 수 있음
- 검투사가 방어구를 요청할 수 있음
- 모험가가 장검을 요청할 수 있음
- 병사가 의식 장비를 요청할 수 있음

단지 고객 유형과 사용 목적에 더 자주 어울리는 종류의 상대 확률이 높아질 수 있다.

금지되는 구조:

- `검투사이면 장검만 요청`
- `수집가이면 의식 장비 외 요청 금지`
- 고객 이름을 검사해 장비 종류를 코드 분기로 고정
- 특정 고객 전용 장비 클래스를 별도 생성

고객 성향과 장비 종류 가중치는 콘텐츠 데이터로 정의한다. 정확한 수치와 가중치 표는 후속 밸런스 및 콘텐츠 명세에서 확정한다.

## 최근 일반 요청 반복 억제

최근 생성된 **일반 무작위 요청 2개**와 같은 정확한 장비 종류는 다음 일반 요청 생성 시 상대 가중치를 낮춘다.

```text
최근 일반 요청 이력
1. 장검
2. 방패

다음 일반 요청 생성
→ 장검 가중치 감소
→ 방패 가중치 감소
→ 다른 제작 가능 종류는 기본 가중치 유지
```

원칙:

- 최근 이력 길이: 일반 요청 2개
- 정확히 같은 장비 종류에만 반복 억제 적용
- 장비 대분류 전체를 금지하지 않음
- 반복을 완전히 금지하지 않음
- 제작 가능한 유효 종류가 하나뿐이면 해당 종류를 정상적으로 요청 가능
- 고객 성향상 특정 종류의 기본 가중치가 높더라도 반복 억제를 적용 가능
- 반복 억제 때문에 모든 가중치가 0이 되도록 만들지 않음
- 정확한 감소 배율은 플레이테스트 조정 대상으로 남김

반복 억제는 다음 항목에는 적용하지 않는다.

- 중요 고객 확정 트리거가 콘텐츠 데이터로 지정한 요청 종류
- 튜토리얼 또는 복구 목적의 필수 요청
- 아직 실제 요청으로 생성되지 않은 대기 중요 고객 트리거

일반 요청 이력에는 실제로 생성·저장된 일반 무작위 요청만 기록한다. 거절·만료·거래 여부와 관계없이 요청이 실제 생성됐다면 최근 이력에 포함한다.

## 중요 고객 확정 트리거의 장비 종류

중요 고객 트리거는 콘텐츠 데이터에서 다음 두 방식 중 하나를 사용할 수 있다.

1. 정확한 장비 종류 지정
2. 장비 범주 지정 후 현재 제작 가능 풀 안에서 종류 결정

### 정확한 종류 지정

- 트리거 데이터가 장비 종류를 직접 지정함
- 지정 종류가 고객 전용 장비가 되는 것은 아님
- 실제 요청 생성 시점에 해당 종류가 정상 제작 가능한지 검증함
- 아직 제작 불가능하면 요청을 잘못 생성하지 않고 트리거를 대기 또는 무효 상태로 유지함
- 선행 해금 조건 누락은 콘텐츠 데이터 오류로 기록함

### 범주 지정

- 예: `한손 무기`, `방어구`, `전시 가능한 장비`
- 실제 요청 생성 시 현재 제작 가능 종류로 후보 풀을 구성함
- 고객 성향·콘텐츠 규칙을 적용해 범주 안에서 한 종류를 선정함
- 선정 결과는 요청 생성과 함께 저장하며 앱 재실행으로 재추첨하지 않음

중요 고객 요청은 최근 일반 요청 반복 억제에 의해 막히지 않는다. 다만 중요 고객 요청 생성 이력과 일반 요청 이력은 진단·분석을 위해 구분해 기록한다.

## 2영업일 대응 가능성 검증

일반 요청은 플레이어가 현재 완제품을 갖고 있지 않아도 생성될 수 있다. 다만 현재 진행 상태에서 기본 2영업일 안에 정상적으로 대응할 수 있는 경로가 있어야 한다.

검증 대상:

- 제작에 필요한 기능이 해금돼 있는가
- 필수 재료가 정상 플레이에서 획득 가능한가
- 제작·강화·수리에 필요한 행동이 영업일 규칙상 허용되는가
- 요청 최소 조건이 현재 성장 단계에서 달성 가능한가
- 필수 조건이 사실상 고위 정밀강화 성공만을 강제하지 않는가
- 요청 생성 직후부터 기한 안에 최소 하나의 합법적 대응 계획이 존재하는가

`대응 가능성`은 성공을 보장한다는 뜻이 아니다.

- 자원이 부족할 수 있음
- 강화가 실패할 수 있음
- 다른 일반 판매를 우선할 수 있음
- 요청을 거절하거나 만료시킬 수 있음

그러나 시스템이 현재 진행에서는 만들 수 없는 종류나 달성 불가능한 최소 조건을 일반 요청으로 생성해서는 안 된다.

## 요청 종류 생성 순서

일반 요청이 발생하기로 확정된 뒤 다음 순서로 요청 종류를 결정한다.

```text
1. 현재 제작 가능 종류 목록 로드
2. 고객 유형·사용 목적 결정
3. 고객 성향 기본 가중치 적용
4. 최근 일반 요청 2개의 정확한 종류 가중치 감소
5. 진행 단계·콘텐츠 조건에 따른 후보 제외
6. 모든 유효 가중치 검사
7. 장비 종류 1개 추첨
8. 최소 조건·선호·보상 구성
9. 2영업일 대응 가능성 검증
10. 요청 데이터와 최근 이력 갱신 원자적 저장
11. 방문 고객 알림 표시
```

후보가 비어 있거나 대응 가능성 검증을 통과하지 못하면 잘못된 요청을 생성하지 않는다.

처리 원칙:

- 일반 요청 생성 실패를 플레이어의 미발생 누적으로 잘못 계산하지 않음
- 콘텐츠 데이터 오류 또는 유효 후보 없음으로 진단 기록
- 당일 판정을 무한 반복하지 않음
- 앱 재실행으로 다른 장비 종류를 다시 추첨하지 않음
- 테스트 환경에서 오류 원인을 확인할 수 있어야 함

정확한 오류 복구 정책은 구현 계획에서 정하되, 잘못된 요청을 사용자에게 노출하는 방식으로 숨기지 않는다.

## 생성 이력

일반 요청 반복 억제와 검증을 위해 최소 다음 이력을 저장한다.

- 요청 식별자
- 생성 영업일
- 생성 경로: 일반 확률 또는 연속 미발생 보정
- 고객 유형 또는 사용 목적
- 선정된 장비 종류
- 적용된 고객 성향 가중치 데이터 버전
- 최근 반복 억제 적용 여부
- 반복 억제 대상이었던 최근 장비 종류
- 최종 유효 후보 수
- 생성 완료 여부

최근 일반 요청 종류 이력은 최대 2개를 핵심 런타임 상태로 유지할 수 있으며, 전체 요청 기록은 장기 통계 또는 진단 기록으로 별도 보존할 수 있다.

## 원자적 저장 계약

다음 상태를 하나의 일관된 결과로 저장한다.

```text
요청 발생 확정
+ 고객 유형·사용 목적
+ 선정된 장비 종류
+ 최소 조건·선호·보상
+ 기본 2영업일 기한
+ 활성 요청 슬롯 점유
+ 최근 일반 요청 종류 이력 갱신
+ 당일 신규 요청 판정 완료
+ 일반 미발생 누적 초기화 또는 유지
```

금지되는 중간 상태:

- 요청은 생성됐지만 장비 종류가 저장되지 않음
- 요청 종류는 저장됐지만 최근 이력에 반영되지 않음
- 최근 이력만 갱신되고 요청이 생성되지 않음
- 앱 재실행 후 같은 요청의 장비 종류가 바뀜
- 보관함 변화로 이미 생성된 요청 종류가 변경됨
- 중요 고객 요청 때문에 일반 최근 요청 이력이 잘못 덮어써짐

저장 실패 시 요청 생성 전의 확정 상태로 복귀한다.

- 최소 조건
- 선호 방향
- 사용 목적
- 보상
- 남은 영업일
- 현재 보관함에서 즉시 제안 가능한 제품 수
- 새로 제작 또는 강화해 대응할 수 있다는 안내

`즉시 제안 가능한 제품 0개`는 오류가 아니다. 요청 기한 안에 제품을 준비할 수 있다면 정상 상태다.

보관함에 맞는 제품이 없다는 이유로 요청 종류를 사용자 모르게 교체하지 않는다.

## 검증 시나리오

버티컬 슬라이스와 구현 테스트에서 최소 다음을 검증한다.

1. 보관함에 해당 종류 제품이 없어도 제작 가능한 종류 요청이 정상 생성됨
2. 보관함 제품 구성 변경으로 이미 생성된 요청 종류가 바뀌지 않음
3. 고객 성향 가중치가 고객 전용 종류 제한으로 작동하지 않음
4. 최근 일반 요청 2개와 같은 종류의 상대 가중치가 감소함
5. 반복 억제 대상 종류도 완전히 금지되지 않음
6. 유효 종류가 하나뿐이면 그 종류 요청이 정상 생성됨
7. 중요 고객의 정확한 종류 지정이 일반 반복 이력에 막히지 않음
8. 제작 불가능한 중요 고객 지정 종류는 잘못된 요청으로 생성되지 않음
9. 앱 재실행 후 동일 요청 종류·조건·보상 유지
10. 요청 생성과 최근 이력 갱신 중 앱 종료 시 중복·재추첨 없음
11. 일반 요청 이력과 중요 고객 요청 이력이 구분됨
12. 신규 장비 종류 추가 시 고객 이름 코드 분기 없이 후보 풀에 편입 가능

## 현재 기획 상태 영향

이번 결정으로 해결되는 항목:

- 일반 요청 장비 종류 후보 풀 기준
- 고객 성향 가중치 적용 구조
- 최근 동일 종류 반복 억제 구조
- 보관함 비종속 생성 원칙
- 중요 고객 고정 종류·범주 처리
- 요청 종류 생성과 이력의 저장 계약

아직 미정인 항목:

- 고객 유형별 정확한 장비 종류 가중치
- 최근 반복 억제의 정확한 감소 배율
- 요청 최소 조건·선호 난이도 생성 규칙
- 요청 가격·특별 보상 산정 방식
- 버티컬 슬라이스 대표 고객 이벤트 조합
- 일반 영업과 방문 고객 이벤트를 포함한 15~25분 세션 예산
