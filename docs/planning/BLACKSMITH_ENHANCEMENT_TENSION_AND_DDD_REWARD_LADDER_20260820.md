## 1. 설계 목표

강화가 메인이라는 말이 실제 플레이 시간·감정 곡선·UI 우선순위에서 증명되어야 한다.

플레이어가 반복해서 느껴야 하는 감정은 하나의 고정 확률이 아니라 다음 곡선이다.

```text
규칙을 배운다
→ 성공을 믿게 된다
→ 처음으로 '여기서 멈춰도 된다'는 확보점을 얻는다
→ 더 욕심낼 이유가 생긴다
→ 손실이 실제로 무서워진다
→ 그래도 다시 한 번 누르고 싶어진다
```

## 2. 경험 밴드

정확 강화 레벨과 1:1로 고정하지 않는다. 먼저 경험 역할을 정의한 뒤 Balance Budget에서 실제 레벨 범위에 매핑한다.

### BAND A · LEARN

목적: 강화 버튼을 두려워하기 전에 행동→결과 규칙을 학습.

권장:

- 첫 1~2회 강화는 첫 세션 1~2분 안에 경험.
- 성공 기대: `90~100%` 권장 범위.
- 심각 손상: 없음.
- 연속 실패: 기본 0~1회 이내가 목표.
- anticipation: 짧음 `0.5~0.9s` 튜닝 후보.
- 성공 결과는 강화 단계·대표 능력/가치 상승을 즉시 보여준다.

실패 조건:

- 첫 강화에서 이유를 모른 채 작품이 손상됨.
- 성공 연출이 너무 길어 반복 입력 리듬을 방해.

### BAND B · BUILD_CONFIDENCE

목적: `강화하면 좋아진다`는 보상 기대를 학습.

권장:

- 성공 기대: `80~95%`.
- 실패: `FAIL_HOLD` 중심.
- 실패 누적 회복이 처음 보이기 시작.
- 2회 이상 연속 실패는 첫 세션에서는 드물어야 한다.
- 강화 결과마다 다음 확보점까지 남은 거리를 보임.

플레이어 질문:

> “한 번만 더 하면 첫 확보점인데?”

### BAND C · FIRST_STOP_POINT

목적: 처음으로 `멈추는 것도 정답`인 순간을 만든다.

권장:

- 첫 의미 있는 확보점/이정표.
- 성공 기대: `70~90%` 범위에서 튜닝 시작.
- 이 지점 도달 직후에는 플레이어가 즉시 작품을 사용할/인계할 가치가 있어야 한다.
- 다음 강화 보상은 명확히 매력적이어야 하지만 필수는 아니다.
- 심각 파손은 아직 기본값으로 사용하지 않는다.

플레이어 질문:

> “이 정도면 충분한데 더 갈까?”

### BAND D · TENSION

목적: 강화가 Blacksmith의 메인이라는 감정적 증거.

권장:

- 성공 기대: `55~80%`.
- `FAIL_HOLD + FAIL_DAMAGE` 혼합.
- 실패 누적 회복을 명확히 체감.
- ordinary bad-luck window: `3~5회 실패` 안에서 강한 보정 또는 확정 성공에 접근하도록 튜닝 후보.
- 손상은 단순 숫자 패널티가 아니라 `수리/계속/멈춤` 질문을 생성.

플레이어 질문:

> “지금 멈추면 이 작품은 안전하다. 그래도 한 번 더?”

### BAND E · HIGH_STAKES

목적: 작품 애착과 강화 욕심을 정면 충돌시킴.

권장:

- 성공 기대: `35~65%`.
- 고위험 시도 전에 한 번 의도적인 decision pause.
- 보호/완화 또는 강행 선택을 이 구간에서만 활성화하는 것을 우선.
- `CRITICAL_BREAK_UID_PRESERVED` 가능.
- UID 영구 삭제는 없음.
- bad-luck window: 기본 `4~7회` 이내에서 확정/매우 강한 보정 도달을 권장.
- anticipation: `1.2~2.0s` 튜닝 후보. 일반 강화보다 명확히 무겁게 느껴져야 함.

플레이어 질문:

> “이 작품을 망가뜨릴 수도 있는데, 성공하면 정말 특별해진다.”

### BAND F · MASTERY / OPTIONAL EXTREME

목적: 숙련 플레이어의 선택적 장기 욕구.

규칙:

- 첫 세션·초기 콘텐츠의 완료에 필수로 요구하지 않는다.
- 낮은 성공률을 콘텐츠 분량 늘리기에 사용하지 않는다.
- 성공률 하한은 우선 `25~40%` 범위에서 검토. 그보다 낮은 확률은 별도 근거가 없으면 사용하지 않는다.
- 강한 회복/확정 성공 상한과 비용 회복 루프가 필수.
- 매우 높은 단계의 가치는 단순 공격력/가격 배율만이 아니라 시각·이름·촉매 계보·고객/세계 기회 등 여러 payoff 후보로 분산한다.

## 3. 실패 누적 회복 — 권장 내부 모델

플레이어-facing 최종 명칭은 아직 정하지 않는다.

내부 계약 후보:

```yaml
recovery_progress:
  owner: ITEM_UID
  scope: CURRENT_ENHANCEMENT_BAND_OR_TARGET
  on_fail: INCREASE
  on_success: RESET_OR_CONSUME_FOR_TARGET
  cross_item_transfer: FORBIDDEN_BASELINE
  hidden_if_affects_probability: false
  hard_guarantee_or_strong_boost: REQUIRED_BEFORE_BAD_LUCK_CEILING
```

권장 이유:

- Blacksmith의 작품 단위 애착과 일치.
- 값싼 작품을 일부러 실패시키는 별도 failstack 게임을 만들지 않음.
- 플레이어가 '이 작품을 계속 두드렸다'는 서사를 강화함.

## 4. DDD Reward Ladder

### MICRO — 한 번의 강화

목표 시간: 수 초.

```text
강화 버튼
→ 0.5~2.0초 anticipation (위험도에 따라 스케일)
→ 타격/불꽃/금속음/VFX
→ 결과 reveal
→ 성공/유지/손상/파손 상태
→ 변화 숫자 1~3개 강조
→ 다음 질문
```

P0 피드백:

- 성공/실패 상태 텍스트.
- 강화 단계 변화.
- 핵심 작품 변화.
- 실패 누적 회복 변화.
- 손상 발생 시 즉시 다음 행동.

금지:

- 결과보다 파티클이 먼저 읽힘.
- 반복 시도마다 긴 연출 스킵 불가.
- 진동/색상/사운드 하나만으로 핵심 상태 전달.

### SESSION — 한 작품의 강화 여정

목표: 수 분~한 세션.

보상 사다리:

```text
첫 성공
→ 첫 확보점
→ 첫 위험 강화
→ 첫 실패 회복
→ 첫 이정표 선택
→ '여기서 멈춘 내 작품' 또는 '더 밀어붙인 내 작품'
```

Session completion은 최고 단계 도달이 아니라 **의미 있는 확보/도전 결정을 하나 이상 남긴 것**으로 본다.

### META — 작품 밖의 payoff

```text
강화된 작품 사용/인계
→ 고객·세계에서 성능/손상/기능이 드러남
→ 같은 UID 기록
→ 수리·복원·재강화 또는 다음 작품 목표
```

고객/세계 콘텐츠는 이 Meta payoff를 위해 존재하며 강화보다 더 긴 필수 조작 루프가 되어서는 안 된다.

## 5. 첫 세션 강화 배치 — 권장

목표: 첫 10분 안에 강화 메인 정체성을 증명.

```text
0:00~1:30
짧은 목표 / 첫 작품 확보

1:30~2:30
첫 안전 강화
→ 즉시 성공 경험

2:30~4:00
2~3회 Build Confidence
→ 강화가 실제 가치를 올린다는 학습

4:00~6:00
첫 확보점
→ 인계 가능 / 다음 위험 보상 공개

6:00~7:30
첫 의미 있는 멈춤 vs 도전
→ 첫 실패가 나와도 무진전이 아님

7:30~9:00
결과 확정 / 짧은 작품 UID 흔적

9:00~10:00
고객/세계의 짧은 payoff
→ 다음 강화 이유 생성
```

첫 세션 목표:

- 플레이어가 `강화가 메인`이라고 스스로 설명할 수 있다.
- 첫 위험 강화 전에 성공/비용/주요 실패를 읽는다.
- 첫 실패 시 `다시 누를 이유`를 하나 이상 본다.
- 첫 확보점에서 멈춤이 실제로 유효한 선택이다.

## 6. 기존 역사 수치와의 비교

역사 `data/crafting/enhancement_balance.json`:

- +1~+10 base success `98% → 68%`.
- decade마다 -2.5%p.
- minimum base success 25%.
- pity 실패당 +4%p, 최대 +24%p.
- +10까지 safe.
- +30부터 destroy risk.

판정:

- **ADAPT:** 초기 높은 성공률, 25% 하한 아이디어, 실패 누적 보정, 안전/고위험 구간 분리.
- **REVISE:** 100단계 장기 곡선, 정확 decade 패턴, 파괴로 UID 전체를 0으로 만드는 역사 구현.
- **TEST:** +10 단위 확보점, +4%p pity 크기, 손상/하락 비율.

## 7. 다음 중요한 기획 충돌

`BS-ENHANCE-20260820-05` — 실패 시 **강화 단계 하락**의 역할.

A. `DOWNGRADE_CORE`
- 중·후반 실패에서 단계 하락 유지.
- 긴장 가장 강함.
- 반복 재강화 피로와 확보감 훼손 위험 큼.

B. `CHECKPOINT_FLOOR + DAMAGE` **권장**
- 이정표/확보점은 영구 바닥으로 잠금.
- 구간 안에서는 일부 단계 하락 가능 또는 진전 손실 가능.
- 심각 실패는 단계 삭제보다 손상/복원 부담을 주로 사용.
- '여기까지 얻었다'는 DDD 확보감과 긴장을 함께 유지.

C. `NO_DOWNGRADE_DAMAGE_ONLY`
- 강화 단계는 절대 내려가지 않음.
- 실패는 비용·손상·복원·회복 진전만 사용.
- 가장 접근성 좋지만 후반 긴장도가 약해질 가능성.

현재 권장: **B**.

## 8. 재검토 조건

- 첫 10분에 강화보다 제작/고객 화면 체류 시간이 더 길다.
- 플레이어가 성공률을 보고도 무조건 누르거나 무조건 멈춘다.
- 실패 뒤 3초 안에 다음 행동을 찾지 못한다.
- 실패 누적이 '몇 번 실패하면 자동 성공'만 남겨 긴장감이 사라진다.
- 고위험 구간이 플레이어에게 선택이 아니라 필수 progression wall로 느껴진다.
- 작품 손상 때문에 좋아하는 작품은 아예 강화하지 않는 것이 정답이 된다.
