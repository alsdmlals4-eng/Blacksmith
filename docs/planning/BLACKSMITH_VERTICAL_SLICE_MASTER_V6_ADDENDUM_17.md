## 15~25분 세션 내 네 고객 동일 깊이 진행

사용자 선택에 따라 버티컬 슬라이스의 세션 구조는 **수집가·모험가·검투사·병사 네 고객을 모두 동일한 깊이로 진행**하는 방식으로 확정한다.

모든 세션에서 네 고객은 단순 비교 카드나 잠긴 티저가 아니라 실제 판매 대상이며, 판매 이후 각자의 세계 활동·결과·관계·장비 연대기까지 완주해야 한다.

```text
공통 강화 준비
→ 네 고객 요구·선호·야망 비교
→ 고객별 장비 배정·판매
→ 네 고객별 후속 활동 진행
→ 네 결과·관계·장비 연대기 확인
→ 다음 영업일 방향 확인
```

## 기존 결정에 대한 변경

이 결정은 기존의 `네 고객 비교 + 세션당 하나의 심화 분기` 권장안을 채택하지 않는다.

다음 범위가 새 기준이다.

- 검투사: 판매 후 경기·배팅·대표 수식어 심화·재방문까지 완료
- 모험가: 판매 후 원정 지원·귀환·손상 또는 분실·회수까지 완료
- 수집가: 판매 후 전시·감정·유물화 계열의 독립 세계 결과까지 완료
- 병사: 판매 후 군수 배치·부대 사용·손상 또는 공적 기록 계열의 독립 세계 결과까지 완료

수집가와 병사는 더 이상 데이터 호환성 점검만으로 충분하지 않다. 각각 실제 플레이 가능한 완주 사건 체인이 필요하다.

## 동일 깊이의 정의

`동일 깊이`는 네 고객의 콘텐츠 분량과 연출 시간이 완전히 같다는 뜻이 아니다. 각 고객이 아래의 공통 단계와 결과 계약을 모두 가진다는 뜻이다.

| 공통 단계 | 필수 내용 |
|---|---|
| 방문 | 이름·유형·요구·선호·야망·기한 표시 |
| 비교 | 장비 적합도·가격·즉시 보상·후속 가치 비교 |
| 판매 | 비용·보상·소유권 이전 원자적 저장 |
| 후속 준비 | 약속·지원·구독·배팅 또는 고객별 개입 선택 |
| 세계 진행 | 영업 종료 후 고객별 활동 결과 판정·저장 |
| 장비 운명 | 손상·분실·회수·명성·유물화 등 고객별 상태 변화 |
| 관계 | 관계·신뢰·대표 수식어 변화 |
| 연대기 | 장비 소유자·사건·성과·손실 기록 |
| 복귀 | 결과 확인 후 다음 행동 방향 제공 |

한 고객만 판매 이후 결과와 재방문을 제공하고 다른 고객은 판매로 끝나는 구조는 동일 깊이로 인정하지 않는다.

## 고객별 완주 체인

### 검투사

```text
무기 강화·고위 정밀강화
→ 검투사 판매
→ 경기 준비·배팅
→ 경기 결과
→ 대표 수식어 심화
→ 장비 상태·관계·연대기 갱신
→ 재방문
```

필수 검증:

- 공식 배당과 배팅 확정
- 경기 결과 1회 정산
- 승패 양쪽의 관계·수식어·연대기 변화
- 결과 확인 후 검투사의 다음 야망 표시

### 모험가

```text
탐험용 방어구 강화
→ 모험가 판매
→ 원정 사전 지원
→ 귀환·손상 또는 분실·회수
→ 장비 상태·관계·연대기 갱신
→ 재방문 또는 후속 요청
```

필수 검증:

- 지원 비용과 상태 원자적 저장
- 소유권과 점유·위치 상태 구분
- 회수 시 동일 장비 식별자와 연대기 유지
- 손상·분실 결과의 중복 적용 금지

### 수집가

```text
전시·의식용 장비 강화
→ 수집가 판매
→ 감정·전시·희소성 검증
→ 유물화 또는 역사 가치 상승 결과
→ 소유권·가치·대표 수식어·연대기 갱신
→ 재방문 또는 추가 감정 요청
```

필수 검증:

- 실전 성능과 다른 희소성·역사 가치 축
- 전시·감정 상태와 일반 판매 가치 구분
- 유물화가 장비 삭제나 복제 없이 동일 식별자에 적용
- 과거 소유자와 제작자 기록 유지
- 결과가 고객명 하드코딩 없이 공통 세계 사건 구조로 처리

### 병사

```text
군용 장비 강화
→ 병사 판매
→ 부대 배치·보급 또는 임무 준비
→ 사용 결과·손상·공적 기록
→ 소유권·부대 점유·관계·연대기 갱신
→ 재방문 또는 보급 요청
```

필수 검증:

- 개인 고객과 부대 사용 맥락을 공통 소유권·점유 구조로 표현
- 보급·수리·내구 지원 상태 저장
- 임무 결과가 장비 가치·공적·대표 수식어에 반영
- 병사 전용 별도 관계·저장 엔진 금지

## 세션 완료 조건

한 세션의 완료는 아래 항목이 모두 확인된 상태다.

1. 네 고객이 모두 실제 방문한다.
2. 네 고객 모두 요구·선호·야망·가격·후속 가치가 표시된다.
3. 네 고객 모두에게 장비가 판매되거나 배정된다.
4. 네 고객별 후속 준비 행동을 최소 하나 수행한다.
5. 영업 종료 후 네 고객의 세계 결과가 모두 판정·저장된다.
6. 네 고객별 장비 운명·관계·수식어·연대기 변화가 표시된다.
7. 네 결과를 확인한 뒤 각 고객의 다음 행동 방향을 알 수 있다.

한 고객의 결과가 누락되거나 설명 카드로 대체되면 전체 세션 미완료다.

## 장비 준비 전제

네 고객에게 각각 판매 가능한 장비가 필요하므로 버티컬 슬라이스는 복수 장비 준비를 전제로 한다.

필수 원칙:

- 세션 시작 시 네 고객 후보를 검증할 수 있는 준비 장비 또는 빠른 완성 경로 제공
- 모든 장비를 +0부터 장시간 강화하도록 요구하지 않음
- 대표 강화 체감은 최소 한 장비에서 충분히 제공
- 나머지 장비도 비용·위험·보호·판매 판단을 실제로 거침
- 고객별 장비가 서로 다른 유형·적합도·후속 가치를 보여야 함
- 동일 장비를 네 고객에게 중복 판매하지 않음

정확한 시작 강화 단계·초기 자원·장비 개수는 후속 세션 구조 결정에서 확정한다.

## 저장·복귀 계약

네 고객의 진행이 병렬로 존재하더라도 기존 저장 계약을 유지한다.

- 고객별 판매·소유권 이전은 각각 원자적으로 저장
- 고객별 약속·지원·배팅·보급 선택도 각각 원자적으로 저장
- 영업 종료 시 네 고객 세계 결과를 하나의 일관된 체크포인트로 저장
- 일부 고객 결과만 적용된 중간 상태 금지
- 결과 화면 도중 종료해도 네 고객의 동일한 확정 결과로 복귀
- 결과 확인 순서가 판정 결과를 바꾸지 않음
- 한 고객의 결과 복구가 다른 고객 보상을 중복 적용하지 않음

```text
영업 종료
→ 네 고객 결과 판정
→ 장비·소유권·관계·수식어·연대기 일괄 무결성 검사
→ 체크포인트 저장
→ 네 결과 묶음 표시
```

## UI·정보 구조 영향

네 고객 완주를 위해 기존 3개 최상위 영역은 유지한다.

- `[대장간]`: 복수 장비 준비·강화·수리
- `[방문 고객]`: 네 고객 비교·장비 배정·판매·후속 준비
- `[세계]`: 네 고객별 사건·경기·원정·전시·군사 결과

네 고객 때문에 네 번째 최상위 탭이나 고객별 독립 앱 구조를 만들지 않는다.

세계 결과 화면은 고객별 결과를 구분하되 다음 정보를 공통 형식으로 보여야 한다.

- 고객
- 장비
- 활동
- 결과
- 장비 상태
- 관계 변화
- 수식어 변화
- 연대기 추가
- 다음 행동

## 콘텐츠 파이프라인 영향

이 결정으로 대표 세트와 두 번째 증명 세트만 완주하던 범위를 넘어 네 고객 모두 완주 콘텐츠가 필요하다.

공통 데이터·시스템 재사용 원칙은 더 강하게 적용한다.

- 고객별 별도 강화 엔진 금지
- 고객별 별도 저장 파일 금지
- 고객 이름 하드코딩 분기 금지
- 수집가 전용 유물화도 공통 장비 상태·수식어·연대기 구조 사용
- 병사 전용 부대 사용도 공통 소유권·점유·세계 사건 구조 사용
- 네 세트 중 하나의 수정 후 나머지 세 세트 회귀 검증

네 고객 완주가 가능하더라도 공통 제작 규격 없이 수작업 전용 연결로 구성되면 파이프라인 합격으로 보지 않는다.

## 세션 시간 위험

15~25분 목표는 유지되지만, 네 고객 동일 깊이 진행은 기존 권장 구조보다 범위·정보량·결정 수가 크게 증가한다.

현재 단계에서 다음 항목은 미해결이다.

- 네 장비 준비 시간을 15~25분에 맞추는 방법
- 네 판매와 후속 선택을 압축하는 정보 구조
- 네 세계 활동을 순차 또는 병렬로 처리하는 방식
- 네 결과를 피로 없이 확인하는 묶음 구조
- 연출 시간과 반복 행동의 상한

따라서 이 결정만으로 `SHOULD_FIX_01_SESSION_FLOW`가 해결됐다고 판단하지 않는다. 후속 결정에서 네 고객 동시 완주 구조와 시간 예산을 다시 확정해야 한다.

## 플레이테스트 영향

비유도 플레이테스트 완료 조건을 다음과 같이 강화한다.

- 테스터는 네 고객을 모두 실제 비교해야 함
- 네 고객 판매·배정 상태를 이해해야 함
- 네 고객별 후속 결과를 모두 확인해야 함
- 네 장비의 현재 소유권·상태를 설명할 수 있어야 함
- 특정 고객 결과를 놓쳐도 세션 완료로 계산하지 않음

기존 `6명 중 5명 비유도 완료` 기준은 유지하되, 완료 정의에 네 고객 완주가 포함된다.

실제 테스트 전에는 `PLAYTEST_RESULT: NOT_AVAILABLE` 상태를 유지한다.
