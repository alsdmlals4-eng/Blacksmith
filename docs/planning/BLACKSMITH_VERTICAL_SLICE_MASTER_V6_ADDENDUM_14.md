## 두 번째 증명 세트 고객 확정

두 번째 완주 콘텐츠 세트는 **모험가 + 탐험용 방어구 + 원정 사전 지원 + 제한된 장비 운명 분기**로 확정한다.

수집가는 버티컬 슬라이스에 실제 방문·비교·판매 가능한 고객으로 유지하되, 별도의 완전한 세계 사건 체인을 제작하지 않는다. 수집가는 공통 고객·장비·소유권·연대기 데이터 구조에 정상적으로 들어가는지 확인하는 **데이터 호환성 점검 대상**으로 사용한다.

| 구분 | 적용 범위 | 검증 목적 |
|---|---|---|
| 모험가 | 두 번째 완주 증명 세트 | 지원·손상·분실·회수·복귀와 저장 구조 검증 |
| 수집가 | 방문·비교·판매·기본 결과 | 공통 데이터와 UI 호환성 검증 |

```text
대표 세트 A
검투사
→ 고위 정밀강화 무기
→ 경기·배팅
→ 수식어 심화
→ 재방문

증명 세트 B
모험가
→ 탐험용 방어구
→ 원정 관련 특수재료
→ 판매·소유권 이전
→ 원정 사전 지원
→ 귀환·손상 또는 분실·회수
→ 장비 연대기·관계 심화

호환성 점검
수집가
→ 공통 고객 데이터로 방문
→ 장비 비교·판매
→ 소유권·기본 연대기 기록
```

## 모험가 세트의 장비 경계

모험가 세트는 대표 검투사 세트의 무기와 구분되는 **탐험용 방어구 계열**을 사용한다.

필수 차이:

- 대표 세트와 다른 장비 유형이어야 한다.
- 장비 외형과 이름은 원정·생존·기동성 방향을 표현한다.
- 검투사 세트와 다른 특수재료 출처와 진화 후보를 사용한다.
- 고객 적합도는 단순 공격력보다 생존, 내구, 기동, 환경 대응 방향을 포함한다.
- 장비의 손상·분실·회수 상태가 외형·가치·수식어·연대기에 반영될 수 있어야 한다.

정확한 장비 이름, 특수재료 이름, 진화 후보 문구와 수치는 후속 콘텐츠 명세에서 확정한다. 다만 데이터 입력 규격과 저장 계약은 대표 검투사 세트와 동일하게 사용한다.

## 모험가 완주 흐름

### 1. 대장간 준비

```text
준비된 탐험용 방어구 선택
→ 일반 강화 또는 일반 정밀강화 경험
→ 원정 관련 특수재료 확인
→ 진화 후보 비교
→ 강화 결과 원자적 저장
```

- 버티컬 슬라이스 시작 장비와 자원은 15~25분 안에 전체 세트를 완주할 수 있도록 준비한다.
- 강화 성공률·비용·최대 하락·영구 파괴·보호 정보는 기존 작업대 계약을 그대로 사용한다.
- 모험가 장비 때문에 별도 강화 규칙이나 전용 판정기를 만들지 않는다.
- 고위 정밀강화를 사용하는 경우 후보 선택, 비용, 진화, 대표 수식어와 저장 순서는 검투사 세트와 동일한 원자적 계약을 사용한다.

### 2. 방문 고객 판매

```text
모험가 방문
→ 요구·선호·야망 확인
→ 탐험용 방어구 적합도 확인
→ 다른 고객 후보와 가격·보상 비교
→ 판매 확정
→ 소유권 이전 원자적 저장
```

모험가의 요구·선호·야망은 공통 고객 데이터 필드로 표현한다.

- 요구: 원정에 필요한 최소 조건
- 선호: 생존·기동·환경 대응 방향
- 야망: 특정 원정의 완수와 이후 성장 방향
- 즉시 보상: 판매 시점의 자금·재료·관계 보상
- 후속 가치: 원정 결과와 장비 연대기 변화 가능성

판매 완료 후 장비는 모험가 소유로 이전된다. 원정 중 손상되거나 분실되더라도 별도 사건이 소유권 이전을 명시하지 않는 한 소유자는 모험가로 유지한다.

### 3. 원정 사전 지원

판매 이후 원정 시작 전 제한된 사전 지원 선택을 제공한다.

지원 후보:

- 수리 또는 내구 보강
- 소모품 제공
- 원정 환경에 맞는 보조 재료 제공
- 지원하지 않고 현재 상태로 출발

```text
원정 일정 공개
→ 남은 영업일 표시
→ 지원 가능 항목 확인
→ 지원 선택 또는 보류
→ 비용·지원 상태 원자적 저장
→ 영업 종료 후 원정 진행
```

원칙:

- 지원은 원정 결과 방향에 영향을 줄 수 있지만 결과를 소리·색상 또는 숨은 수치로만 전달하지 않는다.
- 지원 선택에는 비용, 예상 도움 방향과 기한을 표시한다.
- 지원하지 않는 선택도 유효하며 자동 실패로 취급하지 않는다.
- 지원 완료 후 앱이 종료돼도 비용과 지원 상태가 함께 유지돼야 한다.
- 같은 지원을 재실행해 자원이 중복 소비되지 않아야 한다.

## 제한된 장비 운명 분기

모험가 세트는 파이프라인 증명을 위해 장비 운명 상태를 검증하되, 버티컬 슬라이스에서 모든 가능한 원정 결과를 제작하지 않는다.

대표 분기는 다음 두 계열로 제한한다.

| 분기 | 핵심 상태 | 후속 처리 |
|---|---|---|
| 귀환·손상 | 모험가와 장비가 귀환했지만 장비가 손상됨 | 수리·보강 요청, 관계·수식어·연대기 갱신 |
| 분실·회수 | 장비가 원정 중 분실되고 후속 사건에서 회수됨 | 소유권과 점유 상태 구분, 회수 결과·연대기 갱신 |

### 귀환·손상

```text
원정 결과 저장
→ 모험가 귀환
→ 장비 손상 상태 적용
→ 손상 원인과 성과 공개
→ 수리·보강 요청 또는 후속 약속
→ 장비 연대기·관계 갱신
```

- 손상은 장비 삭제나 영구 파괴와 구분한다.
- 현재 소유자는 모험가로 유지한다.
- 손상 상태, 수리 가능 여부와 수리 후 변화는 공통 장비 상태로 저장한다.
- 수리 전후 외형 또는 상태 문구를 확인할 수 있어야 한다.
- 원정 성과와 손상은 동시에 존재할 수 있다.

### 분실·회수

```text
원정 결과 저장
→ 장비 분실 상태 적용
→ 현재 소유자와 현재 점유 상태 분리
→ 회수 사건과 기한 공개
→ 제한된 지원 선택
→ 회수 결과 저장
→ 장비 연대기·관계 갱신
```

- `분실`은 자동 소유권 이전을 의미하지 않는다.
- 소유자, 현재 보유자 또는 위치와 장비 운명 상태를 구분한다.
- 회수 성공 시 기존 장비 식별자와 연대기를 유지한다.
- 회수된 장비를 새 장비로 복제하거나 보상을 두 번 지급하지 않는다.
- 회수 실패·영구 소실까지 버티컬 슬라이스의 필수 분기로 확장하지 않는다.
- 정확한 결과 확률과 지원 영향 수치는 플레이테스트 조정 대상으로 남긴다.

## 분기 범위 제한

두 번째 세트는 다음을 증명하면 충분하다.

- 사전 지원 상태가 세계 사건 결과에 연결된다.
- 장비 손상이 판매 이후에도 저장된다.
- 장비 분실 상태에서 소유권과 점유 상태가 구분된다.
- 회수 후 동일 장비 식별자와 연대기가 이어진다.
- 관계·대표 수식어·가치·연대기가 결과에 따라 갱신된다.
- 앱 중단·복귀 시 동일 결과가 유지되고 중복 보상이 발생하지 않는다.

버티컬 슬라이스에서 다음을 모두 제작하지 않는다.

- 다수 지역으로 구성된 장기 원정 지도
- 실시간 탐험 조작
- 전투 시스템
- 여러 단계의 무한 원정 분기
- 장비 분실 후 경매·도난·상속의 모든 후속 체인
- 모험가 전용 별도 경제 또는 관계 시스템
- 원정마다 새로운 저장 형식

## 수집가 데이터 호환성 점검

수집가는 깊은 두 번째 사건 세트가 아니라 공통 구조 호환성 검증 대상으로 사용한다.

필수 검증:

- 공통 고객 데이터로 방문 고객 목록에 나타난다.
- 요구·선호·야망·가격·즉시 보상을 같은 비교 UI에서 표시한다.
- 적합 장비를 판매하고 소유권을 이전할 수 있다.
- 구독 또는 관심 인물 상태를 공통 구조로 저장할 수 있다.
- 판매 장비의 기본 연대기와 현재 소유자를 기록한다.
- 앱 종료·복귀 후 방문·판매·소유권 상태가 유지된다.
- 수집가 데이터가 검투사·모험가 분기 코드에 의존하지 않는다.

수집가 범위에서 제외:

- 완전한 전시·감정·유물화 사건 체인
- 수집가 전용 최상위 화면
- 별도 역사 가치 저장 시스템
- 전용 강화 규칙
- 장기 재방문 시나리오 전체

수집가의 향후 전시·유물화 체인은 제3 콘텐츠 세트 후보로 남길 수 있지만, 현재 버티컬 슬라이스 합격 조건에는 포함하지 않는다.

## 공통 시스템 재사용 조건

모험가 세트와 수집가 호환성 점검은 다음 기존 구조를 재사용한다.

- `[대장간]`, `[방문 고객]`, `[세계]` 3개 최상위 영역
- 강화·정밀강화·고위 정밀강화 판정과 원자적 저장
- 고객 요구·선호·야망 비교
- 판매·소유권 이전
- 약속·지원·구독 상태
- 영업일과 사건 마감
- 세계 결과 저장과 미확인 결과 복귀
- 장비 현재 소유자·점유 상태·운명 상태·연대기
- 관계·수식어·가치 변경
- 알림·배지 우선순위와 남은 영업일 표시

고객 유형이나 장비 이름을 검사해 별도 시스템 경로로 보내는 구조를 사용하지 않는다.

## 회귀 검증

모험가 세트를 추가한 뒤 다음을 다시 검증한다.

- 검투사 세트의 강화·판매·경기·배팅·재방문 흐름이 변하지 않았는지
- 검투사 무기의 소유권과 연대기 저장이 모험가 방어구 상태 필드 때문에 손상되지 않았는지
- 수집가 방문·비교·판매가 같은 고객 UI에서 정상 동작하는지
- 장비 분실 상태가 영구 파괴나 판매 취소로 잘못 처리되지 않는지
- 모험가 회수 결과가 검투사 경기 보상과 중복 집계되지 않는지
- 세 콘텐츠 유형이 같은 알림을 여러 탭에 중복 생성하지 않는지
- 앱 종료·복귀 후 각 세트의 미확인 결과가 올바른 대상에 연결되는지

## 합격 조건

다음 조건을 모두 만족해야 모험가 두 번째 세트가 파이프라인 증명으로 인정된다.

1. 모험가와 탐험용 방어구가 공통 데이터 입력 규격으로 생성된다.
2. 대장간 강화부터 방문 고객 판매, 원정 지원, 세계 결과와 연대기까지 완주한다.
3. 손상 상태가 공통 장비 상태로 저장되고 수리 흐름과 연결된다.
4. 분실 상태에서 소유권과 점유 상태가 분리된다.
5. 회수 후 같은 장비 식별자와 연대기가 유지된다.
6. 두 번째 세트 전용 핵심 시스템이나 별도 저장 형식을 만들지 않는다.
7. 수집가가 공통 고객·판매·소유권 구조에 데이터 변경만으로 들어간다.
8. 대표 검투사 세트의 회귀 테스트를 통과한다.
