# Blacksmith Godot Vertical Slice Readiness Audit — 2026-08-06

## 판정

```text
PLANNING_VERDICT: CONDITIONALLY_FEASIBLE
IMPLEMENTATION_STATUS: BLOCKED_PENDING_EXPLICIT_USER_APPROVAL
HUMAN_PLAYTEST: NOT_RUN
CURRENT_POC_AUTHORITY: HISTORICAL_REFERENCE_ONLY
```

현재 승인된 기획을 모두 **계약과 경계로 적용**한 Godot 버티컬 슬라이스 데모는 진행 가능하다. 그러나 모든 장비·재료·고객·일정·강화 이정표를 동시에 구현하는 방식은 버티컬 슬라이스가 아니라 광범위한 제품 구현이므로 비채택한다.

권장 방식은 모든 승인 계약을 위반하지 않되, 대표 콘텐츠 한 경로만 처음부터 끝까지 연결하는 것이다.

## 감사 범위

- `project.godot`
- `scenes/main/main.tscn`
- `scripts/ui/game_flow_screen.gd`
- `scripts/forging/forging_session.gd`
- `scripts/enhancement/**`
- `scripts/customers/customer_contract.gd`
- `scripts/world/**`
- `scripts/economy/**`
- `data/crafting/**`, `data/customers/**`, `data/world/**`, `data/sales/**`
- Godot 4.7.1 import·parse·씬 스모크·모델·통합 검증
- 현재 R2 정본 Registry와 승인 Canon

## 확인된 기반

### 사용 가능

- Godot 4.7 프로젝트와 세로형 720×1280 기준
- 직접 단조 화면과 단조 세션
- 일반 강화 화면·세션·경제 자원 구조
- 고객 계약 모델과 화면
- 월드·진행·판매 데이터 디렉터리
- 모델·통합·씬 스모크 자동 테스트
- `scenes/main/main.tscn` 앱 흐름 셸 후보

### 그대로 사용할 수 없음

현재 `project.godot`의 시작 씬은 실제 앱 셸이 아니라 `scenes/test/enhancement_test.tscn`이다.

현재 POC에는 최신 정본과 충돌하는 역사 구현이 남아 있다.

- 단조 품질 `STANDARD / GOOD / PERFECT`
- 보조재료 선택과 재고
- 범용 `affixes` 배열
- 공격·가치 배율 중심 단조 결과
- 고정 계약 일수와 구형 고객 점수 가중치
- 작품 UID·변동 장부·세이브가 연결되지 않은 인메모리 보관함
- 과거 정확한 확률·비용·파괴 수치

이 코드는 실행 기반과 UX 참고로는 가치가 있지만 최신 정본 모델의 권위 구현으로 사용할 수 없다.

## 기획 충돌

### 충돌 1 — “모든 승인 기획 적용”과 버티컬 슬라이스 범위

모든 승인 기획을 콘텐츠 수량까지 전부 구현하면 범위가 제품 개발로 팽창한다.

해결 원칙:

```text
모든 승인 계약·금지사항: 반드시 적용
모든 콘텐츠 조합·수량: 대표 표본만 적용
```

### 충돌 2 — 최신 정본과 역사 POC 데이터 모델

최신 정본은 보조재료를 금지하고 제작 등급 5단계·세 수식어 슬롯·역할 수치·작품 UID 장부를 요구한다. 기존 POC는 보조재료와 구형 품질·범용 수식어 모델을 사용한다.

해결 원칙:

- 기존 클래스를 직접 증축하지 않는다.
- `scripts/vertical_slice/`, `data/vertical_slice/`, `scenes/vertical_slice/`처럼 새 경계를 둔다.
- 검증된 입력·화면 유틸리티만 선별 이식한다.
- 구형 필드와 새 필드를 한 작품 Dictionary에 혼합하지 않는다.

### 충돌 3 — 데모 수치와 최종 밸런스

제작 등급 확률, 예술성 구간, 강화 성공·파괴 확률, 고객 보정은 아직 사람 검증이 없다.

해결 원칙:

- 모든 정확한 값에 `BASELINE_TEST_PRESET` 표식을 둔다.
- 저장 데이터에 프리셋 버전을 기록한다.
- 데모 성공을 최종 밸런스 승인으로 해석하지 않는다.

## 권장 대표 경로

### 콘텐츠 표본

- 장비군: `SWORD` 1종
- 기본 작품: 철검 1종
- 주재료: 철 + 대비용 재료 2종
- 역할: `PHYSICAL_WEAPON / ATTACK`
- 최초 역할 수치: `5 / 10 / 15`
- 기본 중량: 대표 한 값과 `LIGHTWEIGHT / NONE / WEIGHTED`
- 최초 특수기능: 승인된 기능 중 2종만 노출
- 고객: 검투사·병사·귀족 3종
- 일정: 고객 개인 일정 1개, 예고형 세계 일정 1개

### 플레이 경로

```text
새 게임
→ 주재료·검 설계 선택
→ 역할별 3구간 직접 단조
→ 작품 UID 생성
→ 제작 등급 5단계·예술성·공격·중량·기능 확정
→ 일반 강화 지속·중단
→ 대표 +10 정밀강화에서 방식·촉매 선택
→ 촉매 SEED 또는 기존 계보 유지
→ 고객 3명 중 한 명에게 배정
→ 중량 Gate·대략 성공률·핵심 원인 2~4개 공개
→ 결과 처리
→ 연대기·손상 또는 복원 선택
→ 저장·종료·불러오기
→ 같은 UID 재방문
→ 다음 제작 판단
```

## 반드시 적용할 승인 계약

### 제작·작품

- `[보통 / 우수 / 명품 / 걸작 / 전설]`
- 동일 UID 제작 등급 고정
- 예술성 비음수 정수·고정 설계 최대치 없음
- `GRADE_AFFIX / CATALYST_AFFIX / CHRONICLE_AFFIX`
- 주재료 장비군 적합
- 3구간 직접 단조
- 역할 수치·중량·기능 용량
- 모든 변동 원인 장부

### 강화

- 일반 강화 한 입력 한 결과
- 일반 강화로 역할 수치·예술성 자동 증가 금지
- 대표 `+10` 정밀강화
- 수치 패키지와 기능 재작업 상호배타
- 촉매 계보 보존·동일 이정표 무한 재굴림 금지

### 고객·일정·UX

- 고객 능력 `1~10`
- 최대 중량 `STRENGTH × 10`
- 초과 장비 배정 금지
- 강화 단계가 성공률 주효과
- 성공률 10% 단위 대략 표시
- 기본 → 판단 → 상세 3단계 공개
- 48dp와 비색상 단독 신호 금지
- 개인 일정과 세계 일정 분리

## 데모에서 제외할 범위

- 모든 장비군·모든 주재료
- 다섯 정밀강화 이정표 전체의 완성 콘텐츠
- 전체 촉매 계보·전체 연대기 사건
- 완전한 경제·상점·광고·과금
- 모든 고객 가족과 장기 세계 시뮬레이션
- Android 스토어 출시 품질
- 최종 아트·오디오·현지화
- 최종 밸런스 확정

제외는 계약 무시가 아니라 대표 경로 바깥 콘텐츠 확장을 보류하는 것이다.

## 최종 결론

Godot 버티컬 슬라이스는 기술적으로 진행 가능하다. 현재 가장 큰 위험은 엔진이나 테스트 기반 부족이 아니라, 역사 POC를 최신 기획 구현으로 오인해 구형 필드를 혼합하는 것이다.

따라서 다음 Gate는 제품 코드 착수가 아니라:

```text
PR #119 정본 드리프트 폐쇄
→ R2 Batch 006 대표 범위·Schema 10건 승인
→ 별도 구현 승인
→ 새 namespace에서 버티컬 슬라이스 제작
```
