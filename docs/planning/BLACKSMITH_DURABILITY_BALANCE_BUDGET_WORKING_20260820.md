# [작업중 / 튜닝] Blacksmith 내구도 Balance Budget

- Parent: `BS-ENHANCE-20260820-05~06`
- 상태: `TUNABLE_BASELINE_TEST_PRESET / NOT_FINAL`
- 구현: `BLOCKED`
- Human/Player evidence: `NOT_RUN`

## 1. 목표

내구도는 강화의 긴장을 높이되 다음 실패를 만들지 않아야 한다.

- 초반에 작품이 갑자기 사라져 강화 학습을 막음
- 매일 자동 수리하는 유지비 세금
- 고가 작품에서는 항상 보호가 정답이 되는 가짜 선택
- 수리를 여러 번 클릭하는 반복 노동
- 0% 파괴가 너무 흔해 UID 애착을 포기하게 만듦

## 2. 손실 곡선 대안

### A. 고정 손실

모든 `FAIL_DAMAGE`가 같은 `%`를 잃는다.

- 장점: 매우 이해하기 쉽다.
- 문제: 단계가 올라가도 긴장 상승이 약하다.
- 판정: `REJECT_AS_PRIMARY`.

### B. 위험 밴드별 증가 손실 — 권장

```text
BUILD_CONFIDENCE < FIRST_STOP_POINT < TENSION < HIGH_STAKES
```

단계가 높아질수록 `FAIL_DAMAGE / FAIL_CRITICAL_DAMAGE`의 손실 범위가 커진다.

- 장점: 강화 가치·성공 보상·파괴 위험이 같이 상승한다.
- 파괴는 주로 이미 손상된 작품을 더 밀어붙일 때 현실적인 위험이 된다.
- 판정: `ADOPT_FOR_BASELINE_TEST`.

### C. 현재 내구도의 비율 손실

예: 항상 현재 내구도의 20% 감소.

- 장점: 고내구도에서 큰 숫자가 보인다.
- 문제: 0%에 수렴하기만 하고 파괴 조건이 불명료해지기 쉽다.
- 판정: `REJECT`.

## 3. 최초 테스트 범위

정확값이 아니라 시뮬레이션 시작 범위다.

| 경험 밴드 | 일반 손상 후보 | 심각 손상 후보 | 파괴 설계 |
|---|---:|---:|---|
| `LEARN` | 0% | 0% | 없음 |
| `BUILD_CONFIDENCE` | 3~6% | 없음 | 없음 |
| `FIRST_STOP_POINT` | 4~8% | 10~15% | 의도적으로 매우 희박/없음부터 테스트 |
| `TENSION` | 6~12% | 15~25% | 저내구도에서 현실적 |
| `HIGH_STAKES` | 10~20% | 25~50% | 명시적 고위험에서 허용 |
| `MASTERY` | 별도 테스트 | 별도 테스트 | 진행 필수 아님 |

설계 의도:

- 100% 작품이 한 번의 일반 실패로 바로 파괴되지 않는다.
- 파괴는 `이미 손상된 작품 + 추가 욕심`의 결과로 주로 발생한다.
- 25% 이하 작품에서 고위험 도전은 실제 파괴 선택으로 읽혀야 한다.
- 정확 확률과 손실량은 시뮬레이션/사람 플레이에서 조정한다.

## 4. 수리 UX 기본 후보

반복 클릭을 줄이기 위해 공방 수리는 **한 번의 행동으로 100%까지 회복**시키는 안을 우선 테스트한다.

```text
REPAIR_TO_FULL
current 1~99% → 100%
```

대신 비용과 작업량은 잃은 내구도에 비례한다.

```text
repair_burden ∝ missing_durability_percent × item_value_context
```

정확 공식은 확정하지 않는다.

장점:
- 5%씩 여러 번 수리하는 클릭 노동이 없다.
- 저내구도에서 `수리 비용을 낼지 / 그냥 납품할지 / 더 강화할지`가 한 번의 의사결정이 된다.

`FIELD_SERVICEABILITY`는 공방 밖에서 제한량만 회복하는 별도 예외다. 현장 완전 수리는 허용하지 않는다.

## 5. 파괴 직전 판단 UX

내구도가 낮다고 버튼을 잠그지 않는다.

예시:

```text
현재 +18 / 체크포인트 +10
내구도 27%
성공 61%
실패 시:
- 유지
- +17 하락
- 내구도 -6~12%
- 심각 손상 -15~25%
```

실제 파괴 가능성이 있으면 `파괴 가능`을 별도 텍스트로 표시한다.

## 6. 보호 수단 후보 — 아직 미승인

### P1. 손실 절반

한 시도의 내구도 손실을 50% 감소.

### P2. 파괴 방지

해당 시도에서 내구도가 0 이하가 될 경우 `1%`에 남김.

### P3. 손실 outcome 제거 대신 성공 보상 감소

내구도 손상 결과를 줄이는 대신 성공 시 성장 보상을 일부 포기.

현재 권장 탐색 순서:

`P1 → P2 → P3`.

P2는 고가 작품에서 항상 정답인 세금이 될 위험이 있으므로 자동 채택하지 않는다.

## 7. 세계 활동 마모 Budget

세계 활동은 자동 일일 내구도 세금이 아니다.

사건별 시작 후보:

- 경미한 마모: `1~5%`
- 의미 있는 환경 노출/충격: `5~12%`
- 큰 사건 손상: `10~25%`
- 명시적 재난/고위험 사건: 별도 승인/테스트

`ENVIRONMENTAL_SEALING`은 맞는 환경에서 손실을 완화할 수 있다. `FIELD_SERVICEABILITY`는 1% 이상 작품의 제한 현장 회복에 사용할 수 있다.

## 8. 파괴 후 상태

`0% -> DESTROYED`가 되면 active equipment pool에서는 제거한다.

그러나 다음 역사 레코드는 유지한다.

```text
uid
name
highest_checkpoint
highest_enhancement_reached
owner_history
world_history
damage_and_repair_history
destruction_source
destruction_timestamp
chronicle_provenance
```

파괴된 작품을 복제/부활하지 않는다.

## 9. 테스트 지표

시뮬레이션:

- 강화 밴드별 평균 파괴율
- 100% 시작 작품이 첫 파괴까지 버티는 평균 실패 수
- 체크포인트별 파괴율
- 수리 전 평균 잔여 내구도
- 수리 비용이 강화 비용 대비 차지하는 비율
- 실패 연속 길이와 누적 회복 효과
- 보호 옵션별 지배 전략 여부

Human:

- 파괴 가능성을 누르기 전에 이해했는가
- 파괴 후 `불공정`보다 `내가 무리했다`라고 설명하는가
- 수리를 반복 노동으로 느끼는가
- 25% 이하에서 멈춤/수리/도전이 실제로 갈리는가
- 파괴된 작품의 UID 기록을 다시 확인하고 싶은가

## 10. 완료 경계

이 문서는 Balance 시작점이다. 정확 수치는 승인 정본이 아니며 `Balance & Scenario Lab` 또는 기존 시뮬레이터를 새 제품 계약에 맞게 별도 구현/검증하기 전 `TUNABLE`이다.
