12. 등록·갱신 화면은 오늘의 사용 여부, 마지막 반영 시각, 다음 등록 가능 시점을 명확히 보여준다.
13. 갱신하지 않은 작품은 명예의 전당에서 `마지막 등록·갱신 시점 기준 상태`로 남으며, 실제 게임 내 현재 상태와 다를 수 있음을 표시한다.
14. 작품을 갱신해도 최초 입성 스냅샷은 유지되고 현재 상태와 마지막 갱신 시각만 새로 기록한다.
15. 현실 날짜의 기준 시간대, 일일 초기화 시각, 실패·취소 시 한도 소비 여부, 오프라인·온라인 권위 시간과 기기 시계 조작 방지는 후속 기술·운영 설계에서 확정한다.
16. 외부 작품의 시스템 운영 등록·갱신이 플레이어 계정의 일일 1회 한도를 사용하는지는 후속 설계에서 분리해 결정하며, 본 결정의 일일 제한은 플레이어가 실행하는 등록 행동을 우선 대상으로 한다.

### 기록 구조

```text
최초 등록
→ 현실 일일 등록권 1회 사용
→ 입성 스냅샷 영구 생성
→ 현재 상태 = 입성 상태
→ 마지막 반영 시각 기록

이후 작품 성장
→ 게임 내 실제 작품 상태만 변화
→ 명예의 전당 표시 상태 자동 변화 없음

후속 등록·갱신
→ 다음 현실 날짜의 일일 등록권 사용
→ 최초 입성 스냅샷 유지
→ 현재 상태만 새 스냅샷으로 교체
→ 마지막 반영 시각 갱신
```

### 보호 조건

- 게임 내 날짜를 넘겨 현실 일일 제한을 우회하지 않는다.
- 신규 등록과 갱신에 별도 일일 횟수를 제공해 하루 2회 이상 실행하지 않는다.
- 작품 데이터 변화마다 자동 갱신해 등록 행동의 선택 의미를 제거하지 않는다.
- 갱신하지 않은 상태를 실제 최신 상태인 것처럼 표시하지 않는다.
- 현재 상태 갱신으로 최초 입성 당시의 강화·수식어·세트·연대기를 덮어쓰지 않는다.
- 단순 조회·정렬·상세 열람이 등록 행동으로 오인되어 일일 한도를 소모하지 않게 한다.
- 시간대 변경·기기 시계 조작·재접속으로 등록 횟수를 무한 복구하지 않게 한다.
- 일일 제한을 유료 해제·광고 시청·희귀 재화 소비로 반복 확장하는 구조를 기본 설계로 두지 않는다.

### 후속 상세화

- R2: 현실 일일 1회 등록이 강화·연대기 성장과 만드는 장기 출품 리듬
- R3: `HALL_ENTRY_SNAPSHOT`, `HALL_CURRENT_SNAPSHOT`, `LAST_SUBMITTED_AT`, `DAILY_SUBMISSION_USED` 데이터
- R4: 자격 검증→등록권 확인→스냅샷 생성 또는 현재 상태 갱신→원자적 한도 소비 파이프라인
- R5: 시간 조작, 다중 기기, 중복 요청, 등록 스팸과 일일 제한 유료화 방지
- R6: 입성 당시/현재 상태/마지막 반영 시각/다음 가능 시점 비교 UI
- R7: 일일 제한의 답답함, 등록 선택의 의미, 스냅샷 이해도와 반복 억제 효과 검증
