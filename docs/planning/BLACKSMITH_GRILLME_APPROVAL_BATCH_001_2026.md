## 1. 배치 목적

현재까지 사용자에게 Grill Me 방식으로 제시하고 승인받은 핵심 기획 결정을 하나의 병합 단위로 묶는다. 이 배치는 승인 기록을 새로 해석하거나 대체하지 않으며, 기존 Decision ID와 상세 정본을 병합 전 검증 가능한 목록으로 연결한다.

## 2. 포함 승인 결정

### 2.1 `BS-CORE-20260802-01` — 피로도·날짜 진행 핵심 불변

- 피로도와 날짜는 클리커형 무제한 반복과 구분되는 핵심 리듬이다.
- 한 명의 대장장이가 제한된 하루 안에서 제작·강화·복원·납품 우선순위를 선택한다.
- 날짜는 세계 일정·시장·의뢰·고객 재방문·사건을 연결하는 공통 시간축이다.

### 2.2 `BS-CORE-20260802-02` — 강화 주도 코어와 작품 역사 환류

- 가장 자주 반복되는 메인 재미는 강화 성공·실패와 멈춤·추가 도전 판단이다.
- 고객 납품과 결과 이벤트는 강화 사이의 휴식·보상·세계 환류 구간이다.
- 장기 차별화는 작품의 소유자·사건·운명·연대기가 다시 제작 동기로 돌아오는 데 있다.

### 2.3 `BS-SET-20260802-02` — 사건 연대기 기반 동적 세트

- 세계 일정에 실제 납품·사용·기여한 고유 작품들이 동일 사건 연대기 ID를 공유하면 연대기 세트가 된다.
- 사건 전 후보는 예정 세트이며, 실제 기여가 확인된 뒤에만 역사적 세트로 확정한다.
- 각 작품의 UID·제작 품질·강화 경로·수식어·소유자·운명은 독립 보존한다.

### 2.4 `BS-SET-20260802-03` — 연대기 세트 3층 보상

1. 모든 상황에서 작동하는 작은 범용 능력치 보정
2. 환경·위협·임무·제약·전술·사회 상황 태그가 유사한 새 사건에서 추가 정보·선택지·전용 장면
3. 사건명·날짜·기여 작품·결과를 짧게 확인하고 상세 기록을 펼쳐보는 역사 기능

동일한 세계 일정의 반복은 전제하지 않는다. 정확한 수치·상한·점감·태그 유사도 기준은 `RECOMMENDED_DEFAULT / TEST_VALUE`다.

### 2.5 `BS-SET-20260802-04` — 실패 사건도 연대기 세트 성립

- 사건이 성공·부분 성공·실패 중 어떤 결과로 끝나더라도 작품이 실제로 기여했다면 사건 연대기와 연대기 세트가 성립한다.
- 결과에 따라 세트 별칭·범용 보정의 성격·상황 태그·전용 장면·후속 사건이 달라진다.
- 실패 기록은 성공 보상의 열화판이 아니라 희생·후퇴·생환·최후 방어·교훈·복구의 역사로 취급한다.
- 작품을 배정만 하고 실제로 사용하지 않은 경우에는 세트 구성품으로 인정하지 않는다.
- 고의 실패 파밍이 유리하지 않도록 보상 가치와 후속 기회의 종류를 결과·기여도·손실에 따라 구분한다.

예시:

```text
사건 결과: 왕도 방어 실패
실제 기여: 후퇴로 확보·민간인 생환
연대기 세트: 무너진 성문의 최후 방패
상황 태그: [방어] [포위] [후퇴] [희생] [생환]
후속 가능성: 파손 장비 복원, 생존자 재방문, 설욕전 준비
```

## 3. 병합 전 필수 게이트

병합 직전 다음을 모두 새로 확인한다.

1. GitHub 정본·승인 원장·PR 본문의 Decision ID, 의미, 파일 경로가 일치한다.
2. Google Sheet 결정 원장·GDD 요약·변경 이력의 Decision ID, 의미, 정본 커밋, 상태가 일치한다.
3. PR changed files에 제품 코드·Scene·런타임 데이터·에셋이 포함되지 않는다.
4. PR의 unresolved review thread, requested changes, 충돌, 병합 가능 상태를 확인한다.
5. CI/check 상태를 확인하고 실패·대기·미실행을 구분한다.
6. 승인된 결정 누락, 상호 충돌, 구형 문서의 반대 서술, Sheet 범위 오기재를 적대적으로 검토한다.
7. 차단 결함이 없을 때만 expected HEAD SHA를 고정하여 `squash` 병합한다.

## 4. 향후 Grill Me 병합 주기

- 이번 배치 병합 후 승인 카운터를 `0`으로 재설정한다.
- 이후 Grill Me 승인 결정이 `10건` 누적될 때마다 새 승인 배치를 만든다.
- 10건에 도달하기 전에는 승인 결정을 GitHub 정본과 Sheet에 즉시 동기화하되, 원칙적으로 병합하지 않고 Draft PR에 누적한다.
- 긴급 충돌 수정·정본 복구·보안 또는 데이터 손상 방지는 10건 규칙의 예외가 될 수 있으나, 별도 Decision ID와 근거를 남긴다.
- 병합 직전에는 항상 본 문서 3절의 상세 대조와 적대적 검토를 다시 수행한다.
- 병합 방식은 누적된 중간 커밋을 정리하기 위해 기본적으로 `squash`를 사용한다.
