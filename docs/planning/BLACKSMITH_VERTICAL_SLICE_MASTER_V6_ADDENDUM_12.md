## Android 테스트 패키지 경계

버티컬 슬라이스의 Android 산출물은 **세로형 스마트폰 중심의 설치 가능한 내부 테스트 패키지 + 저사양·중간·상위 3단계 기준 기기군**으로 한정한다.

이 패키지는 핵심 루프와 사용자 경험 계약을 실제 기기에서 검증하기 위한 테스트 산출물이다. 정식 출시 후보, Google Play 상용화 패키지, 전체 Android 호환성 보증 또는 장기 운영 빌드가 아니다.

```text
목적
→ 내부·외부 테스터가 Android 스마트폰에 설치
→ 15~25분 버티컬 슬라이스 전체 흐름 검증
→ 성능·저장·중단 복귀·접근성·화면 비율 검증

아님
→ 정식 출시 빌드
→ 스토어 상용화 후보
→ 모든 Android 기기 호환성 보증
→ 전체 +100 장기 콘텐츠 패키지
```

## 패키지 목적

테스트 패키지는 다음 질문에 답해야 한다.

- 준비된 장비로 시작해 1분 이내 강화에 진입할 수 있는가
- 저위험 반복 강화가 Android 터치 환경에서 반응성 있게 작동하는가
- 일반 정밀강화와 고위 정밀강화의 위험·비용·결과가 세로 화면에서 읽히는가
- `[대장간]`, `[방문 고객]`, `[세계]`의 3영역 흐름이 15~25분 안에 연결되는가
- 앱 중단·백그라운드·강제 종료 이후 동일 결과와 상태로 복귀하는가
- 텍스트 확대, 모션 감소, 무음·무진동, 길게 누르기 대체 입력으로 핵심 흐름을 완료할 수 있는가
- 저사양·중간·상위 기기군에서 성능 저하가 입력·판정·저장 무결성을 훼손하지 않는가

테스트 패키지는 이 질문에 필요한 기능과 콘텐츠만 포함한다. 출시 운영 기능을 미리 채우기 위해 범위를 확장하지 않는다.

## 지원 플랫폼 경계

### 포함

- Android 스마트폰
- 세로형 화면 우선
- 터치 입력
- 저사양·중간·상위의 3단계 기준 기기군
- 기기 내 로컬 활성 진행 저장
- 오프라인 핵심 슬라이스 진행
- APK 또는 동등한 내부 배포용 설치 패키지
- 기존 설치본 위에 테스트 업데이트를 적용하는 경로

### 필수 범위에서 제외

- Android 태블릿 전용 레이아웃
- 폴더블 펼침 화면 전용 최적화
- 가로 화면 전용 UI
- PC용 Android 실행 환경 대응
- 게임패드·키보드 전용 조작
- iOS 패키지
- 웹 패키지

제외 대상에서 실행 자체를 의도적으로 차단해야 한다는 뜻은 아니다. 다만 버티컬 슬라이스의 합격 기준과 제작 의무에 포함하지 않는다.

## 3단계 기준 기기군

정확한 기기 모델과 Android 버전은 구현 계획에서 확정하되, 테스트 범주는 다음 세 단계로 고정한다.

| 기기군 | 목적 | 주요 검증 |
|---|---|---|
| 저사양 | 최소 허용 경험 검증 | 안정적인 30fps 하한, 메모리·발열, 적응형 품질 축소 |
| 중간 | 대표 사용자 경험 기준 | 일반 UI·반복 강화 60fps 목표, 전체 슬라이스 안정성 |
| 상위 | 최대 연출 품질 검증 | 고위 정밀강화·세계 결과의 전체 연출과 고해상도 자산 |

기기군 선정 원칙:

- 실제 테스트 가능한 물리 기기를 최소 한 대씩 포함한다.
- 세 기기군의 화면 비율과 메모리 규모가 동일하지 않게 한다.
- 저사양 기준은 실행만 가능한 기기가 아니라 전체 슬라이스 완료가 가능한 최소 경험을 대표해야 한다.
- 상위 기기에서만 핵심 정보나 기능이 완전하게 보이는 구조를 허용하지 않는다.
- 에뮬레이터 결과만으로 기준 기기 검증을 대체하지 않는다.

## 화면 방향과 비율

- 기본 방향은 세로형으로 고정한다.
- 자동 회전으로 가로 화면에 전환되어 핵심 조작 영역이 무너지는 상태를 허용하지 않는다.
- 다양한 세로 화면 비율에서 상단 정보, 중앙 장비, 하단 고정 조작 영역과 3개 탭이 겹치지 않아야 한다.
- 카메라 구멍, 노치, 시스템 상태 영역과 하단 제스처 영역이 핵심 버튼을 가리지 않아야 한다.
- 정확한 최소·최대 화면 비율과 해상도는 구현 계획에서 기준 기기군과 함께 확정한다.

검증 대상:

- 긴 세로 화면에서 정보 간격이 과도하게 벌어지지 않는지
- 짧은 세로 화면에서 성공률·비용·파괴 위험·강화 버튼이 잘리지 않는지
- 텍스트 확대 상태에서 하단 내비게이션과 위험 정보가 겹치지 않는지
- 하단 패널이 시스템 제스처 영역과 충돌하지 않는지

## 네트워크·계정 경계

버티컬 슬라이스의 핵심 진행은 인터넷 연결 없이 완료 가능해야 한다.

포함하지 않는 항목:

- 필수 로그인
- 계정 생성
- 소셜 로그인
- 클라우드 저장
- 온라인 동기화
- 온라인 순위표
- 실시간 멀티플레이
- 서버 의존 강화 판정
- 푸시 알림

세계 게시판과 구독 소식은 실제 온라인 서비스가 아니라 슬라이스 내부 세계 시뮬레이션 결과로 제공한다. 네트워크가 없다는 이유로 강화, 고객 판매, 약속, 경기·배팅, 세계 결과 흐름이 중단되지 않는다.

## 권한 정책

테스트 패키지는 핵심 슬라이스에 필요하지 않은 Android 권한을 요구하지 않는다.

기본적으로 요구하지 않는 권한:

- 연락처
- 통화 기록
- 위치
- 카메라
- 마이크
- 사진·미디어 전체 접근
- 알림 권한

진단 로그 내보내기처럼 선택적 기능이 추가되더라도, 권한 거부로 핵심 플레이가 차단되지 않아야 한다. 정확한 파일 접근 방식은 구현 계획에서 결정한다.

## 설치·최초 실행 검증

필수 검증:

- 새 설치 후 정상 실행
- 첫 화면에서 `[대장간]` 진입
- 준비 장비와 초기 자원 상태 로딩
- 첫 강화까지 불필요한 로그인·권한·다운로드 절차가 없는지
- 앱 버전과 테스트 빌드 식별 가능
- 저장 데이터가 없는 상태와 기존 저장이 있는 상태를 올바르게 구분
- 초기화 오류를 강화 실패나 저장 손상으로 오인하지 않음

첫 실행에서 정식 서비스용 이용약관, 결제, 광고 동의나 계정 생성 흐름을 필수로 요구하지 않는다.

## 업데이트·저장 마이그레이션 경계

내부 테스트 중 패키지 업데이트가 기존 활성 진행을 보존하는 경로를 검증한다.

```text
기존 테스트 빌드 실행
→ 활성 저장 검증
→ 마이그레이션 전 복구 스냅샷 보관
→ 새 테스트 빌드 설치
→ 저장 구조 변환
→ 무결성 검사
→ 동일 활성 진행 복귀
```

- 테스트 빌드 업데이트가 항상 저장 초기화를 요구해서는 안 된다.
- 마이그레이션 실패 시 손상 상태를 정상 진행으로 덮어쓰지 않는다.
- 장비 강화 단계, 수식어, 소유권, 약속, 구독, 관계와 연대기 참조를 함께 검증한다.
- 정확한 지원 이전 버전 수는 구현·테스트 계획에서 결정한다.
- 정식 출시까지의 영구 마이그레이션 호환성을 이 슬라이스에서 보증하지는 않는다.

## Android 시스템 중단·복귀

다음 중단 상황을 필수 검증한다.

- 홈 버튼 또는 제스처로 백그라운드 이동
- 최근 앱 전환
- 화면 잠금과 잠금 해제
- 알람·전화·시스템 팝업 등 포커스 중단
- 앱 프로세스가 유지된 상태의 복귀
- 운영체제가 프로세스를 종료한 뒤 재실행
- 강제 종료 후 재실행
- 저메모리 경고 또는 자원 회수 후 복귀

복귀 계약:

- 최종 입력 완료 전 중단은 행동 미실행·자원 미소비 상태로 복귀
- 원자적 저장 완료 후 중단은 동일 결과 유지
- 강화·거래·세계 결과 연출 도중 중단은 저장된 결과를 다시 표시
- 앱 중단만으로 세계 시간이나 남은 영업일이 진행되지 않음
- 사운드·진동·연출이 중복 재생되지 않음
- 동일 강화·배팅·보상·관계 변경이 중복 적용되지 않음

## Android 뒤로 가기 계약

- 하단 패널이 열려 있으면 현재 패널을 먼저 닫는다.
- 고객·사건·장비 직접 이동 화면에서는 이전 맥락으로 복귀한다.
- `[대장간]`, `[방문 고객]`, `[세계]`의 최상위에서 뒤로 가기를 눌렀다고 비가역 행동이 취소되지 않는다.
- 강화 최종 입력이 완료된 뒤 뒤로 가기로 판정·저장을 취소할 수 없다.
- 앱 종료로 이어지는 뒤로 가기에는 진행 손실이 없도록 마지막 확정 상태가 이미 저장돼 있어야 한다.
- 영업 종료는 Android 뒤로 가기가 아니라 게임 내 명시적 선택으로만 실행한다.

정확한 루트 화면 종료 확인 방식은 UI 프로토타입에서 결정한다.

## 저메모리·자원 회수

저사양 기기와 장시간 세션에서 다음을 검증한다.

- 백그라운드 복귀 시 파괴된 장비나 이전 장비 자산이 다시 나타나지 않는지
- 고위 정밀강화 전용 연출 자산이 일반 작업대 복귀 후 정리되는지
- 고객 네 유형과 세계 화면을 순회해도 메모리가 지속 증가하지 않는지
- 운영체제 자원 회수 후 미확인 결과가 안전하게 복구되는지
- 저메모리 상태에서 저장 파일이 일부만 기록되지 않는지
- 자산 로딩 실패를 강화·사건 실패 결과로 위장하지 않는지

프레임·메모리 문제로 장식 효과는 축소할 수 있지만 핵심 정보와 상태 무결성은 유지한다.

## 접근성 실기기 검증

각 기준 기기군에서 최소한 다음 설정 조합을 검증한다.

- 텍스트 확대
- 모션 감소
- 무음
- 무진동
- 길게 누르기 대체 입력
- 세로형 한 손 조작
- 핵심 화면 읽기 순서와 대체 문구

검증 항목:

- 확대 상태에서 강화 버튼과 위험 정보가 겹치지 않는지
- 색상 없이 성공·실패·하락·파괴를 구분할 수 있는지
- 무음·무진동 상태에서 결과를 누락 없이 이해하는지
- 모션 감소 상태에서 정밀강화와 고위 정밀강화를 구분하는지
- 대체 입력이 확률·비용·결과를 변경하지 않는지
- 화면 읽기 포커스 이동이 행동 실행으로 오인되지 않는지

## 15~25분 세션 검증

각 기준 기기군에서 버티컬 슬라이스 전체를 반복 실행한다.

대표 흐름:

```text
앱 실행
→ [대장간] 강화·정밀강화·고위 정밀강화
→ [방문 고객] 비교·판매·약속·지원
→ 영업 종료
→ [세계] 게시판·구독·경기·배팅·장비 결과
→ 검투사 재방문 또는 장비 연대기 확인
```

검증 항목:

- 15~25분 목표 시간 안에 세 영역을 완료하는지
- 반복 강화 후 입력 지연이 누적되지 않는지
- 장시간 사운드·진동·파티클 피로가 과도하지 않은지
- 프레임과 메모리가 세션 후반에 지속 악화되지 않는지
- 발열로 적응형 품질이 작동해도 핵심 정보가 유지되는지
- 백그라운드 중단을 포함해도 총 흐름이 파손되지 않는지
- 완료 후 다음 세션 복귀가 동일 상태에서 시작되는지

## 배포·식별 원칙

- 테스트 패키지임을 앱 내부에서 식별할 수 있어야 한다.
- 빌드 버전, 콘텐츠 버전과 저장 버전을 구분할 수 있어야 한다.
- 테스터가 오류 보고 시 사용한 빌드를 확인할 수 있어야 한다.
- 정식 스토어용 이름·설명·스크린샷·등급 분류 완성은 필수 범위가 아니다.
- 테스트 패키지 배포 방식과 서명 키 관리는 구현·운영 계획에서 결정한다.
- 배포 편의를 이유로 플레이어 진행 데이터나 진단 정보를 외부에 자동 전송하지 않는다.
