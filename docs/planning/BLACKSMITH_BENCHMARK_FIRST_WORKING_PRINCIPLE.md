## 1. 원칙

Blacksmith는 매 작업마다 대규모 조사를 반복하지 않는다.

다만 다음 대상의 설계를 새로 시작하거나 기존 계약을 크게 변경할 때는 **설계안 작성 전에 관련 벤치마킹을 반드시 수행한다.**

- 새 시스템
- 프로젝트 코어를 바꾸는 핵심 규칙
- 반복 플레이에 영향을 주는 콘텐츠 구조
- 주요 화면·탭·입력·복귀를 바꾸는 UX 흐름
- 경제·강화·보호·저장·서버·랭킹처럼 여러 소비자에 전파되는 규칙

```text
새 설계 요청
→ 선행 벤치마킹 필요 여부 판정
→ 관련 사례와 플랫폼 기준 조사
→ 채택·변형·제외 분류
→ Blacksmith 코어에 맞춘 설계
→ 충돌·전파·검증 항목 기록
→ 사용자 결정 또는 현행 기획 반영
```

## 2. 벤치마킹을 생략할 수 있는 작업

다음은 기존 승인 계약을 바꾸지 않는 한 새 조사를 요구하지 않는다.

- 오탈자·문장 정리
- 문서 경로·목차·표현 정합화
- 이미 승인된 규칙의 단순 Sheet 동기화
- 기존 데이터 필드에 콘텐츠 항목만 추가
- 이미 정의된 UX 흐름의 라벨·간격·카피 미세 조정
- 기존 계약을 그대로 따르는 버그 수정 계획
- 같은 조사 결과를 사용하는 연속 세부 작업

단, 작은 변경처럼 보여도 결과적으로 핵심 규칙·정보 위계·경제·저장·접근성 계약을 바꾸면 벤치마킹 대상이다.

## 3. 조사 깊이

### LIGHT

- 동일 작업군에서 이미 최근 벤치마킹을 완료함
- 기존 구조 안의 제한된 변형
- 공식·1차 출처 중심 2~4개 사례

### STANDARD

- 새 시스템·콘텐츠 구조·주요 UX 흐름
- 직접 경쟁작과 인접 장르 4~8개 사례
- Android·플랫폼 공식 기준 포함
- 기본값

### DEEP

- 프로젝트 코어 변경
- 대규모 경제·라이브 운영·서버·보안·법적 위험
- 여러 시스템을 동시에 교체
- 기존 정본과 실제 구현을 광범위하게 뒤집는 작업

DEEP 조사는 필요할 때만 수행한다. 단순히 자료가 많다는 이유로 선택하지 않는다.

## 4. 필수 산출물

새 설계에는 최소한 다음 기록이 있어야 한다.

| 항목 | 내용 |
|---|---|
| Design Question | 무엇을 결정하기 위한 조사인지 |
| References | 사용한 공식·1차 출처와 보조 출처 |
| Adopt | 그대로 받아들일 구조 |
| Adapt | Blacksmith 코어에 맞게 변형할 구조 |
| Avoid | 범위 과잉·위험·정체성 훼손 때문에 제외할 구조 |
| Decision | 최종 추천안과 이유 |
| Propagation | 어떤 문서·데이터·UX·테스트가 영향을 받는지 |
| Validation | 어떤 테스트로 가설을 확인할지 |

## 5. 출처 규칙

우선순위:

1. 공식 게임 페이지·공식 문서·개발사 자료
2. 실제 게임 화면·공식 트레일러·공식 패치 노트
3. 신뢰할 수 있는 리뷰·분석
4. 커뮤니티 반응은 문제 발견의 보조 증거로만 사용

다른 게임의 명칭·캐릭터·수치·아트·카피를 복제하지 않는다. 벤치마킹 대상은 원리, 정보 구조, 선택 구조, 피드백 방식과 실패 사례다.

## 6. 재조사 조건

다음 중 하나가 발생하면 기존 조사 결과를 그대로 재사용하지 않고 필요한 범위만 갱신한다.

- 핵심 설계 질문이 변경됨
- 플랫폼 정책·공식 가이드가 변경됨
- 벤치마크 게임이 대규모 업데이트로 구조를 변경함
- 서버·보안·결제·개인정보처럼 최신성이 중요한 영역
- 기존 조사로 설명되지 않는 새로운 충돌이 발견됨
