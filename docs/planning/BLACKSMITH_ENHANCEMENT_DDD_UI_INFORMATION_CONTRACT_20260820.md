# [제안] Blacksmith 강화 DDD UI Information Contract

- Parent: `BS-CORE-20260820-01`
- 상태: `PROPOSED / VISUAL_BRIEF_INPUT`

## 강화 화면 P0 정보

플레이어가 강화 결정을 내리기 전 2~3초 안에 다음을 읽을 수 있어야 한다.

1. 현재 작품/강화 상태
2. 강화 성공 기대
3. 이번 시도 비용·작업량
4. 실패 시 가장 중요한 결과
5. 현재 사용할 수 있는 보호/완화 수단
6. 성공하면 도달하는 다음 확보점/이정표
7. `멈춤`과 `도전` 행동

## 정보 계층

```text
P0: 강화 단계 + 성공 기대 + 실패 핵심 결과 + 비용 + 강화 버튼
P1: 보호/회복 상태 + 다음 이정표
P2: 세부 확률 구성·역사·수학 근거
```

## DDD Feedback states

```text
READY
ANTICIPATION
SUCCESS
FAIL_HOLD
FAIL_DAMAGE
CRITICAL_BREAK_CANDIDATE
RECOVERY_PROGRESS
MILESTONE_READY
STOP_AND_SECURE
```

각 상태는 색상만으로 구분하지 않고 텍스트/형태/아이콘/모션/소리 중 복수 채널을 사용한다.

## 금지

- 핵심 성공률 또는 실패 결과 숨김
- 강화 결과 확정 전에 과도하게 긴 연출
- 실패 후 무엇이 바뀌었는지 찾기 위해 별도 로그를 열어야 함
- 보호 수단을 자동 체크해 플레이어 선택을 제거
- 화면 절반 이상을 보조 고객 정보가 점유
- 강화 버튼보다 정밀제작/고객 상세 CTA가 더 강하게 보임

## Visual QA 질문

- 첫눈에 강화가 이 게임의 주 행동으로 보이는가?
- `여기서 멈춤`도 강화 버튼만큼 명확한 선택으로 보이는가?
- 위험이 커질 때 시각적 긴장도도 증가하는가?
- 성공과 실패가 단순 초록/빨강 토스트보다 강한 상태 변화로 느껴지는가?
