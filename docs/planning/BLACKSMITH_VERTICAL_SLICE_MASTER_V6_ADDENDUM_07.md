## 저장 슬롯과 복구 정책

저장 구조는 **단일 활성 진행 + 시스템 복구 스냅샷**을 사용한다.

플레이어가 정상 플레이 중 임의의 과거 시점으로 돌아가기 위한 수동 저장 슬롯은 제공하지 않는다. 시스템 복구 스냅샷은 저장 손상, 버전 마이그레이션 실패 또는 상태 무결성 오류에 대응하기 위한 안전 장치이며, 강화 실패·영구 파괴·배팅 손실·세계 사건 결과를 되돌리는 기능이 아니다.

```text
플레이어 진행
→ 하나의 활성 캠페인 자동 저장

시스템 내부
→ 최근 정상 체크포인트를 순환 보관
→ 저장 손상·버전 오류·무결성 실패 때만 복구 후보로 사용
```

## 활성 진행 슬롯

- 정상 플레이에서 사용하는 진행 슬롯은 하나다.
- 모든 강화, 거래, 약속, 배팅, 세계 사건과 연대기는 같은 활성 캠페인에 누적된다.
- 플레이어가 강화 직전, 배팅 직전 또는 영업 종료 직전 상태를 별도 저장해 선택적으로 불러올 수 없다.
- 새 게임 또는 캠페인 초기화 기능이 필요하다면 기존 활성 진행을 명시적으로 폐기하는 별도 절차로 취급한다.
- 캠페인 초기화는 실수 방지를 위한 강한 확인이 필요하며, 복구 스냅샷을 일반적인 되돌리기 수단으로 노출하지 않는다.

## 시스템 복구 스냅샷

시스템은 최근 정상 상태를 내부적으로 순환 보관할 수 있다.

복구 스냅샷 생성 후보:

- 영업일 체크포인트 저장 완료 후
- 버전 마이그레이션 직전
- 대규모 세계 결과 묶음 적용 전후
- 저장 파일 구조 변경 직전
- 무결성 검사 통과 후 정상 상태로 확인된 시점

복구 스냅샷은 다음 조건을 만족해야 한다.

- 저장 완료 상태여야 한다.
- 장비·자원·소유권·약속·관계·연대기 사이의 무결성 검사를 통과해야 한다.
- 미완료 원자적 행동의 중간 상태를 포함하지 않아야 한다.
- 스냅샷 식별 시점과 게임 내 영업일을 기록해야 한다.
- 어떤 버전에서 생성됐는지 식별할 수 있어야 한다.

정확한 백업 개수, 보관 기간, 파일 위치, 압축과 암호화 방식은 구현 계획 단계에서 결정한다.

## 정상 플레이에서 금지되는 사용

시스템 복구 스냅샷은 다음 용도로 사용할 수 없다.

- 강화 실패·단계 하락·영구 파괴 취소
- 고위 정밀강화 후보 재선택
- 배팅 결과 재시도
- 고객 판매 선택 변경
- 약속 수락 또는 파기 철회
- 세계 사건 결과 재추첨
- 장비 분실·상속·파괴 결과 되돌리기
- 플레이어가 원하는 시점으로 자유롭게 시간 이동

정상 활성 저장이 유효하다면 복구 스냅샷 목록을 일반 로드 메뉴에 표시하지 않는다.

## 복구 진입 조건

복구 절차는 다음과 같은 오류가 감지될 때만 시작한다.

- 활성 저장을 읽을 수 없음
- 체크섬 또는 무결성 검사 실패
- 저장 버전 마이그레이션 실패
- 필수 장비·소유권·연대기 참조가 끊어짐
- 원자적 행동이 일부만 적용된 비정상 상태 감지
- 세계 결과가 중복 적용되었거나 필수 결과 일부가 누락된 상태 감지

단순한 플레이 결과 불만, 자금 부족, 장비 파괴 또는 약속 실패는 복구 조건이 아니다.

## 복구 화면 계약

복구가 필요하면 오류를 정상 진행처럼 숨기지 않고 별도 복구 화면을 표시한다.

복구 화면에는 다음 정보를 제공한다.

- 현재 활성 저장을 사용할 수 없는 이유
- 마지막 정상 복구 시점
- 해당 스냅샷의 게임 내 영업일
- 복구 시 예상되는 진행 손실 범위
- 복구 후 유지되는 주요 상태
- 복구 실행과 종료 선택

```text
저장 오류 감지
→ 활성 저장 사용 중단
→ 최근 정상 스냅샷 검증
├─ 정상 스냅샷 존재
│  → 시점·손실 범위 표시
│  → 플레이어 확인 후 활성 진행으로 복구
└─ 정상 스냅샷 없음
   → 오류 상태와 지원용 진단 정보 표시
   → 손상 상태를 정상 저장으로 덮어쓰지 않음
```

복구 시 예상 손실 범위를 정확히 계산할 수 없다면 `마지막 정상 체크포인트 이후 진행이 손실될 수 있음`을 명확히 표시한다.

## 복구 적용 원칙

- 선택한 정상 스냅샷 전체를 활성 진행으로 교체한다.
- 손상된 활성 저장과 정상 스냅샷을 임의로 부분 병합하지 않는다.
- 복구 완료 후 새 활성 저장을 원자적으로 확정한다.
- 복구 도중 앱이 종료돼도 손상 상태와 복구 상태가 혼합되지 않아야 한다.
- 복구 성공 후 해당 사실과 복구된 영업일을 기록한다.
- 복구 실패 시 기존 손상 파일을 정상 파일로 위장하거나 삭제하지 않는다.
- 동일 복구를 반복 실행해 자원·보상·장비가 중복 적용되지 않아야 한다.

## 버전 마이그레이션

게임 버전 업데이트로 저장 구조가 변경될 때는 다음 순서를 사용한다.

```text
기존 활성 저장 검증
→ 마이그레이션 전 복구 스냅샷 보관
→ 새 버전 구조로 변환
→ 변환 결과 무결성 검사
├─ 성공: 새 활성 저장 확정
└─ 실패: 기존 정상 스냅샷 보존, 오류 안내
```

- 마이그레이션 실패를 강화 실패나 세계 사건으로 처리하지 않는다.
- 변환 도중 소유권, 장비 계보, 약속, 구독, 관계와 연대기 참조가 끊어지지 않아야 한다.
- 지원되지 않는 구버전 저장의 처리 기준은 구현·운영 계획에서 결정한다.

## 검증 항목

- 활성 저장 손상 시 정상 복구 스냅샷이 탐지되는지 확인
- 정상 활성 저장에서는 복구 스냅샷을 일반 로드 메뉴에 노출하지 않는지 확인
- 강화 실패 또는 장비 파괴가 복구 조건으로 오인되지 않는지 확인
- 복구 전 마지막 정상 영업일과 예상 손실 범위가 표시되는지 확인
- 복구 도중 강제 종료 후 손상·정상 상태가 혼합되지 않는지 확인
- 복구 후 보상·관계·장비·연대기가 중복 적용되지 않는지 확인
- 버전 마이그레이션 실패 시 이전 정상 스냅샷이 보존되는지 확인
- 정상 스냅샷이 없을 때 손상 상태를 덮어쓰지 않고 오류를 명확히 표시하는지 확인

```text
PARTIAL_MERGE_OF_CORRUPT_AND_VALID_STATE: FORBIDDEN
EXACT_SNAPSHOT_COUNT_AND_RETENTION: IMPLEMENTATION_PLANNING_DECISION
```
