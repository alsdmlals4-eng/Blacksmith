## 1. 사용자 최신 결정

Blacksmith의 메인은 **강화**다.

정확히는 다음 두 요소가 1차 코어다.

1. 강화 직전의 긴장감과 `지금 멈출지 / 한 번 더 도전할지` 판단
2. 짧은 행동-피드백-보상 주기, 기대와 결과의 명료성, Micro→Session→Meta 사다리를 이용한 DDD(Digital Dopamine Design) 구조

정밀제작과 고객/작품 생애주기는 강화보다 높은 주 책임을 갖지 않는다.

## 2. 코어 계층

```text
PRIMARY CORE
강화 시도 전 긴장
→ 멈춤 / 추가 도전
→ 즉시 강화 결과·피드백
→ 다음 한 번에 대한 기대

SECONDARY AMPLIFIER
같은 작품 UID·생애
→ 강화 선택에 손실·기억·애착·역사를 부여

SUPPORT CONTENT A
정밀제작
→ 무엇을 강화할지 / 어떤 성장 방향을 노릴지 다양화

SUPPORT CONTENT B
고객·세계 생애주기
→ 강화된 작품을 사용시켜 결과를 돌려주고 다음 강화 이유를 생성

META SUPPORT
경제·하루 작업량·명성·관계
→ 강화 선택의 비용·기회비용을 만들되 메인 루프를 대체하지 않음
```

## 3. 보호 계약

### INVARIANT

- 강화가 플레이 시간과 의사결정의 중심이다.
- 강화 버튼/행동 이전에 성공 기대와 실패 위험이 이해 가능해야 한다.
- 핵심 선택은 `현재 가치를 확보하고 멈춤` 대 `추가 보상을 위해 위험 감수`다.
- 강화 결과는 짧은 지연 안에 강하고 명료한 피드백을 준다.
- 실패도 다음 시도를 납득시키는 정보·상태·복구 경로를 남긴다.
- DDD는 무조건적인 자극량 증가가 아니라 행동→기대→피드백→보상→다음 질문의 밀도와 명료성을 관리한다.

### CORE SUPPORT / CHANGEABLE

- 작품 UID와 생애는 강화 결과의 무게를 증폭한다. 생애 자체가 강화보다 상위 메인 루프가 되지 않는다.
- 정밀제작은 강화 후보와 성장 방향을 만든다. 복잡한 제작 툴 자체가 게임의 주인공이 되지 않는다.
- 고객 콘텐츠는 강화 결과를 검증하고 기억시키며 다음 강화 이유를 만든다. 고객 관리/RPG/전투 게임으로 확장하지 않는다.
- 5등급, 예술성, 세 수식어, 고객 4능력치, 정확한 정밀강화 이정표, D01~D09 고객 콘텐츠는 현재 정본이지만 코어 불변값은 아니다. 강화 재미를 약화하면 축소·재설계할 수 있다.

## 4. DDD 적용 계약

Blacksmith에서 DDD는 다음 순서로 평가한다.

```text
PLAYER ACTION
강화 시도 준비 / 보호 수단 선택 / 멈춤 또는 도전

EXPECTATION
현재 성공 가능성·비용·실패 결과·다음 이정표를 이해

IMMEDIATE FEEDBACK
망치/불꽃/소리/VFX/수치 변화/성공·실패 상태

REWARD OR LOSS
강화 상승 / 유지 / 손상 / 기회 상실 / 회복 자원 / 특별 진전

NEXT QUESTION
멈출까? 다시 시도할까? 보호할까? 정밀강화할까? 다른 작품으로 갈까?

META MEMORY
같은 UID 작품·고객/세계 결과가 이전 강화 선택을 다시 상기
```

### DDD 안전선

- 긴장감을 만들기 위해 결과 정보를 불공정하게 숨기지 않는다.
- 실패만 반복되는 무보상 구간을 길게 두지 않는다.
- 실패가 전부 무효화되는 구조를 기본값으로 두지 않는다.
- 고가치 작품의 완전 파괴는 일반 실패와 분리한 명시적 고위험 선택 후보로만 검토한다.
- 재화 소모량·확률·연출만 키워 재미를 만든다고 간주하지 않는다.
- 반복 클릭 수 증가를 보상 밀도 증가로 오인하지 않는다.

## 5. 다른 시스템의 존재 이유

| 시스템 | 강화 코어에 기여해야 하는 질문 |
|---|---|
| 정밀제작 | 어떤 작품/성장 방향이면 이번 강화 도전의 의미가 달라지는가? |
| 재료 | 이번 작품의 강화 가치·목표·기회비용을 어떻게 바꾸는가? |
| 제작 등급 | 이 작품을 더 밀어붙이고 싶은 욕구를 만드는가? |
| 촉매/정밀강화 | 단순 +숫자가 아닌 다음 이정표의 선택을 만드는가? |
| UID/생애 | 지금 실패하거나 멈추는 선택이 왜 기억에 남는가? |
| 고객 | 강화 결과가 실제로 어디에서 가치/실패로 드러나는가? |
| 세계 결과 | 과거 강화 선택을 어떻게 다시 상기시키는가? |
| 경제 | 계속 도전할 수 있지만 무조건 도전하는 것이 정답이 아니게 만드는가? |
| 하루 작업량 | 강화·제작·복원 사이 기회비용을 만드는가? |

위 질문에 답하지 못하는 기능은 `SUPPORT_ONLY`, `DEFER`, `REMOVE_CANDIDATE`로 재검토한다.

## 6. 첫 세션 목표 재정렬

첫 세션의 대표 경험은 작품 생애 전체를 먼저 보여주는 것이 아니라 **강화 긴장감을 가능한 빨리 증명**해야 한다.

```text
짧은 의뢰/목표 제시
→ 기본 작품 확보
→ 첫 안전 강화로 규칙 학습
→ 보상 상승 체감
→ 첫 의미 있는 위험 강화
→ 멈춤/도전 선택
→ 즉시 결과
→ 작품 UID에 결과 흔적
→ 짧은 고객/세계 피드백
→ 다음 강화 질문 생성
```

첫 작품의 세계 결과·재방문은 강화 선택의 의미를 증명하는 후속 payoff다.

## 7. 벤치마크 해석

- 확률형 강화 사례에서 채택할 것은 `높은 단계일수록 보상과 위험이 동시에 커지는 명료한 긴장`, `파괴/손실 완화 수단`, `실패 누적의 회복 장치` 같은 원리다.
- 장기 MMO의 과도한 재료 소모·막힘·실패 피로는 그대로 복제하지 않는다.
- Blacksmith는 싱글플레이 제작 게임이므로 실패 후 다시 시도하고 싶게 만드는 짧은 회복 루프와 작품 애착 보호가 더 중요하다.

## 8. 재검토 조건

다음 중 하나가 실제 플레이에서 관찰되면 코어 세부를 재검토한다.

- 플레이어가 강화 전 멈춤/도전을 고민하지 않고 항상 같은 선택을 한다.
- 강화 성공/실패 뒤 다음 행동이 즉시 떠오르지 않는다.
- 실패가 긴장보다 피로·허탈만 만든다.
- 작품 UID/고객 결과가 강화 판단을 바꾸지 못한다.
- 정밀제작/고객 콘텐츠가 강화보다 더 많은 시간과 인지부하를 차지한다.
- 반복 강화가 단순 클릭 작업으로 느껴진다.

## 9. 현재 증거 경계

- 기존 MVP-003과 P2는 기술적 기반·역사 증거로 재사용한다.
- Human usability / Player experience: `NOT_RUN`.
- 정확 확률·비용·손상·보호·보상 수치는 새 Balance Budget과 플레이테스트 전 `TUNABLE / NOT_FINAL`이다.
- 이 Decision은 기획 계층을 재정렬할 뿐 Godot 제품 코드를 변경하지 않는다.
