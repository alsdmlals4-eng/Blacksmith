이번 벤치마크는 현재 구조를 재설계하지 않는다.

| 영역 | 최신 규칙 | 상태 |
|---|---|---|
| 코어 루프 | 제작 → 반복 강화 → 계속/판매 판단 → 재투자 | `CONFIRMED` |
| 고객 | 자율적 생애주기·조언·재방문·장비 이력 | `CONFIRMED` |
| 판매 | 공개시장 즉시 고정 매입, 특별 거래만 흥정 | `CONFIRMED` |
| 정밀강화 | 정밀 등급 1개 + 수식어 2개 | `CONFIRMED` |
| 정밀 실패 | 투입 재료만 손실, 장비 상태 유지, 이정표 종료 | `CONFIRMED` |
| 한계 돌파 | 강화 메인 포인트를 쓰는 고강화 메인 빌드 | `CONFIRMED` |
| POC 목표 | 강화·생애주기·세계 시스템을 대표 경로로 체험 | `CONFIRMED` |

## 3. 신규 제안

아래 항목은 사용자 승인 전까지 모두 `PROPOSED_ONLY`다.

### P1. POC 시나리오 런처와 체험 패스

- 상태: `PROPOSED_ONLY / HIGH_PRIORITY`
- POC·QA 전용
- 결정적 seed, 재료 프리셋, 대표 결과 경로 제공
- 파괴·보호·회복·고위 정밀강화·재방문·국가·밀수·전시·수집가를 개별 재현
- 출시 일반 플레이 메뉴에 그대로 노출하지 않음

### P2. 장비 연대기 요약 카드

- 상태: `PROPOSED_ONLY / HIGH_PRIORITY`
- 제작·정밀강화·실패·손상·복구·소유·활동·판매·전시 이력을 한 화면에 표시
- POC 외부 테스트의 장비 기억률 측정과 연결

### P3. 위험·결과 사전 카드

- 상태: `PROPOSED_ONLY / HIGH_PRIORITY`
- 최악 결과, 보호석 변화, 세계 수치 방향, 판정 시점 표시
- 숨은 정확 확률은 공개하지 않음

### P4. 오늘의 대장간 목표

- 상태: `PROPOSED_ONLY / MEDIUM_PRIORITY`
- 하루에 선택 목표 1개
- 미선택·실패 불이익 없음
- 작은 명성·기록·도감 진척 중심
- 일일 숙제와 메인 경제 대체 금지

### P5. 숙련 후 저위험 연속 강화

- 상태: `PROPOSED_ONLY / POST_POC`
- 수동 체험 완료 구간에서만 해금
- 개별 판정·재료·기록 유지
- 실패·위험 진입·10강 이정표에서 자동 정지
- 고위험과 정밀강화는 수동 유지

### P6. 기존 특수 타격 충전의 최악 상한화

- 상태: `PROPOSED_ONLY / POST_POC`
- 새 실패 게이지 추가 금지
- 기존 강화 기여도·특수 타격 구조에 실패 기여 통합
- 긴 실패 뒤 파괴 방지·하락 제한·재료 절약 중 하나의 강한 안전 행동 후보

### P7. 등록 조합 선택권 강화

- 상태: `PROPOSED_ONLY / POST_POC`
- 등록 조합은 수식어 정체성과 계보 확정
- 변동성은 성공 여부와 세부 강도에 유지
- 미등록 조합은 후보 계열·호환도·불가능 결과 사전 표시

### P8. 경제 목표와 비용 우선순위 안내

- 상태: `PROPOSED_ONLY / POST_POC`
- 다음 한계 돌파·시설·회복·재료 비용의 동시 압박 완화
- `다음 의미 있는 투자`와 부족량 표시
- 자동 추천은 참고 정보이며 결정을 대신하지 않음

## 4. 우선 검토 묶음

권장 승인 묶음:

```text
POC 시나리오 런처
+ 장비 연대기 요약 카드
+ 위험·결과 사전 카드
+ 오늘의 대장간 목표
```

이 묶음은 새 장기 경제나 성장축을 추가하지 않는다. 기존 기획을 POC에서 이해·재현·검증하기 위한 표현 계층이다.

P5~P8은 실제 POC의 반복 피로, 실패 감정, 수식어 폐기율, 경제 혼란 지표를 확인한 후 결정한다.

## 5. 벤치마크 해석 원칙

- 타 게임의 시스템을 이름만 바꾸어 복제하지 않는다.
- 경쟁작이 복잡한 생산망을 제공한다는 이유로 현재 코어를 확장하지 않는다.
- 보장 시스템은 실패 비용과 시장가의 관계를 함께 검증한다.
- 자동화는 플레이어가 이미 이해한 저위험 반복에만 적용한다.
- 관계 콘텐츠는 가격 보너스보다 기록·재방문·세계 반응을 우선한다.
- POC에 들어가는 기능은 외부 플레이어가 실제로 접할 수 있어야 한다.
