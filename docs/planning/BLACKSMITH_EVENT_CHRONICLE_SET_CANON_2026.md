## 1. 사용자 승인 근거

- `권장안대로 진행`
- `[일대기](세계일정)을 세우면 그 아이템을 사건과 연관지어서 [세트]로 만들자.`
- `해당 사건 연대기를 가진 물품들이 세트인거야`

## 2. 핵심 정의

세트는 미리 정해진 동일 외형 장비를 모아 완성하는 수집 묶음이 아니다.

**같은 세계 사건에 실제로 납품·배치·사용되어 동일한 사건 연대기를 공유하게 된 고유 작품들이 그 사건의 세트가 된다.**

```text
세계 일정 공개
→ 사건이 요구하는 역할 확인
→ 플레이어가 고유 작품을 제작·강화
→ 예정 작품을 고객·집단에 납품
→ 사건 진행·결과 확정
→ 실제 기여 작품에 동일 사건 연대기 ID 기록
→ 해당 작품들이 연대기 세트로 성립
→ 세트 결과·별칭·후속 사건·복원 의뢰 생성
```

## 3. 용어 구분

혼선을 막기 위해 시간 상태에 따라 용어를 구분한다.

- **세계 일정 (`World Schedule`)**: 아직 발생하지 않았거나 진행 중인 미래 사건과 마감 정보.
- **예정 세트 (`Planned Set`)**: 세계 일정에 대응하기 위해 플레이어가 준비·배정한 작품 후보 묶음. 아직 역사적 세트로 확정되지 않는다.
- **사건 연대기 (`Event Chronicle`)**: 사건 종료 후 결과, 참여자, 기여 작품, 선택과 후속 영향을 보존하는 기록.
- **연대기 세트 (`Chronicle Set`)**: 동일한 사건 연대기 ID를 공유하는 실제 기여 작품들의 묶음.

표현상 사용자가 말한 `[일대기](세계일정)`의 의도는 유지하되, 데이터와 기획 문서에서는 `세계 일정 → 사건 연대기`의 전후 상태를 구분한다.

## 4. 혼합형 세트 생성 계약

권장 혼합형 `C`를 다음과 같이 확정한다.

1. 게임은 세계 사건의 주제, 일정, 고객·집단, 요구 역할을 제시한다.
2. 게임이 특정 고정 아이템 ID를 요구하지는 않는다.
3. 플레이어는 자신이 만든 고유 작품 중 어떤 작품을 준비·강화·납품할지 선택한다.
4. 사건 종료 후 실제 기여한 작품만 동일한 사건 연대기 ID를 부여받는다.
5. 동일 사건 연대기 ID를 가진 작품들은 자동으로 하나의 연대기 세트가 된다.
6. 세트 정체성과 별칭은 사건명, 결과, 인물, 지역, 작품의 특징에서 파생한다.
7. 각 구성품의 UID, 제작 등급, 강화 경로, 수식어, 소유자, 운명과 개별 연대기는 그대로 유지한다.

예시:

```text
세계 일정: 잿빛 협곡 원정
요구 역할: 주력 무기 / 생존 방어구 / 길잡이 장신구
플레이어 선택: 유성철 장검 + 흑철 흉갑 + 북극성 부적
사건 결과: 폭설 속 원정대 생환
사건 연대기 ID: EVENT_ASHEN_GORGE_001
연대기 세트 별칭: 잿빛 협곡의 생환자들
```

세 작품은 외형·재료·등급이 달라도 같은 사건을 함께 통과했기 때문에 하나의 세트다.

## 5. 세트 성립 규칙

### 5.1 예정과 확정

- 사건 전 작품을 배정하면 `예정 세트 후보`로 표시한다.
- 단순히 후보로 등록한 작품은 아직 연대기 세트가 아니다.
- 사건 결과 계산에 실제로 사용되었거나 공식 납품된 작품만 기여 기록을 받는다.
- 사건이 취소되거나 작품이 납품되지 않았다면 확정 세트에 포함하지 않는다.

### 5.2 최소 구성

- 연대기 세트는 원칙적으로 서로 다른 UID를 가진 작품 2점 이상으로 성립한다.
- 단일 작품도 사건 연대기는 가질 수 있지만 `단일 대표작`으로 분류하며 세트로 부르지 않는다.
- 정확한 최소·최대 구성 수는 `RECOMMENDED_DEFAULT / TEST_VALUE`다.

### 5.3 작품 역할

- 세계 사건은 `무기 1개` 같은 단순 분류뿐 아니라 `돌파`, `방호`, `생존`, `상징`, `정찰`, `의식`처럼 역할을 제시할 수 있다.
- 어떤 작품군으로 역할을 해결할지는 플레이어가 선택한다.
- 예를 들어 방패와 중갑 모두 `방호` 역할을 수행할 수 있지만 결과 장면과 후속 연대기는 달라질 수 있다.

### 5.4 다중 연대기

- 한 작품은 생애 동안 여러 사건에 참여하여 여러 사건 연대기를 누적할 수 있다.
- 따라서 한 작품이 여러 연대기 세트에 역사적으로 소속되는 것을 허용한다.
- 단, 서로 다른 사건 세트의 수치 효과를 무제한 중첩하지 않는다.
- 현재 사건에서 활성화되는 맥락형 효과와 UI의 대표 연대기 표시는 R4~R6에서 상세화한다.

## 6. 세트 효과의 방향

연대기 세트의 가치는 단순한 상시 공격력 합산보다 **공유한 사건의 의미와 후속 가능성**에서 발생해야 한다.

우선 효과:

- 해당 사건과 연결된 후속 의뢰·재대결·추모·복원 선택지 해금
- 구성품을 사용한 고객·집단의 관계와 명성 변화
- 사건 유형과 유사한 미래 일정에서 추가 정보 또는 선택지 제공
- 세트 전용 결과 장면·별칭·전시 설명·연대기 페이지
- 분실·파괴된 구성품의 회수, 복원, 대체품 제작 의뢰
- 세트가 다른 소유자에게 흩어졌을 때 재결합·계승·갈등 사건 생성

보조 효과:

- 사건 맥락에서 설명 가능한 적합도·위험 완화·보상 보정
- 정확한 수치, 중첩 규칙, 활성 조건은 `RECOMMENDED_DEFAULT / TEST_VALUE`

## 7. 다양한 작품을 만들 이유와의 연결

사건 연대기 세트는 여러 종류의 작품 제작 동기를 직접 만든다.

- 세계 일정마다 요구 역할이 달라 가장 강한 한 종류의 무기만으로 모든 문제를 해결할 수 없다.
- 다른 작품군은 결과에 서로 다른 방식으로 기여한다.
- 부분 준비로 사건에 참여할 수 있지만, 부족한 역할은 위험·결과·후속 의뢰에 남는다.
- 완벽한 세트만 정답이 되지 않으며, 플레이어의 선택과 보유 작품에 따라 서로 다른 사건 연대기가 생성된다.
- 동일 사건도 다른 플레이에서는 다른 작품들이 세트가 되어 다른 역사를 만든다.

## 8. 작품과 세트의 생애

```text
개별 제작·강화
→ 세계 일정에 배정
→ 납품·사건 참여
→ 사건 연대기 획득
→ 연대기 세트 성립
→ 소유자 이전·분실·파괴·복원
→ 세트 활성 상태 변화
→ 후속 사건에서 재사용 또는 새로운 연대기 추가
```

- 구성품이 파괴되거나 분실되어도 과거 세트 기록은 삭제하지 않는다.
- 대체 작품은 원래 구성품의 UID를 덮어쓰지 않는다.
- 대체 작품이 후속 사건을 통해 세트에 합류하면 `후계 구성품`으로 별도 기록한다.
- 세트의 현재 완전성, 역사적 완성 여부, 현재 소유 분산 상태를 구분한다.

## 10. 적대적 보호 조건

- 사건에 실제 기여하지 않은 작품을 등록만 했다는 이유로 세트에 포함하면 안 된다.
- 모든 사건이 세트 제작을 강제해 단품 대표작과 자유 판매를 무가치하게 만들면 안 된다.
- 세트 효과가 개별 작품의 제작 품질과 강화 판단을 압도하면 안 된다.
- 같은 사건 이름을 반복 파밍해 동일 세트 보너스를 무한 중첩하면 안 된다.
- 사건 RNG가 작품 구성과 역할 선택보다 결과를 더 크게 좌우하면 안 된다.
- 과거 구성품이 분실·파괴되었다는 이유로 사건 기록을 삭제하면 안 된다.
- 연대기 세트가 단순 아이템 태그 묶음으로 축소되어 고객·사건·결과 장면과 분리되면 안 된다.
- 모든 장비를 모든 사건에 등록하여 연대기만 대량 부여하는 전략이 최적이 되면 안 된다.
- 세트명과 연대기는 결과와 무관한 무작위 수식어가 아니라 실제 사건 근거를 가져야 한다.

## 11. 후속 검증

- R2: 세계 일정 준비와 강화·피로도 배분이 일일 루프에서 경쟁하는 방식
- R3: 장비 UID·사건 연대기·다중 세트 참조·저장·마이그레이션 계약
- R4: 일정 생성, 고객 납품, 사건 해결, 연대기 생성, 후속 사건 파이프라인
- R5: 세트 프리미엄과 사건 보상, 반복 파밍·중첩·최적해 반증
- R6: 예정 세트, 기여 작품, 사건 연대기, 현재/과거 세트 상태의 모바일 정보 위계
- R7: 첫 세계 일정 준비부터 연대기 세트 성립까지의 사람 이해도 검증

현재 구현·런타임·Android·사람 플레이 검증은 `NOT_RUN`이다.
