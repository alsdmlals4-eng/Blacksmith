## 2. 핵심 정의

세트는 미리 정해진 동일 외형 장비를 모아 완성하는 수집 묶음이 아니다.

**같은 세계 사건에 실제로 납품·배치·사용되어 동일한 사건 연대기를 공유하게 된 고유 작품들이 그 사건의 세트가 된다.**

```text
세계 일정 공개
→ 사건이 요구하는 역할 확인
→ 플레이어가 고유 작품을 제작·강화
→ 예정 작품을 고객·집단에 납품
→ 사건 진행·결과 확정
→ 실제 기여 작품에 동일 사건 연대기 ID 기록
→ 해당 작품들이 연대기 세트로 성립
→ 범용 보정·상황 태그·역사 기록 획득
→ 유사 상황의 선택지·전용 장면·후속 의뢰로 환류
```

## 3. 용어 구분

혼선을 막기 위해 시간 상태에 따라 용어를 구분한다.

- **세계 일정 (`World Schedule`)**: 아직 발생하지 않았거나 진행 중인 미래 사건과 마감 정보.
- **예정 세트 (`Planned Set`)**: 세계 일정에 대응하기 위해 플레이어가 준비·배정한 작품 후보 묶음. 아직 역사적 세트로 확정되지 않는다.
- **사건 연대기 (`Event Chronicle`)**: 사건 종료 후 결과, 참여자, 기여 작품, 선택과 후속 영향을 보존하는 기록.
- **연대기 세트 (`Chronicle Set`)**: 동일한 사건 연대기 ID를 공유하는 실제 기여 작품들의 묶음.
- **상황 태그 (`Situation Tag`)**: 서로 다른 사건 사이의 유사성을 판정하기 위한 환경·위협·임무·제약·전술 맥락.
- **연대기 보정 (`Chronicle Modifier`)**: 연대기 세트 성립으로 구성품에 부여되는 작고 범용적인 능력 보정.

표현상 사용자가 말한 `[일대기](세계일정)`의 의도는 유지하되, 데이터와 기획 문서에서는 `세계 일정 → 사건 연대기`의 전후 상태를 구분한다.

## 4. 혼합형 세트 생성 계약

권장 혼합형 `C`를 다음과 같이 확정한다.

1. 게임은 세계 사건의 주제, 일정, 고객·집단, 요구 역할을 제시한다.
2. 게임이 특정 고정 아이템 ID를 요구하지는 않는다.
3. 플레이어는 자신이 만든 고유 작품 중 어떤 작품을 준비·강화·납품할지 선택한다.
4. 사건 종료 후 실제 기여한 작품만 동일한 사건 연대기 ID를 부여받는다.
5. 동일 사건 연대기 ID를 가진 작품들은 자동으로 하나의 연대기 세트가 된다.
6. 세트 정체성과 별칭은 사건명, 결과, 인물, 지역, 작품의 특징에서 파생한다.
7. 각 구성품의 UID, 제작 등급, 강화 경로, 수식어, 소유자, 운명과 개별 연대기는 그대로 유지한다.
8. 동일한 세계 일정의 재등장을 전제로 하지 않는다. 세트의 미래 활용은 상황 태그가 유사한 새 사건에서 발생한다.

예시:

```text
세계 일정: 잿빛 협곡 원정
요구 역할: 주력 무기 / 생존 방어구 / 길잡이 장신구
플레이어 선택: 유성철 장검 + 흑철 흉갑 + 북극성 부적
사건 결과: 폭설 속 원정대 생환
사건 연대기 ID: EVENT_ASHEN_GORGE_001
상황 태그: [원정] [혹한] [산악] [고립] [생환]
연대기 세트 별칭: 잿빛 협곡의 생환자들
```

세 작품은 외형·재료·등급이 달라도 같은 사건을 함께 통과했기 때문에 하나의 세트다.

## 5. 세트 성립 규칙

### 5.1 예정과 확정

- 사건 전 작품을 배정하면 `예정 세트 후보`로 표시한다.
- 단순히 후보로 등록한 작품은 아직 연대기 세트가 아니다.
- 사건 결과 계산에 실제로 사용되었거나 공식 납품된 작품만 기여 기록을 받는다.
- 사건이 취소되거나 작품이 납품되지 않았다면 확정 세트에 포함하지 않는다.

### 5.2 최소 구성

- 연대기 세트는 원칙적으로 서로 다른 UID를 가진 작품 2점 이상으로 성립한다.
- 단일 작품도 사건 연대기는 가질 수 있지만 `단일 대표작`으로 분류하며 세트로 부르지 않는다.
- 정확한 최소·최대 구성 수는 `RECOMMENDED_DEFAULT / TEST_VALUE`다.

### 5.3 작품 역할

- 세계 사건은 `무기 1개` 같은 단순 분류뿐 아니라 `돌파`, `방호`, `생존`, `상징`, `정찰`, `의식`처럼 역할을 제시할 수 있다.
- 어떤 작품군으로 역할을 해결할지는 플레이어가 선택한다.
- 예를 들어 방패와 중갑 모두 `방호` 역할을 수행할 수 있지만 결과 장면과 후속 연대기는 달라질 수 있다.

### 5.4 다중 연대기

- 한 작품은 생애 동안 여러 사건에 참여하여 여러 사건 연대기를 누적할 수 있다.
- 따라서 한 작품이 여러 연대기 세트에 역사적으로 소속되는 것을 허용한다.
- 단, 서로 다른 사건에서 얻은 범용 보정과 상황 효과를 무제한 중첩하지 않는다.
- 대표 연대기 선택, 보정 상한, 중첩 우선순위는 R3~R6에서 상세화한다.

## 6. 세트 보상 3층 구조

연대기 세트는 다음 세 보상을 동시에 가진다.

### 6.1 1층 — 범용 능력치 보정

- 세트 성립에 실제 기여한 각 구성품은 작고 영구적인 `연대기 보정`을 얻는다.
- 보정은 모든 상황에서 적용되며 같은 사건의 재등장을 요구하지 않는다.
- 보정 종류는 작품 역할에 맞게 변환할 수 있다.
  - 무기: 공격·관통·명중·내구 등
  - 방어구: 방어·저항·내구·생존 등
  - 장신구·도구: 적합도·지원·조건 대응·보상 보정 등
- 정확한 스탯 종류, 수치와 성장식은 `RECOMMENDED_DEFAULT / TEST_VALUE`다.
- 범용 보정은 개별 작품의 재료·제작 품질·강화 단계·수식어보다 작은 보조 성장이어야 한다.
- 연대기 수가 많다는 이유만으로 오래된 작품이 무조건 최강이 되지 않도록 누적 상한 또는 점감 규칙을 둔다.

### 6.2 2층 — 상황 태그 기반 서사·선택 보상

동일한 사건은 다시 발생하지 않으므로, 과거 사건과 현재 사건의 `상황 태그 유사도`로 활용 가능성을 판단한다.

권장 태그 축:

- **환경:** 산악, 사막, 설원, 해상, 지하, 도시, 폐허
- **위협:** 괴수, 군대, 도적, 재해, 저주, 질병, 포위
- **임무:** 원정, 호위, 방어, 구조, 추적, 결투, 의식
- **제약:** 혹한, 폭염, 고립, 시간 제한, 보급 부족, 시야 제한
- **전술·해결:** 돌파, 잠입, 장기전, 생환, 희생, 협상, 유인
- **사회 맥락:** 왕실, 길드, 군대, 마을, 종교, 검투장, 상단

새 세계 일정이 과거 연대기와 충분히 유사하면 다음 효과 중 일부가 열린다.

- 위험이나 숨은 조건을 미리 알려주는 추가 정보
- 기존 선택지를 대체하지 않는 추가 선택지
- 과거 경험을 반영한 전용 결과 장면 또는 대사
- 특정 실패 위험 완화, 준비 비용 절감 또는 역할 적합도 보정
- 과거 참여자·소유자·지역과 연결된 관계 반응
- 복원·재사용·계승·재결합 같은 후속 의뢰

태그가 하나 일치했다는 이유만으로 강한 효과가 발동하면 안 된다. 핵심 태그와 보조 태그, 일치 개수, 작품의 실제 기여 역할을 함께 판정하는 방식을 우선한다. 정확한 유사도 기준은 `RECOMMENDED_DEFAULT / TEST_VALUE`다.

예시:

```text
과거 연대기: 잿빛 협곡 원정
태그: [원정] [혹한] [산악] [고립] [생환]

새 세계 일정: 북부 봉쇄선 구조 작전
태그: [구조] [혹한] [산악] [보급 부족] [생환]

공통 맥락:
- 혹한
- 산악
- 생환

가능한 효과:
- 눈사태 위험 사전 정보
- 우회로 확보 선택지
- 잿빛 협곡 생환 경험을 언급하는 전용 장면
```

### 6.3 3층 — 역사 기록·확인

연대기 세트는 능력치 묶음인 동시에 작품의 역사 기록이다.

기본 화면에서는 다음을 짧게 확인한다.

```text
잿빛 협곡의 생환자들
제12일, 잿빛 협곡 원정에서 원정대를 생환시킨 세 작품.
유성철 장검은 돌파, 흑철 흉갑은 방호, 북극성 부적은 길잡이에 기여했다.
```

확장 화면에서는 다음 정보를 제공한다.

- 사건명·발생 날짜·지역
- 의뢰인·참여자·당시 소유자
- 사건의 목적과 핵심 위기
- 각 작품의 기여 역할
- 플레이어가 선택한 준비와 결과
- 성공·실패·손실·생환 등 결말
- 사건 이후 작품의 소유·분실·파괴·복원·계승
- 파생된 후속 의뢰와 추가 연대기

기본 요약은 강화 흐름을 끊지 않을 만큼 짧게 유지하며, 상세 기록은 플레이어가 원할 때 펼쳐본다.

## 7. 다양한 작품을 만들 이유와의 연결

사건 연대기 세트는 여러 종류의 작품 제작 동기를 직접 만든다.

- 세계 일정마다 요구 역할이 달라 가장 강한 한 종류의 무기만으로 모든 문제를 해결할 수 없다.
- 다른 작품군은 결과에 서로 다른 방식으로 기여한다.
- 부분 준비로 사건에 참여할 수 있지만, 부족한 역할은 위험·결과·후속 의뢰에 남는다.
- 완벽한 세트만 정답이 되지 않으며, 플레이어의 선택과 보유 작품에 따라 서로 다른 사건 연대기가 생성된다.
- 세계 일정은 고유 사건이지만 상황 태그는 다른 사건으로 이어져 과거 작품을 다시 활용할 이유를 만든다.
- 범용 보정은 작품의 지속 가치를 만들고, 태그 효과는 특정 작품만 반복 사용하는 최적해를 완화한다.

## 8. 작품과 세트의 생애

```text
개별 제작·강화
→ 세계 일정에 배정
→ 납품·사건 참여
→ 사건 연대기 획득
→ 연대기 세트 성립
→ 범용 보정·상황 태그·역사 요약 획득
→ 소유자 이전·분실·파괴·복원
→ 유사 상황에서 추가 선택·전용 장면 발생
→ 새로운 사건 연대기 추가
```

- 구성품이 파괴되거나 분실되어도 과거 세트 기록은 삭제하지 않는다.
- 대체 작품은 원래 구성품의 UID를 덮어쓰지 않는다.
- 대체 작품이 후속 사건을 통해 세트에 합류하면 `후계 구성품`으로 별도 기록한다.
- 세트의 현재 완전성, 역사적 완성 여부, 현재 소유 분산 상태를 구분한다.
- 현재 구성품이 함께 있지 않아도 역사 기록은 유지한다. 단, 함께 사용해야 하는 효과가 후속 설계에서 추가될 경우 현재 소유·배치 상태를 검사한다.

## 10. 적대적 보호 조건

- 사건에 실제 기여하지 않은 작품을 등록만 했다는 이유로 세트에 포함하면 안 된다.
- 모든 사건이 세트 제작을 강제해 단품 대표작과 자유 판매를 무가치하게 만들면 안 된다.
- 범용 보정이 개별 작품의 제작 품질과 강화 판단을 압도하면 안 된다.
- 연대기 누적만으로 오래된 작품이 신규 걸작보다 항상 강해지면 안 된다.
- 동일한 세계 일정이 반복된다는 전제에 의존하는 효과를 만들면 안 된다.
- 상황 태그 하나만 억지로 맞춰 모든 사건에서 추가 선택지를 여는 전략이 최적이 되면 안 된다.
- 상황 태그가 지나치게 세분화되어 플레이어가 효과 발동 이유를 이해하지 못하면 안 된다.
- 사건 RNG가 작품 구성과 역할 선택보다 결과를 더 크게 좌우하면 안 된다.
- 과거 구성품이 분실·파괴되었다는 이유로 사건 기록을 삭제하면 안 된다.
- 연대기 세트가 단순 아이템 태그 묶음으로 축소되어 고객·사건·결과 장면과 분리되면 안 된다.
- 모든 장비를 모든 사건에 등록하여 연대기와 범용 보정만 대량 부여하는 전략이 최적이 되면 안 된다.
- 세트명과 연대기는 결과와 무관한 무작위 수식어가 아니라 실제 사건 근거를 가져야 한다.
- 연대기 설명이 너무 길어 강화 중심 플레이 흐름을 반복적으로 중단하면 안 된다.

## 11. 후속 검증

- R2: 세계 일정 준비와 강화·피로도 배분이 일일 루프에서 경쟁하는 방식
- R3: 장비 UID·연대기 보정·상황 태그·다중 세트 참조·저장·마이그레이션 계약
- R4: 일정 생성, 고객 납품, 사건 해결, 연대기 생성, 태그 유사도, 추가 선택지·전용 장면 파이프라인
- R5: 범용 보정 수치, 누적 상한, 태그 발동 가치, 반복 파밍·최적해 반증
- R6: 예정 세트, 기여 작품, 범용 보정, 상황 태그, 3줄 역사 요약과 상세 기록의 모바일 정보 위계
- R7: 첫 세계 일정 준비부터 연대기 세트 성립, 보상 이해, 유사 상황 재활용까지의 사람 이해도 검증
