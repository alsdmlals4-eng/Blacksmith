## 3. 근본 원인 분석

### RC-01 — 병합 SHA를 현재 상태 필드로 직접 보관하는 자기참조

PR #104는 사후 폐쇄 상태를 정상 병합했지만, 병합 전 문서가 `closure PR #104 pending`과 PR #103 병합 SHA를 `current_main`으로 보관했다. PR #104가 병합되면 main은 다시 움직이므로 문서가 즉시 오래된 상태가 된다.

조치:

- Registry에서 변동하는 `current_main`을 권위 판정 기준으로 사용하지 않는다.
- 불변 증거인 `checkpoint_merge_sha`, `closure_merge_sha`, `readback_status`를 분리한다.
- 현재 브랜치 HEAD는 GitHub readback으로 확인하고 문서가 자기 자신의 미래 병합 SHA를 예측하지 않는다.

### RC-02 — R1 통합 문서와 R2 세부 정본의 supersession 전파 누락

R2에서 세 수식어·보조재료 제거·개인 일정과 세계 일정 분리를 승인했지만 Game Bible·Roadmap·Development Gates·R1 Registry 일부에는 다음 구형 규칙이 남았다.

- PR #81의 5단계 제작 등급을 현재 구조처럼 읽을 가능성

조치:

- 상위 진입 문서는 최신 R2 구조로 갱신한다.
- 역사 문서는 상태 배너와 대체 문서를 직접 표시한다.

PR #81은 이미 `REFERENCE_ASSET / DO_NOT_MERGE_AS_UNIT` 판정을 받았지만 여전히 열린 Draft이며 제목만 보면 최신 기획 PR처럼 보인다. 181개 커밋·88개 파일 안에 승인 원문, 제안, 구현 계획, 현재와 충돌하는 규칙이 섞여 있다.

조치:

- PR 제목·설명 첫 줄에 `[REFERENCE ONLY · DO NOT MERGE]`를 표시한다.
- 전체 병합은 `[폐기]`, 브랜치와 원문은 `[역사 증거]`로 보존한다.

## 5. 핵심 재미 정합성 판정

### 유지되는 강점

- **즉각 재미:** 강화 성공·실패와 멈춤·추가 도전 판단이 짧은 주기로 반복된다.
- **작품 정체성:** 등급·촉매·연대기 세 축이 출생, 제작자 선택, 실제 생애를 서로 다른 원인으로 설명한다.
- **장기 의미:** 고객과 세계에 보낸 동일 UID 작품이 결과와 다음 제작 이유를 돌려준다.
- **모바일 적합성:** 일반 강화는 한 입력 한 결과이고 정밀강화만 고밀도 선택을 요구한다.
- **콘텐츠 확장성:** 검투사·모험가·군인·귀족과 개인·세계 일정이 같은 작품 생애 파이프라인을 공유한다.

### 핵심 재미를 약화시킬 수 있는 위험

- 세 수식어가 설명용 메타데이터로만 남고 실제 다음 판단을 만들지 못하면 장식적 시스템이 된다.
- 성공률 공개가 너무 정확하면 작품의 생애보다 수치 최적화가 우선한다.
- 여러 일정과 연대기 알림이 강화 리듬을 자주 끊으면 메인 반복 재미가 분산된다.
- 예술성·제작 등급·등급 수식어·촉매 수식어·연대기 수식어가 동일 화면에서 위계 없이 노출되면 인지 부하가 커진다.

## 6. 권장 개선 방향 — 아직 정본 아님

아래 항목은 `PROPOSED_ONLY / USER_REVIEW_REQUIRED`다.

### 제안 A — 등급과 예술성의 표시 어휘 분리

권장안:

- 제작 등급 수식어: `[표준] / [우수] / [완벽]` 계열
- 예술성 시각 단계: `기본 / 세련 / 거장 / 걸작` 계열

같은 `명품`을 두 축에 중복 사용하지 않는다. 정확한 한국어 라벨은 별도 Decision에서 확정한다.

### 제안 B — 연대기 효과 책임 제한

연대기 수식어는 기본적으로 다음에만 영향을 주는 방향을 권장한다.

- 고객·세력의 선호와 대화
- 감정 가치·감정가·전시·선물·상속 가치
- 관련 사건의 추가 선택지

기본 전투 수치를 직접 올리는 효과는 예외 콘텐츠 Gate로 제한한다. 이는 촉매 수식어의 실용 성능 책임을 보호한다.

### 제안 C — 작품 소유권 상태 머신

```text
PLAYER_OWNED
→ SOLD_OR_GIFTED
→ TEMPORARILY_RETURNED_FOR_SERVICE
→ RETURNED_TO_OWNER
→ INHERITED_OR_LOST
```

복원 의뢰 중 임시 회수와 영구 재소유를 분리해야 중복 판매·소유권 복제·UID 충돌을 막을 수 있다.

### 제안 D — 첫 작품 정체성 보상 시점 검증

첫 작품은 제작 완료 즉시 등급 수식어를 얻고, 첫 정밀강화에서는 촉매 계보의 방향을 체감하며, 첫 고객 결과에서는 연대기 수식어의 형성 가능성을 예고해야 한다. 실제 생성 확률이나 보장 여부는 사람 플레이 뒤 결정한다.
