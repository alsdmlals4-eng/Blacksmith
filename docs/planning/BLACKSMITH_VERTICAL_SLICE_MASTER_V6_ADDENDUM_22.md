## 방문 고객 요청 처리 기한

`[방문 고객]` 요청 이벤트는 **기본 2영업일 기한**을 가진다.

방문 고객이 특정 장비 종류와 조건을 요청하면 플레이어는 요청이 발생한 영업일과 그다음 영업일 동안 보관함 제품을 제안하거나, 새 제품을 제작·강화·수리·정비해 대응할 수 있다.

```text
방문 고객 요청 발생
→ 요청 장비 종류·조건·보상·남은 영업일 공개
→ 일반 제작·강화·일반 판매 계속 가능
→ 기한 안에 보관함 제품 제안
→ 거래 성립 / 명시적 거절 / 기한 만료
```

방문 고객 요청은 일반 영업을 중단시키는 즉시 처리 팝업이 아니며, 무기한 보관되는 영구 퀘스트도 아니다.

## 2영업일 기한의 정확한 의미

요청 생성 시 `남은 영업일: 2`로 시작한다.

```text
요청 발생 영업일
남은 영업일 2
→ 현재 영업일 동안 대응 가능
→ 명시적 영업 종료

다음 영업일
남은 영업일 1
→ 해당 영업일 동안 대응 가능
→ 명시적 영업 종료

기한 만료
남은 영업일 0
→ 다음 영업일 시작 전에 만료 결과 확정
```

원칙:

- 요청 발생 당일을 포함해 총 2개 영업일 동안 대응 가능하다.
- 기한은 **명시적 영업 종료로 세계 시간이 진행될 때만** 감소한다.
- 앱 종료, 백그라운드 전환, 화면 잠금, 실제 시간 경과로 감소하지 않는다.
- 영업일 도중 요청 화면을 닫거나 다른 탭으로 이동해도 감소하지 않는다.
- 요청을 확인하지 않았다는 이유로 추가 유예 시간을 자동 제공하지 않는다.
- 저장 복구 후에도 이전에 확정된 남은 영업일이 유지된다.

정확한 콘텐츠별 예외 기한은 데이터로 설정할 수 있으나, 버티컬 슬라이스의 기본 기준은 2영업일이다.

## 요청 상태 모델

방문 고객 요청은 다음 상태 중 하나를 가진다.

| 상태 | 의미 |
|---|---|
| `미확인` | 요청이 발생했지만 상세 조건을 아직 열지 않음 |
| `활성` | 기한 내 대응 가능 |
| `제안 검토 중` | 보관함 제품을 선택해 거래 결과를 미리 확인 중 |
| `거래 완료` | 판매·보상·소유권 이전이 확정됨 |
| `거절` | 플레이어가 명시적으로 요청을 거절함 |
| `만료` | 남은 영업일이 0이 되어 요청이 종료됨 |
| `후속 진행 중` | 거래 후 약속·지원·세계 활동이 활성화됨 |
| `후속 완료` | 고객 세계 결과와 연대기가 확정됨 |

`제안 검토 중`은 제품 예약이나 소유권 이전이 아니다. 최종 거래 확정 전까지 제품은 플레이어 보관함에 남고 일반 영업에서 사용할 수 있다.

## 요청 발생 시 공개 정보

요청을 열면 최소 다음 정보를 확인할 수 있어야 한다.

- 고객 또는 요청 이벤트의 식별 정보
- 요청 장비 종류 또는 범주
- 최소 요구 조건
- 선호 강화 단계·수식어·내구·역사 가치 방향
- 사용 목적 또는 야망
- 제안 가격과 즉시 보상
- 남은 영업일
- 거래 후 가능한 후속 활동 방향
- 거절 또는 만료 시 알려진 영향

숨은 조건 때문에 기한 마지막에 거래가 거부되는 구조를 사용하지 않는다. 필수 조건과 판매 불가 사유는 제품 제안 전에 확인할 수 있어야 한다.

## 기한 중 일반 영업

방문 고객 요청이 활성화돼 있어도 `[대장간]`의 일반 영업은 계속된다.

### 허용되는 행동

- 새 장비 제작
- 작업 중 장비 완성
- 보관함 장비 강화·정밀강화·고위 정밀강화
- 수리·정비
- 요청과 무관한 장비 일반 판매
- 요청 조건에 맞는 제품 준비
- 요청 대응을 다음 영업일까지 보류
- 요청 명시적 거절

### 일반 판매와 요청의 충돌

요청에 적합할 수 있는 제품도 거래 확정 전에는 일반 판매할 수 있다.

```text
보관함 제품 A
→ 방문 고객 제안 후보로 표시
→ 플레이어가 일반 판매 확정
→ 제품 A가 보관함에서 제외
→ 방문 고객 요청은 계속 활성
→ 다른 제품을 준비하거나 요청을 포기
```

- 제안 후보 표시는 제품을 예약하지 않는다.
- 일반 판매 전에는 해당 제품이 활성 요청의 후보라는 사실을 표시한다.
- 일반 판매가 확정되면 모든 활성 요청에서 즉시 판매 불가로 갱신한다.
- 시스템이 판매된 제품을 복제하거나 고객 거래용으로 되돌리지 않는다.
- 제품이 없어졌다는 이유로 요청이 자동 거절되지는 않는다.

## 방문 후 제작·강화 대응

방문 고객은 현재 보관함에 맞는 제품이 없어도 요청 기한을 제공한다.

```text
장검 요청 발생
→ 보관함에 조건 충족 장검 없음
→ 일반 영업에서 장검 제작 또는 기존 장검 강화
→ 제작·강화 결과 보관함 등록
→ 요청 화면에서 새 제품 다시 평가
→ 기한 안에 거래 확정
```

원칙:

- 방문 이후 제작한 제품도 일반 제품이며 고객 전용 플래그를 갖지 않는다.
- 요청에 맞추어 제작했더라도 다른 판매 경로를 선택할 수 있다.
- 제품이 조건을 충족했는지는 현재 제품 상태로 다시 계산한다.
- 강화 결과가 실패·하락·파괴돼도 요청 상태와 제품 상태를 별도로 정확히 유지한다.
- 영구 파괴된 제품은 제안 목록에서 제거되지만 요청 자체는 기한까지 유지할 수 있다.
- 요청 대응을 위해 확률이나 강화 결과를 보정하지 않는다.

## 제품 제안과 거래 확정

활성 요청에서 보관함 제품을 선택하면 다음을 비교한다.

- 요청 종류 충족 여부
- 최소 조건 충족 여부
- 선호 방향 적합도
- 고객 야망·사용 목적과의 적합성
- 현재 강화·수식어·내구·역사 가치
- 거래 가격과 즉시 보상
- 예상 후속 활동 방향

### 제안 불가 조건

다음 제품은 거래를 확정할 수 없다.

- 아직 제작 완료되지 않은 작업 중 제품
- 이미 일반 판매되거나 다른 고객에게 소유권이 이전된 제품
- 파괴·영구 소실 상태인 제품
- 요청 장비 종류와 명시적으로 불일치하는 제품
- 필수 최소 조건을 충족하지 못한 제품
- 다른 비가역 거래가 진행 중인 제품

### 거래 원자성

방문 고객 거래 확정 시 다음 상태를 하나의 원자적 결과로 저장한다.

- 제품의 보관함 제외
- 기존 제품 식별자 유지
- 고객에게 소유권 이전
- 판매 가격과 즉시 보상 지급
- 관계·신뢰 변화
- 약속·지원·구독 상태
- 후속 세계 활동 생성 여부
- 장비 연대기 거래 기록
- 요청 상태를 `거래 완료`로 변경

저장 완료 전에 성공 연출이나 후속 활동 진입을 시작하지 않는다.

## 거절

플레이어는 기한이 남아 있어도 요청을 명시적으로 거절할 수 있다.

- 거절 전 고객·요청·남은 영업일과 알려진 영향을 다시 표시한다.
- 거절은 비가역 행동이므로 위험 등급에 맞는 확인 입력을 사용한다.
- 거절해도 보관함 제품은 변하지 않는다.
- 거절해도 일반 제작·강화·일반 판매는 계속 가능하다.
- 관계·명성 등 결과가 있다면 거절 전에 방향을 공개한다.
- 거절 결과와 요청 종료 상태를 함께 저장한다.
- 앱 재실행으로 거절한 요청이 다시 활성화되지 않는다.

정확한 관계 변화 수치는 고객 콘텐츠와 밸런스 명세에서 정한다.

## 만료

남은 영업일이 0이 되면 요청은 만료된다.

```text
영업 종료 확정
→ 세계 시간 1일 진행
→ 활성 요청 남은 영업일 감소
→ 0이 된 요청의 만료 결과 판정·저장
→ 다음 영업일 시작
```

- 만료는 요청과 고객 상태에만 영향을 준다.
- 요청 대상이었던 보관함 제품을 삭제·손상·예약하지 않는다.
- 조건에 맞는 제품이 보관함에 남아 있어도 자동 판매하지 않는다.
- 만료 보상이나 패널티를 중복 적용하지 않는다.
- 만료 결과는 다음 영업일 일반 조작 전에 확인 가능해야 한다.
- 만료된 요청을 앱 재실행으로 다시 판정하지 않는다.
- 중요한 이름 있는 고객은 추후 새로운 요청으로 재방문할 수 있다.
- 재방문은 이전 만료 결과를 취소하거나 동일 보상을 다시 지급하는 복구 기능이 아니다.

## 알림과 내비게이션

방문 고객 요청은 기존 알림 우선순위를 사용한다.

### 요청 발생

- `[방문 고객]` 탭에 요청 배지 표시
- 요청 장비 종류와 기본 기한 요약 제공
- 강화 입력·결과 연출을 강제로 중단하지 않음
- 자동으로 `[방문 고객]` 탭으로 이동시키지 않음

### 기한 임박

`남은 영업일: 1`이면 기한·행동 우선 알림으로 올린다.

- 색상만으로 임박 상태를 표현하지 않는다.
- 남은 영업일 숫자와 문구를 함께 표시한다.
- 관련 요청으로 직접 이동하는 동작을 제공한다.
- 알림을 닫아도 요청 상태와 기한은 유지한다.

### 만료 결과

- 만료 결과는 일반 뉴스가 아니라 확인해야 하는 결과 상태로 기록한다.
- 보관함 제품이 변하지 않았음을 명확히 표시한다.
- 관계·명성 변화가 있다면 원인과 방향을 표시한다.

## 저장·복구 계약

방문 고객 요청은 다음 상태를 저장한다.

- 요청 식별자
- 고객 식별자 또는 고객 유형
- 요청 장비 종류·조건
- 제안 가격과 보상
- 생성 영업일
- 남은 영업일
- 확인 여부
- 현재 요청 상태
- 선택 중인 제품 식별자
- 거래·거절·만료 결과 적용 여부
- 후속 활동 연결 상태

무결성 원칙:

- 앱 종료만으로 기한이 감소하지 않는다.
- 영업 종료 1회당 기한 감소도 정확히 1회만 적용한다.
- 거래 완료와 만료가 동시에 적용되지 않는다.
- 거절 후 만료 패널티를 추가 적용하지 않는다.
- 거래 완료 제품을 일반 판매하거나 다른 요청에 다시 판매하지 않는다.
- 복구 시 요청 기한과 제품 소유권이 서로 모순되지 않아야 한다.
- 요청 결과를 연출 애니메이션이 결정하지 않는다.

## 접근성·성능 계약

- 남은 기한은 색·소리·진동에만 의존하지 않는다.
- 화면 읽기 환경에서 고객, 요청 종류, 조건, 보상, 남은 영업일, 실행 버튼 순서를 유지한다.
- 텍스트 확대 상태에서도 요청 종류·기한·거래 버튼이 잘리거나 겹치지 않는다.
- 모션 감소 상태에서 요청 발생·임박·만료의 의미가 유지된다.
- 불씨 정령 반응은 요청 안내를 보조할 수 있지만 유일한 정보 전달 채널이 아니다.
- 다수 요청 표시로 일반 강화 화면의 프레임·입력·저장 무결성이 저하되지 않아야 한다.

## 버티컬 슬라이스 검증 범위

버티컬 슬라이스에서는 최소 다음 경로를 검증한다.

1. 요청 발생 당일 기존 보관함 제품으로 즉시 거래
2. 요청 발생 후 제품을 제작 또는 강화해 다음 영업일 거래
3. 적합 후보 제품을 일반 판매한 뒤 다른 제품으로 대응
4. 요청 명시적 거절
5. 요청 기한 만료
6. 앱 종료·복귀 후 남은 영업일 유지
7. 영업 종료 후 기한 감소와 만료 결과의 1회 적용
8. 거래 완료 후 고객 세계 활동으로 연결

모든 고객 유형의 모든 요청을 한 세션에서 강제하지 않는다. 어떤 고객 이벤트를 대표·증명 세트로 사용할지는 별도 세션 구성 결정에서 확정한다.

## 현재 기획 상태 영향

이번 결정으로 해결되는 항목:

- 방문 고객 요청의 기본 기한
- 기한 감소 기준
- 방문 이후 제작·강화 대응 가능 여부
- 일반 판매와 요청 후보 제품의 충돌 처리
- 거래·거절·만료 상태와 저장 계약

아직 미정인 항목:

- 동시에 활성화할 수 있는 방문 고객 요청 수
- 신규 요청 발생 빈도
- 요청 생성 규칙과 장비 종류 분포
- 고객별 예외 기한 여부
- 요청 거절·만료의 정확한 수치 결과
- 버티컬 슬라이스 대표 고객 이벤트 조합
- 일반 영업과 고객 이벤트를 포함한 15~25분 시간 예산
