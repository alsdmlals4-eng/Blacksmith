## 두 번째 콘텐츠 제작 파이프라인 증명

버티컬 슬라이스는 **대표 콘텐츠 세트 1개와 독립된 두 번째 콘텐츠 세트 1개를 동일한 시스템·데이터·저장 구조로 완주**시켜 콘텐츠 제작 파이프라인의 재사용성을 증명한다.

대표 세트의 완성도만으로 파이프라인이 증명됐다고 판단하지 않는다. 두 번째 세트가 다른 고객 유형, 다른 장비 유형, 다른 특수재료와 다른 세계 결과를 사용하면서도 새로운 핵심 시스템이나 고객명 고정 분기 코드 없이 동작해야 한다.

| 구분 | 역할 | 필수 차이 |
|---|---|---|
| 대표 세트 | 검투사 + 고위 정밀강화 무기 + 경기·배팅·재방문 | 대표 감정 곡선과 완성 품질 기준 |
| 증명 세트 | 수집가 또는 모험가 + 다른 장비 유형 + 다른 특수재료·세계 결과 | 시스템·데이터·저장 구조 재사용 증명 |

```text
콘텐츠 세트 A
검투사
→ 무기 강화
→ +50 고위 정밀강화 진화
→ 판매·소유권 이전
→ 경기·배팅
→ 대표 특수 수식어 심화
→ 장비 변화와 재방문

콘텐츠 세트 B
수집가 또는 모험가
→ 다른 장비 유형 강화
→ 다른 특수재료 또는 진화 방향
→ 판매·소유권 이전
→ 독립 세계 사건
→ 관계·수식어·연대기 결과
```

## 대표 세트 계약

대표 세트는 이미 확정된 이름 있는 검투사와 `+50` 고위 정밀강화 장비의 흐름을 사용한다.

필수 구성:

- `[대장간]`에서 준비된 무기를 일반 강화·일반 정밀강화·고위 정밀강화한다.
- `+49 → +50` 특수재료 고위 정밀강화에서 진화 후보를 선택한다.
- 외형·이름·대표 특수 수식어와 고객 적합 방향을 확정한다.
- `[방문 고객]`에서 두 적합 후보 중 이름 있는 검투사에게 판매한다.
- 판매 후 구독·관심 인물·약속·지원 흐름을 연결한다.
- `[세계]`에서 경기 일정, 공식 배당, 배팅, 짧은 자동 경기와 결과를 제공한다.
- 승패 양쪽에서 관계·장비 연대기·대표 특수 수식어 심화가 의미 있게 진행된다.
- 마지막에는 검투사가 변경된 장비와 다음 야망을 갖고 재방문한다.

대표 세트는 품질 기준이지만 특정 검투사 이름, 무기 이름 또는 경기 이름에 시스템 규칙을 직접 묶지 않는다.

## 두 번째 세트 계약

두 번째 세트는 대표 세트와 구분되는 다음 차이를 모두 포함한다.

- 고객 유형이 검투사가 아니다.
- 대표 세트와 다른 장비 유형을 사용한다.
- 대표 세트와 다른 특수재료 획득 또는 선택 맥락을 사용한다.
- 경기·배팅이 아닌 독립 세계 결과를 사용한다.
- 대표 세트와 다른 관계 상승 원인 또는 장비 운명 변화를 사용한다.
- 같은 고객·장비·세계 사건 데이터 구조와 저장 계약을 재사용한다.

두 번째 세트의 후보는 수집가 또는 모험가다. 정확한 선택과 세부 콘텐츠는 후속 결정에서 확정한다.

## 공통 데이터 표현 계약

두 콘텐츠 세트는 최소한 다음 항목을 같은 데이터 구조로 표현한다.

### 고객

- 고객 식별자
- 고객 유형
- 이름과 표시 정보
- 요구 조건
- 선호 조건
- 야망
- 판매 가격과 즉시 보상
- 장비 적합도 방향
- 관계·신뢰 상태
- 활성 약속과 지원 요구
- 구독·관심 인물 상태
- 재방문 조건

### 장비

- 장비 식별자와 유형
- 현재 강화 단계
- 정밀강화 결과
- 고위 정밀강화 진화 유형
- 대표 특수 수식어와 보조 수식어
- 제작자
- 현재·과거 소유자
- 가치와 역사 가치
- 손상·분실·파괴·상속 등 운명 상태
- 연대기

### 특수재료·진화 후보

- 재료 식별자와 획득 맥락
- 적합 고객·장비 유형
- 진화 후보 2~3개
- 외형·이름·대표 수식어 방향
- 비용과 부가 결과 범위
- 선택 완료 여부

### 세계 사건

- 사건 식별자와 유형
- 대상 고객·장비
- 시작·마감 영업일
- 지원 가능 상태
- 위험·보상 방향
- 결과 분기
- 장비·관계·수식어·연대기 변경
- 미확인 결과 상태

고객 이름, 장비 이름 또는 사건 이름은 콘텐츠 데이터이며 시스템 분기 조건이 아니다.

## 공통 흐름 재사용 계약

두 세트는 다음 공통 흐름을 재사용해야 한다.

```text
[대장간]
장비 선택
→ 위험·비용 확인
→ 강화·정밀강화
→ 원자적 저장

[방문 고객]
요구·선호·야망 비교
→ 장비 적합도·가격 비교
→ 판매·소유권 이전
→ 약속·지원·구독
→ 원자적 저장

[세계]
사건 또는 활동 일정
→ 지원 선택
→ 영업 종료
→ 세계 결과 판정·저장
→ 관계·수식어·연대기 갱신
```

두 번째 세트를 위해 다음을 새로 만들지 않는다.

- 네 번째 최상위 탭
- 별도 강화 규칙 엔진
- 별도 고객 관계 시스템
- 별도 소유권·연대기 저장 방식
- 별도 사건 마감 시간 체계
- 별도 결과 복구 구조
- 고객 이름을 확인하는 하드코딩 분기
- 장비 하나에만 적용되는 전용 저장 필드

## 허용되는 콘텐츠별 차이

파이프라인 재사용은 모든 콘텐츠를 동일하게 만드는 것이 아니다. 다음은 콘텐츠 데이터와 구성 차이로 허용한다.

- 고객 대사와 성격
- 요구·선호·야망 조합
- 판매 가격과 즉시 보상 방향
- 장비 외형·유형·수식어 조합
- 특수재료의 출처와 설명
- 진화 후보 내용
- 세계 사건의 장면·결과 문구
- 관계 상승의 서사적 표현
- 장비 연대기 문장
- 전용 일러스트·사운드·연출 자산

다만 이 차이를 지원하기 위해 새로운 핵심 규칙이나 저장 체계를 만들면 파이프라인 증명 실패로 분류한다.

## 파이프라인 제작 산출물

두 번째 세트 완료 시 다음 제작 산출물이 있어야 한다.

- 고객 데이터 입력 규격
- 장비·정밀강화·진화 후보 입력 규격
- 특수재료 입력 규격
- 세계 사건 입력 규격
- 관계·수식어·연대기 결과 입력 규격
- 콘텐츠 세트 연결 체크리스트
- 필수 자산 목록
- 데이터 검증 체크리스트
- 기존 대표 세트 회귀 테스트 목록
- 세 번째 세트를 추가할 때 사용하는 반복 가능한 제작 순서

```text
새 콘텐츠 세트 제작
→ 고객 데이터 입력
→ 장비·재료·진화 후보 입력
→ 사건·결과·연대기 입력
→ 공통 흐름 연결
→ 데이터 검증
→ 전체 슬라이스 회귀 테스트
```

## 파이프라인 증명 합격 조건

다음 조건을 모두 만족해야 한다.

1. 대표 세트와 두 번째 세트가 같은 3개 최상위 영역에서 동작한다.
2. 두 번째 세트 추가를 위해 새로운 핵심 시스템을 만들지 않는다.
3. 고객 요구·선호·야망이 같은 구조로 비교된다.
4. 장비·특수재료·진화 후보를 데이터 교체로 구성할 수 있다.
5. 판매·소유권·구독·약속·지원·세계 사건·연대기 저장 구조를 재사용한다.
6. 두 세트 모두 앱 중단·강제 종료 후 동일한 확정 상태로 복귀한다.
7. 두 번째 세트에서 대표 세트 전용 이름·장비·사건 분기 코드가 발견되지 않는다.
8. 두 번째 세트 추가 후 대표 세트 전체 흐름이 회귀 없이 완료된다.
9. 제3의 고객·장비·사건 세트를 추가하기 위한 입력 규격과 체크리스트가 남는다.
10. 15~25분 버티컬 슬라이스의 전체 시간 경계를 훼손하지 않는다.

## 실패 조건

다음 중 하나라도 발생하면 파이프라인 증명 실패다.

- 대표 검투사 세트만 동작함
- 두 번째 고객을 추가하기 위해 별도 시스템을 제작함
- 고객·장비 이름을 코드에서 직접 검사해 흐름을 분기함
- 두 번째 장비 유형이 공통 강화·저장 구조를 사용하지 못함
- 두 번째 세계 사건이 공통 마감·지원·결과 구조를 사용하지 못함
- 두 번째 세트 저장이 기존 소유권·관계·연대기와 충돌함
- 두 번째 세트 추가 후 대표 세트가 회귀함
- 콘텐츠 제작 절차가 특정 개발자의 수작업 기억에만 의존함
- 제작 체크리스트와 입력 규격 없이 완료로 판단함

## 버티컬 슬라이스 범위 경계

- 네 고객 유형은 모두 슬라이스에서 실제 상호작용과 결과를 가진다.
- 파이프라인의 깊은 증명은 대표 세트와 두 번째 세트 두 개로 한정한다.
- 나머지 고객 유형을 대표 세트와 같은 깊이로 모두 확장하지 않는다.
- 두 번째 세트를 이유로 전체 +100 강화 콘텐츠를 제작하지 않는다.
- 두 번째 세트를 이유로 새로운 독립 게임 시스템을 추가하지 않는다.
- 증명에 필요한 최소 콘텐츠만 추가하고 15~25분 플레이 시간 경계를 재검증한다.

## 검증 항목

- 두 세트가 동일한 화면·데이터·저장 구조를 사용하는지 확인
- 고객 이름 또는 장비 이름 고정 분기가 없는지 확인
- 두 번째 장비 유형의 강화·정밀강화·판매·연대기 저장 확인
- 다른 특수재료와 진화 후보가 공통 구조로 표현되는지 확인
- 두 번째 세계 사건의 기한·지원·자동 해결·결과 저장 확인
- 두 번째 세트 결과 후 소유권·관계·수식어·연대기가 함께 갱신되는지 확인
- 앱 중단·강제 종료 시 두 세트 모두 중복 결과 없이 복귀하는지 확인
- 두 번째 세트 추가 후 대표 검투사 흐름 전체 회귀 확인
- 제작 체크리스트만으로 세 번째 세트의 입력 범위를 설명할 수 있는지 확인
- 전체 슬라이스가 15~25분 시간 경계를 유지하는지 확인
