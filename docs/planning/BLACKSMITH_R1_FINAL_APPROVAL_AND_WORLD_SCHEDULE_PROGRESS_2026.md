## 2. BS-WORLD-20260803-01 — 세계일정은 날짜마다 단계적으로 진행

### 핵심 결정

1. 세계일정은 납품·발생 당일에 최종 결과까지 즉시 해결하지 않는다.
2. 하루 종료로 게임 날짜가 한 번 진행될 때 세계일정도 최대 한 단계 또는 한 개의 명시적 진행 단위만 전진한다.
3. 모든 세계일정은 최종 결과 전에 최소 한 번 이상의 중간 진행 상태를 플레이어에게 보여준다.
4. 가장 작은 세계일정도 발생 당일 또는 첫 날짜 진행 한 번만으로 최종 해결되지 않는다.
5. 일정의 규모가 클수록 필요한 단계 수와 게임 날짜가 단조 증가해야 한다.
6. 정확한 필요 날짜·단계 수는 `RECOMMENDED_DEFAULT / TEST_VALUE`이며, 규모와 기간의 상대 관계는 정본 불변 규칙이다.
7. 납품 직후 제공하는 즉시 피드백은 사용 계획·초기 반응·예상 위험·작품 기여 가능성을 설명할 수 있지만 세계일정의 최종 성공·실패 판정은 아니다.
8. 날짜별 진행은 단순 대기 문구가 아니라 상황 변화·새 정보·위험 변화·작품 상태·고객 행동·플레이어의 후속 대응 가능성을 보여줘야 한다.
9. 같은 날 여러 단계를 몰아서 처리하거나 날짜 넘기기 한 번으로 대형 사건을 완료하는 방식을 금지한다.
10. 피로도 소진과 날짜 넘기기를 반복해 결과만 빠르게 수확하는 것이 최적해가 되지 않도록, 각 날짜에 실제 작업 우선순위와 대응 선택을 연결한다.

### 권장 상태 구조

```text
SCHEDULED
→ PREPARATION
→ IN_PROGRESS
→ TURNING_POINT 또는 COMPLICATION
→ RESOLUTION_PENDING
→ RESOLVED
```

모든 세계일정이 모든 상태를 사용해야 하는 것은 아니지만 다음은 필수다.

- 발생·납품 당일의 `SCHEDULED` 또는 `PREPARATION`
- 하나 이상의 중간 진행 상태
- 별도 날짜의 최종 `RESOLVED`

### 규모와 기간

정확한 숫자는 테스트 프리셋에서 결정하되 상대 관계는 다음을 지킨다.

```text
LOCAL / PERSONAL
< REGIONAL / FACTION
< REALM / NATIONAL
< WAR / CATASTROPHE
```

- 소규모 일정: 짧지만 다일 진행과 중간 상태가 존재한다.
- 중규모 일정: 복수의 진행 보고와 최소 한 번의 조건 변화가 존재한다.
- 대규모 일정: 준비·전개·전환점·결말이 분리되며 장기간 진행한다.
- 초대형 일정: 여러 작품·고객·세력의 연결 가능성은 열어두되 R2~R4에서 범위 팽창을 별도 검토한다.

### 날짜별 플레이어 정보

플레이어는 세계일정 화면에서 최소한 다음을 확인할 수 있어야 한다.

- 현재 단계
- 경과 게임 날짜
- 예상 남은 기간 범위 또는 다음 갱신 시점
- 지금까지 확인된 작품 기여
- 새로 발생한 위험·조건·기회
- 다음 날 전에 가능한 대응 행동

정확한 결말을 미리 확정적으로 공개하지 않으며, 불확실성은 숨은 랜덤 처벌이 아니라 확인 가능한 정보 부족으로 표현한다.

### 작품 생애와의 연결

- 각 날짜의 진행은 같은 작품 UID 연대기에 순차 기록한다.
- 중간 진행에서 손상·평판 변화·소유자 행동·새로운 요구가 생길 수 있다.
- 사건·연대기 수식어는 최종 결과만이 아니라 인과적으로 중요한 전환점에서 생성·변형될 수 있다.
- 단순히 날짜가 지났다는 이유만으로 사건 수식어를 성장시키지 않는다.
- 플레이어의 제작·강화·지원 선택과 실제 사용·기여가 확인돼야 한다.

### 즉시 결과·지연 결과 정합성

기존 `즉시 인과 결과 + 지연된 생애 결과` 원칙은 다음과 같이 정렬한다.

```text
납품 당일
→ 사용 계획·초기 반응·예상 기여를 즉시 피드백

날짜 1
→ 준비·출발·초기 접촉

날짜 2+
→ 진행·변수·전환점

마지막 날짜
→ 최종 성공·부분 성공·실패·손상·새로운 필요
```

즉시 피드백은 유지하지만, 최종 세계 결과를 하루 만에 소비하지 않는다.

## 3. 적대적 보호 조건

- 기간이 길다는 이유만으로 빈 대기 로그를 반복하지 않는다.
- 규모가 크다는 이유만으로 단순히 숫자만 늘리지 않는다.
- 날짜마다 필수 대화창을 강제해 강화 흐름을 끊지 않는다.
- 플레이어가 개입할 수 없는 일정에 거짓 선택지를 제공하지 않는다.
- 날짜 넘기기를 현금화·광고·실시간 대기로 가속하지 않는다.
- 대형 일정이 한 작품의 생애보다 항상 우선하는 최적해가 되지 않게 한다.
- 일정 동시 진행 수·실패 기한·중단·재개·분기 합류 규칙은 R2~R4에서 별도 승인한다.

## 4. 벤치마킹 적용

## 5. 정본 우선순위

본 결정은 다음 표현보다 우선한다.

- 납품 다음 날 곧바로 최종 세계 결과가 나온다는 해석
- 하나의 날짜 진행으로 준비부터 결말까지 처리하는 구조
- 규모와 관계없이 모든 일정이 같은 기간을 사용하는 구조
- 중간 진행 없이 결과 카드만 지급하는 구조
- 날짜 경과만으로 작품의 사건 수식어가 자동 성장하는 구조

표준 문구:

> 세계일정은 발생 당일에 최종 해결되지 않는다. 하루가 지날 때마다 하나의 진행 상태가 전진하고, 최소 한 번 이상의 중간 변화를 거쳐 별도 날짜에 결말이 나온다. 일정 규모가 클수록 필요한 단계와 게임 날짜가 늘어나며, 정확한 기간은 버전형 테스트 프리셋으로 검증한다.
