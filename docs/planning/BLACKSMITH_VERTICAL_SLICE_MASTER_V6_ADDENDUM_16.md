## 플레이테스트 합격 기준

버티컬 슬라이스 검증은 **결정론적 기능 검증 → 최소 6명 비유도 플레이테스트 → 수정 후 양방향 회귀 검증**의 3단계 게이트로 진행한다.

제작자 단독 반복 실행만으로 기획 검증이 완료됐다고 판단하지 않는다. 반대로 정식 제품 수준의 대규모 통계 표본도 요구하지 않는다. 현재 단계의 목적은 핵심 강화 루프, 고객·세계 연결, 저장·복귀, 접근성 및 두 콘텐츠 세트의 구조적 유효성을 실제 플레이에서 차단 결함 없이 증명하는 것이다.

```text
1단계
결정론적 기능 검증

2단계
최소 6명 비유도 플레이테스트

3단계
수정 후 원조건 재검증 + 양방향 회귀
```

## 1단계: 결정론적 기능 검증

비유도 테스트 전에 제작자가 재현 가능한 검증 시나리오를 기준 기기군에서 통과시켜야 한다.

### 기준 환경

- Android 저사양 기준 기기군
- Android 중간 기준 기기군
- Android 상위 기준 기기군
- 기본 입력 경로
- 길게 누르기 대체 입력 경로
- 텍스트 확대·모션 감소·무음·무진동 조합
- 신규 설치 상태
- 기존 활성 저장 복귀 상태
- 앱 백그라운드·프로세스 종료·강제 종료 복귀 상태

에뮬레이터만으로 물리 기기 검증을 대체하지 않는다.

### 강화·원자적 저장 검증

다음 항목을 직접 재현한다.

- 강화 시도당 판정이 정확히 1회만 수행됨
- 입력 완료 전 자원 미소비
- 비용·재료·보호·장비 상태·정밀 결과가 원자적으로 저장됨
- 결과 저장 후 연출이 시작됨
- 연출 도중 종료해도 동일 결과로 복귀함
- 앱 재실행으로 결과가 재추첨되지 않음
- 빠른 연속 탭으로 강화와 비용이 중복 적용되지 않음
- 영구 파괴와 단계 하락이 정확히 구분됨
- 미확인 결과가 복귀 후 일반 조작보다 먼저 표시됨

### 고객·소유권 검증

- 네 고객 유형이 공통 비교 화면에 표시됨
- 고객 요구·선호·야망과 장비 적합도를 구분할 수 있음
- 판매 비용·보상·소유권 이전이 하나의 확정 상태로 저장됨
- 판매 직후 종료해도 장비와 보상이 분리되지 않음
- 이미 판매된 장비를 중복 판매할 수 없음
- 모험가 장비 분실 시 소유권과 점유·위치 상태가 구분됨
- 회수 후 동일 장비 식별자와 연대기가 유지됨

### 세계·관계·연대기 검증

- 영업 종료 입력만 세계 시간을 진행시킴
- 앱 종료만으로 사건 기한이 감소하지 않음
- 검투사 경기·배팅 결과가 정확히 한 번 정산됨
- 모험가 사전 지원 비용과 결과 영향 상태가 함께 유지됨
- 세계 결과 보상·관계·수식어·연대기가 중복 적용되지 않음
- 수집가 데이터가 공통 고객·소유권·기본 연대기 구조에 정상 진입함
- 미확인 세계 결과가 다음 작업보다 먼저 정리됨

### 접근성·정보 판독 검증

- 색상 없이 성공·실패·하락·파괴를 구분할 수 있음
- 무음·무진동 상태에서 핵심 결과를 완전히 이해할 수 있음
- 모션 감소 상태에서 일반 강화·정밀강화·고위 정밀강화를 구분할 수 있음
- 텍스트 확대 상태에서 성공률·비용·파괴 위험·강화 버튼이 겹치거나 잘리지 않음
- 길게 누르기 대체 입력으로 동일 확률·비용·결과를 사용함
- 화면 읽기 순서에서 장비·확률·비용·손실 위험·실행 순서가 유지됨
- 불씨 정령 반응이 핵심 UI를 가리거나 포커스를 강제로 빼앗지 않음

### 성능·패키지 검증

- 일반 UI·반복 강화가 기준 반응성을 유지함
- 고부하 연출에서 적응형 품질 축소 후 안정적인 30fps 하한을 유지함
- 프레임 저하 중에도 입력·판정·저장 무결성이 유지됨
- 15~25분 전체 슬라이스 반복 후 프레임·메모리·입력 반응이 악화되지 않음
- 신규 설치·업데이트·저장 마이그레이션·프로세스 종료 복귀가 정상 작동함

## 2단계: 비유도 플레이테스트

결정론적 기능 검증을 통과한 빌드로 최소 **고유 테스터 6명**의 비유도 플레이테스트를 수행한다.

### 표본 구성

- 최소 고유 테스터: 6명
- 가능하면 저사양·중간·상위 기기군별 2명
- 프로젝트 상세 규칙을 사전에 알지 못하는 사람 우선
- 같은 사람이 여러 번 플레이해도 고유 테스터 수는 1명으로 계산
- 제작자와 기획자는 최소 표본에 포함하지 않음

정확히 기기군별 2명을 확보하지 못하더라도 6명 전체를 충족해야 하며, 실제 테스트된 기기·Android 버전·화면 비율을 기록한다.

### 비유도 원칙

테스트 시작 전 제공 가능한 설명은 다음 수준으로 제한한다.

```text
“당신은 대장간을 운영합니다.
화면에 보이는 정보를 사용해 준비된 버티컬 슬라이스를 진행해 주세요.
막히거나 이해되지 않는 부분이 있어도 먼저 화면 안에서 해결해 보세요.”
```

관찰자는 다음을 하지 않는다.

- 정답 고객이나 장비 선택을 알려줌
- 강화 위험을 대신 해석함
- 탭 이동 순서를 지시함
- 약속·지원·배팅의 최적 선택을 제시함
- 막힌 즉시 해결 방법을 말함

진행 불능이 지속돼 테스트를 계속할 수 없을 때만 개입하며, 해당 개입 시점과 원인을 기록한다. 개입 후 완료는 비유도 완료로 계산하지 않는다.

### 각 테스터의 목표 흐름

각 테스터는 하나의 15~25분 세션에서 다음 핵심 흐름을 경험해야 한다.

- `[대장간]`에서 일반 강화 진입
- 일반 정밀강화 또는 고위 정밀강화의 위험·비용 확인
- 고객 요구·선호·야망 비교
- 장비 판매와 소유권 이전 이해
- `[세계]`에서 사건·경기·지원·결과 중 의미 있는 후속 활동 확인
- 판매한 장비의 관계·수식어·연대기 변화를 이해
- 최소 하나의 결과 확인 후 다음 행동 방향 인지

검투사와 모험가의 전체 세트를 모든 테스터가 각각 처음부터 끝까지 모두 수행해야 한다는 의미는 아니다. 다만 전체 표본에서 두 세트가 모두 충분히 관찰되고, 각 세트의 필수 경로는 별도 결정론적 검증과 회귀 검증에서 완주돼야 한다.

### 관찰 기록

각 테스트에서 다음을 기록한다.

- 사용 기기·Android 버전·화면 비율
- 시작부터 첫 강화까지 걸린 시간
- 전체 세션 시간
- 각 최상위 영역 진입 여부
- 막힌 화면과 지속 시간
- 관찰자 개입 여부와 이유
- 성공률·비용·하락·파괴 위험 오해
- 고객 요구·선호·야망 오해
- 판매·소유권·지원·배팅·세계 결과 오해
- 잘못 누른 비가역 행동
- 알림·배지·남은 영업일 해석 오류
- 접근성 설정 사용 여부와 진행 가능성
- 충돌·저장·중복 적용·복귀 문제
- 플레이 종료 후 핵심 루프를 자신의 말로 설명할 수 있는지

## 결함 등급

### 차단 결함

다음 문제는 발생 횟수와 무관하게 **1회 발생만으로 해당 빌드 실패**다.

- 앱 충돌 또는 전체 진행 불능
- 활성 저장 손상 또는 읽기 불가
- 자원만 소비되고 결과가 없음
- 결과가 있으나 비용·재료가 적용되지 않음
- 강화·보상·관계·세계 결과의 중복 적용
- 앱 재실행으로 확정 결과 재추첨
- 장비 판매 후 소유권·보상·연대기 일부만 적용
- 영구 파괴 또는 비가역 선택 전에 필수 위험 정보 누락
- 접근성 대체 입력으로 핵심 진행 불가
- 모든 기준 기기 중 하나에서 전체 슬라이스 완료 불가
- 검투사 또는 모험가 공통 시스템 변경 후 상대 세트 진행 불가

차단 결함은 테스트 표본 비율이나 평균으로 상쇄하지 않는다.

### 중대 UX 결함

다음 문제는 핵심 흐름을 완료할 수는 있지만 잘못된 비가역 판단이나 장기 진행 오해를 유발한다.

- 성공률·비용·최대 하락·영구 파괴 여부 오해
- 보호 효과를 실제보다 크게 또는 작게 이해
- 고객 요구·선호·야망을 구분하지 못해 잘못 판매
- 남은 영업일이나 사건 마감 오해
- 소유권과 점유·분실 상태 혼동
- 저장 완료·미완료 상태 오해
- 일반 소식과 필수 확인의 우선순위 혼동
- 대체 입력·텍스트 확대·모션 감소에서 핵심 정보 누락

### 일반 UX 결함

- 중요하지 않은 탭·버튼 명칭 혼동
- 반복 연출이 다소 길거나 짧음
- 비핵심 세계관 문구 이해 지연
- 장식 자산이나 불씨 정령 반응의 가독성 문제
- 진행은 가능하지만 불필요한 화면 왕복이 발생함

## 반복 문제 정의

차단 결함이 아닌 UX 문제는 다음 중 하나를 만족하면 **반복 결함**으로 분류한다.

```text
같은 근본 원인의 문제를
독립된 테스터 2명 이상이 경험

또는

같은 기준 기기·동일 조건에서
2회 이상 재현
```

다른 문구·화면에서 나타났더라도 원인이 같은 정보 구조나 상태 표현이라면 하나의 반복 문제로 묶는다. 반대로 겉모양이 비슷해도 원인이 다른 문제를 임의로 하나로 합치지 않는다.

### 반복 결함의 처리

- 반복된 중대 UX 결함은 수정 전 합격 불가
- 반복된 일반 UX 결함은 핵심 흐름 영향도를 평가해 수정 또는 명시적 범위 이월
- 범위 이월 시 이유, 영향, 재검증 시점을 Issue #60에 기록
- “테스터가 익숙하지 않아서”라는 이유만으로 반복 문제를 무효화하지 않음
- 제작자가 설명했을 때 해결된 문제도 비유도 설계 문제로 기록

## 3단계: 수정 후 회귀 검증

수정된 결함은 원래 발생 조건에서 다시 검증한다.

```text
결함 수정
→ 원래 기기·화면·저장·입력 조건 재현
→ 수정 확인
→ 검투사 세트 회귀
→ 모험가 세트 회귀
→ 저장·복귀·접근성 공통 경로 회귀
```

### 양방향 회귀 원칙

- 검투사 관련 수정 후 모험가 세트 완주 검증
- 모험가 관련 수정 후 검투사 세트 완주 검증
- 고객 공통 UI 수정 후 네 고객 데이터 표시 검증
- 강화 UI 수정 후 일반·정밀·고위 정밀강화 검증
- 저장 구조 수정 후 구매·강화·판매·지원·배팅·세계 결과 검증
- 접근성 수정 후 기본 입력 경로도 재검증
- 성능 품질 축소 수정 후 핵심 정보 보존 검증
- 불씨 정령 수정 후 핵심 UI·화면 읽기·성능 회귀 검증

차단 결함 수정 후에는 최소 해당 기준 기기와 중간 기준 기기에서 전체 슬라이스를 다시 완료한다.

## 합격 기준

다음 조건을 모두 만족해야 버티컬 슬라이스 플레이테스트 게이트를 통과한다.

1. 차단 결함 0건
2. 반복된 미해결 중대 UX 결함 0건
3. 최소 6명 중 5명 이상이 관찰자 개입 없이 핵심 흐름 완료
4. 같은 핵심 정보 오해가 독립된 테스터 2명 이상에게 반복되지 않음
5. 비유도 완료 세션의 중앙값이 15~25분
6. 저사양·중간·상위 기준 기기군에서 전체 슬라이스 완료 가능
7. 텍스트 확대·모션 감소·무음·무진동·대체 입력 경로에서 핵심 흐름 완료 가능
8. 검투사 대표 세트와 모험가 증명 세트의 필수 경로 완주
9. 수정 후 두 콘텐츠 세트·저장·복귀·접근성 회귀 통과
10. 테스트 기록과 미해결 범위 이월 항목이 Issue #60에 남아 있음

### 완료율 계산

`비유도 핵심 흐름 완료`는 다음을 모두 만족한 경우에만 인정한다.

- 관찰자가 진행 방법을 직접 알려주지 않음
- 최소 한 번의 강화와 위험 확인 완료
- 고객 비교와 판매 판단 완료
- 세계 후속 결과 또는 사건 상태 확인
- 현재 장비·소유권·다음 행동을 설명 가능
- 충돌·저장 복구로 세션이 중단되지 않음

중간에 관찰자 개입을 받은 테스터는 표본에는 남기되 완료 인원에는 포함하지 않는다.

### 세션 시간 계산

- 시작 시점: 플레이 가능한 첫 대장간 화면이 표시된 순간
- 종료 시점: 핵심 세계 결과를 확인하고 다음 행동 방향을 인지한 순간
- 설치·권한·진단 준비 시간은 제외
- 충돌·장시간 중단·관찰자 개입 세션은 중앙값 계산에서 별도 표시
- 목표보다 짧아도 핵심 흐름이 누락됐다면 성공으로 보지 않음
- 목표보다 길면 막힘·반복 왕복·연출 대기 원인을 분석함

## 결과 기록 형식

각 테스트 라운드는 최소 다음 산출물을 남긴다.

- 테스트 빌드 식별자
- 테스트 날짜
- 기기·Android 버전·화면 비율
- 테스터 익명 식별자
- 완료 여부와 세션 시간
- 관찰자 개입 여부
- 차단·중대·일반 결함 목록
- 재현 단계
- 관련 콘텐츠 세트와 저장 상태
- 수정 커밋 또는 후속 이슈 연결
- 회귀 결과
- 최종 통과·실패 판정

개인정보나 불필요한 신상 정보는 수집하지 않는다.
