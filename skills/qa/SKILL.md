# Blacksmith QA

## 진입

AGENTS.md → `docs/operations/BLACKSMITH_BASE_CURRENT_ADAPTATION_WORK_CONTRACT_20260901.md` → 현재 승인·production/fields → diff·실제 consumer·검사 결과를 읽는다.
스킬은 게임 규칙을 소유하지 않는다. 기대 결과는 해당 승인 원본과 현재 데이터에서 가져온다.
읽기 전용 설명에는 수정/새 receipt/전체 실행 검사를 요구하지 않는다. 검증을 실행하지 않았으면 명시한다.

## 변경에 따른 검사

| 변경 | 필요한 검사 |
|---|---|
| 문장·링크·운영 경로 | 사실·대상 존재·현재/역사 역할·콜드 스타트·diff·관련 계약 |
| 코드·데이터·공개 계약 | 실패 반례·정상/경계·호출되지 않는 consumer·통합 회귀 |
| 저장·거래 | 동일 UID·원자성·재시작·중복 요청·실패 복구·구버전 격리 |
| UI·이미지·모션 | 실제 프로젝트 실행·입력·상태·읽기·중단/복귀·실제 크기·alpha/권리/승인·consumer |
| 플레이어 경험 | 아래 재미 검증과 대표 플레이 구간 |
| 플랫폼·성능·접근성 | 해당 변경 또는 인도 기준이 요구하는 기기/환경·측정·사람 증거 |

하락·피버·단계 도약·정밀 횟수 같은 구형 기대를 스킬에서 고정하지 않는다.
Notion/Sheet readback은 명시적 legacy 이관에만 적용한다. 일반 작업은 GitHub 원본과 필요한 파생본을 확인한다.
이미지 후보·최종 승인·등록·적용·실제 화면 검증을 구분한다. 문서 교정에 이미지 생성/승인을 요구하지 않는다.

## 재미·표현 검증

운영 계약의 재미 검증 절과 기능 요구 ID에서 시작한다. 가설→상태/선택/정보/피드백→실제 코드·씬·자산→검증을 양방향으로 추적한다.
규칙 결과와 표현이 일치하고 위험/비공개 정보를 가리거나 누설하지 않는지, 취소·연타·중단·복귀가 권위 상태를 보존하는지 본다.
exact 빌드·대표 구간·입력·환경·바뀐 변수를 기록하고 행동 관찰·자기보고·필요 로그·반증을 대조한다.
DOC/MACHINE/RUNTIME/HUMAN/USER_APPROVAL/RELEASE를 나눈다. 문서 링크 PASS·자동 테스트·AI 평가로 HUMAN/FUN_PASS를 만들지 않는다.
못 봄/오해/이해했지만 피로함/규칙 선택 문제/빌드 결함을 구분한다. 보상·화려함 추가를 자동 처방하지 않는다.
사람 검증이 없으면 해당 주장만 NOT_RUN이다. 승인된 독립 구현은 계속할 수 있다. 모든 장르의 공통 재미 점수·표본 수를 강제하지 않는다.

## 검토·병합

전체 승인 후보 검토2회는 계획·구현·인도 단계가 공유한다. 발견 지적은 증거·재현·영향으로 판정하고 이후에는 결함별 표적 교정한다.
모든 변경 patch·untouched consumer·보호 경로·삭제/이동 복구·테스트를 대조한다. 무관한 PR은 읽기 전용이며 흡수하지 않는다.
현재 작업 PR의 exact HEAD·CI·독립 검토·미해결 스레드·실제 repository 규칙을 확인하고 정상 병합 뒤 main을 재조회한다.
파일 존재, 검사 실행, CI 강제, 런타임, 사람 승인은 서로 다른 사실이다.
결과는 PASS/PARTIAL/FAIL/NOT_RUN과 근거·남은 위험·롤백·다음 행동으로 기존 원본에 남긴다.
재사용할 회귀/교정이 있을 때만 기존 Learning Log에 추가한다. 새 일지/감독 스킬/대시보드를 기본 생성하지 않는다.
